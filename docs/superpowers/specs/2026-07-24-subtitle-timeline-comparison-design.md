# 字幕时间轴三阶段对照与播放交互设计

## 背景

旧版 WebUI 的字幕时间轴需要同时让用户查看识别结果、LLM 优化结果和最终字幕。新版虽然保留了部分对比视图代码，但它使用 `original_text` 是否存在来决定是否显示对比列，而该字段目前只在 LLM 实际修改文本时写入。因此，未启用 LLM 或从历史/缓存恢复任务时，时间轴会退化成单一最终版本，无法稳定呈现原始识别结果。

当前编辑逻辑也把三个栏位都绑定到同一个 `event.text`，编辑原始栏或优化栏时无法明确表达“以本次输入作为最终稿”的意图；播放操作则只有单独的播放按钮，没有行选中、点击行自动播放或快捷键。

## 目标与非目标

### 目标

- 时间轴始终显示三列：原始识别、LLM 优化、最终版本。
- 没有 LLM 配置或某条字幕没有发生 LLM 修改时，LLM 栏为空；原始识别和最终版本仍可见。
- 任意一列编辑都把输入写入最终版本，并立即持久化到任务字幕文件和任务历史。
- 保留原始 ASR 与 LLM 对照值，编辑最终稿不会破坏对照基准。
- 支持行选择、点击行自动播放、进入编辑自动播放和空格快捷键播放/暂停。
- 对实时任务结果、内存任务、历史任务和全管道缓存保持一致行为。

### 非目标

- 不改变 ASR、LLM 优化、字幕分段或时间戳算法。
- 不把用户对最终稿的编辑反写为新的 ASR 或 LLM 结果。
- 不增加音频剪辑、波形编辑或跨行批量编辑功能。

## 数据模型与数据流

每个字幕事件使用三个语义明确的文本字段：

- `asr_text`：LLM 处理前的 ASR 原始文本，始终保存。
- `llm_text`：LLM 实际产出的文本；未启用 LLM、没有 API 配置或该条未被修改时为 `null`/空字符串。
- `text`：当前最终版本，也是导出、播放时间段对应的字幕内容和用户编辑的写入目标。

现有 `original_text` 作为旧历史/内部算法兼容字段保留读取能力。新建事件与 WebUI 响应优先使用 `asr_text` 和 `llm_text`；对旧数据缺少新字段时按以下规则兼容：`asr_text` 回退到 `original_text`，再回退到 `text`；只有在能确认存在 LLM 修改时才填充 `llm_text`，否则保持为空。

Pipeline 在进入 LLM 阶段前为每个事件保存 `asr_text`。LLM 阶段成功返回候选时，将候选写入 `llm_text`，同时将候选写入 `text`；未启用或失败降级时不生成 `llm_text`，`text` 保持 ASR 结果。内部的 ASR 锚定去重仍使用 ASR 基准，不使用最终稿覆盖基准。

WebUI API 在任务完成、缓存恢复、历史详情和字幕编辑响应中都返回三个字段。编辑接口只更新 `text`，重建并写回最终字幕输出；`asr_text` 和 `llm_text` 不被清除。历史 `result_json` 保存编辑后的 `text` 与不变的两种对照值，确保重新打开历史任务后仍可对照。

## 时间轴界面

时间轴不再根据是否存在 `original_text` 决定列数，而是固定渲染：

1. 原始识别（ASR）：显示 `asr_text`。
2. LLM 优化：显示 `llm_text`；为空时保持空白并可编辑。
3. 最终版本：显示 `text`，继续支持 SRT/ASS 格式显示切换。

每行增加选中状态。点击行的非编辑区域会选中该行并自动播放对应的 `start` 到 `end` 音频；点击播放按钮也会先选中该行，再播放对应音频，避免按钮播放后空格键没有当前目标。双击任意文本栏进入编辑时，先选中并自动播放该行。

编辑输入框的初始值取自被编辑栏位：ASR 栏取 `asr_text`，LLM 栏取 `llm_text`，最终栏取 `text`。保存时统一调用现有字幕更新 API，将输入值写入 `text`，刷新该行三列显示并持久化最终输出；对照字段保持原值。LLM 栏原本为空时允许输入，保存后仍只会形成最终稿，不会伪造 LLM 结果。

空格键控制当前选中行：未播放时从该行开始播放，播放中暂停，再次按下继续；没有选中行时不执行任何操作。焦点位于 `input`、`textarea`、`select` 或可编辑元素时不拦截空格。播放结束后保留选中状态并恢复播放按钮状态。

## API 与兼容性

- 扩展 `SubtitleEventResponse` 与任务结果事件 JSON，新增 `asr_text`、`llm_text`。
- `PUT /api/subtitle/{task_id}/{index}` 的请求格式保持不变，`text` 仍表示最终稿。
- `_rewrite_subtitle_files` 和最终 SRT/ASS 持久化只使用事件的 `text`，保证用户编辑的内容落到最终版本。
- 历史任务读取时对旧 JSON 做字段归一化，不要求迁移 SQLite 表结构。
- 缓存命中时复制最终字幕文件，同时使用缓存事件中的三阶段字段；旧缓存按兼容回退规则显示。

## 错误处理

- 三阶段字段缺失或为 `null` 时使用兼容回退，不阻塞时间轴渲染。
- 播放音频不存在、加载失败或时间范围非法时显示现有 toast，并清理播放状态。
- 编辑保存失败时恢复编辑前内容，不更新本地最终稿，并显示错误提示。
- 用户在播放过程中切换行时停止上一段并从新行开始，避免多个音频元素同时播放。

## 测试与验收

### 后端

- Pipeline 无 LLM 时事件包含 `asr_text`，`llm_text` 为空，`text` 与 ASR 文本一致。
- Pipeline 有 LLM 修改时三字段分别保存 ASR、LLM 候选和最终文本。
- 编辑接口只修改 `text`，重写最终字幕文件，并保留两个对照字段。
- 历史详情、缓存恢复和旧事件 JSON 均能返回可渲染的三阶段字段。

### 前端

- 无 LLM、部分 LLM 修改和全部 LLM 修改三种事件数据都固定显示三栏。
- 三栏双击编辑时分别使用对应初始值，保存后最终栏显示新文本，对照栏仍保留原值。
- 点击行、点击播放按钮、双击编辑都播放该行；空格键可播放/暂停选中行，输入框中空格正常输入。
- 播放切换、结束、加载失败都会正确清理选中和播放状态。

### 人工验收

- 使用无 LLM 配置生成一次字幕，确认 ASR 与最终栏有内容、LLM 栏为空。
- 使用 LLM 配置生成一次有修改的字幕，确认三栏内容可区分。
- 分别编辑三栏并重新打开任务历史，确认最终文件和最终栏保留编辑结果，而 ASR/LLM 对照值未被覆盖。
- 点击行、进入编辑及空格快捷键均能播放对应时间段。
