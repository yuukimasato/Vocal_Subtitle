# 全链路检测与缺陷修复设计

## 目标

基于当前项目实际代码，对核心管道、CLI 和 WebUI/FastAPI 进行顺序化全链路检测。对可复现且属于项目代码的功能缺失或异常进行最小修复，并通过现有测试、CLI 冒烟、后端接口和浏览器流程验证。识别质量只在已有识别、边界、时间轴、物理覆盖和后处理逻辑范围内提升，不新增产品功能或引入新引擎。

## 范围与约束

检测覆盖三层：

1. 核心管道与质量门禁，包括配置、ASR 路由、物理时间线、映射、最终字幕和报告。
2. `vocal-subtitle` CLI，包括帮助、系统信息、模板、纯人声运行、输出格式、批处理和错误输入。
3. FastAPI/WebUI，包括启动、配置加载/保存、上传、任务创建、状态和 WebSocket 进度、字幕查看/编辑/导出、历史和反馈相关现有入口。

现有工作树包含大量用户改动。检测和修复只修改由本次检测直接证明有问题的文件，不回退或覆盖无关改动。依赖、模型或系统工具缺失时，记录为环境阻断，并验证代码是否正确报告和降级；不为本次检测临时增加产品依赖或下载新模型。

## 检测顺序

```text
配置/依赖预检
  -> 核心单测与契约测试
  -> CLI 冒烟
  -> FastAPI 路由与 WebSocket/API 测试
  -> 浏览器主流程
  -> golden/reference 质量回归
  -> 最小修复与分层回归
```

每个失败记录复现命令或操作、实际结果、预期结果和责任层。修复前先确认失败可复现，修复时先添加最小回归测试，再重跑对应层级；涉及共享契约时扩大到全量测试。

## 分层验证

### 核心层

运行现有 pytest 全集，并单独关注 ASR、物理时间轴、映射、质量门禁和后端契约测试。重点检查候选丢失、时间轴偏移、跨静音合并、尾段截断、最终字幕覆盖和状态/报告契约。

### CLI 层

验证 `--help`、`info`、`profiles`、纯人声 `run`、输出格式、批处理和失败输入。优先使用仓库已有 golden 音频，避免测试结果依赖新下载模型。检查参数到配置的映射、默认值、输入输出路径和失败退出码。

### 后端与浏览器层

启动实际 WebUI，验证健康检查、模板和设置、上传、任务创建、状态查询、WebSocket 进度、字幕读取/编辑/导出、历史和反馈现有接口。浏览器完成文件选择、参数设置、任务提交、进度更新、结果查看和导出，并记录控制台错误、网络失败和 UI 状态错误。前端必须展示后端真实错误，而不是吞掉异常或停留在错误的加载状态。

### 质量层

对已有 golden/reference 运行识别和时间轴检查，关注文本召回、边界、物理覆盖和最终字幕输出。修复后质量必须提升或保持，不接受已有样本回退。模型或外部运行时不可用的 case 不伪造通过，单独标记为环境阻断或未评估。

## 修复原则

- 只修复可复现、可归因到项目代码的缺陷。
- 优先修复阻断全链路的契约错误、状态错误、路径错误和异常处理错误。
- 识别质量修复优先使用现有物理边界、候选、映射和后处理约束，避免通过放宽匹配阈值掩盖候选或后处理问题。
- 不新增用户功能、不引入新引擎、不做无关重构。
- 每个修复配套最小回归测试；必要时补充端到端验证。

## 完成标准

- 所有可运行的既有测试通过，或明确记录与本次改动无关的既有失败。
- CLI 和 WebUI 主流程成功；外部依赖不可用时有明确、可解释的错误或降级结果。
- 每个代码缺陷都有复现证据和回归测试。
- 识别质量相关修复通过已有 golden/reference 质量检查，且无质量回退。
- 最终报告区分代码失败、环境阻断、未评估项和已修复项。
