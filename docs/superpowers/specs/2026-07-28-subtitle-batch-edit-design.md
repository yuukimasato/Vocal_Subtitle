# 字幕多选、批量说话人与合并设计

日期：2026-07-28

## 目标

为 Web 字幕时间轴增加接近 Aegisub 的批量编辑能力：

- 使用快捷键选择多条字幕。
- 对所选字幕批量调整说话人。
- 按换行或空格合并连续字幕。
- 将批量修改同步到任务状态、历史记录和字幕导出文件。

本次设计延续现有 `vocal_subtitle/webui/static/index.html` 的时间轴交互和 FastAPI API，不引入新的前端框架。

## 非目标

- 不增加字幕拆分、拖拽调整时间轴或完整撤销/重做系统。
- 不修改 ASR、说话人识别或字幕生成 pipeline 的自动决策。
- 不改变现有单条文本编辑的公开行为和导出格式。

## 交互设计

### 选区

- 普通单击：播放该行并只选中当前行。
- `Ctrl/Command + 单击`：切换当前行选中状态，并播放该行。
- `Shift + 单击`：从锚点行选择到当前行，并播放当前行。
- `Ctrl/Command + A`：选中全部字幕。
- `Esc`：清除选区。
- 点击文本编辑输入框、下拉框或按钮时，不改变选区，也不触发行播放。
- 重新加载任务、成功执行批量操作或切换历史任务后清空选区。

普通点击保留当前时间轴的播放能力；快捷键只改变选择范围，不新增独立的播放状态模型。

### 批量工具条

工具条固定在字幕表格上方，采用已确认的 A 方案：

- 未选中时隐藏。
- 始终显示已选择数量和“清除选择”。
- 选中至少一条时启用说话人下拉。
- 选中至少两条时启用“合并字幕”。
- 批量操作失败时保留选区，并在工具条附近显示错误提示。

合并按钮打开菜单，提供两个明确操作：

- 用换行合并。
- 用空格合并。

### 说话人候选

候选来自当前任务的字幕事件，而不是全局固定列表：

- 只收集非空说话人。
- 有 `speaker_id` 时以 ID 作为身份；只有 `speaker_label` 时以标签作为身份。
- 空说话人不会成为候选。
- 提供“添加说话人”入口，允许输入新名称。
- 选择已有说话人时同步写入其 `speaker_id` 和 `speaker_label`。
- 新说话人由后端分配未使用的数字 ID，并写入新标签。

## 后端接口

新增：`PUT /api/subtitle/{task_id}/batch`

说话人批量修改请求：

```json
{
  "action": "speaker",
  "indexes": [1, 2, 4],
  "speaker_id": 0,
  "speaker_label": "说话人 A"
}
```

合并请求：

```json
{
  "action": "merge",
  "indexes": [1, 2, 3],
  "separator": "newline"
}
```

响应返回操作后的完整字幕事件列表，前端以响应替换本地 `subtitleEvents`，避免删除事件和重新编号造成局部状态不一致。

### 请求校验

- 任务不存在或任务尚未完成：`404`。
- 所有序号必须存在且无重复：`400`。
- `speaker` 动作要求有效的说话人 ID/标签。
- 新说话人名称不能为空，且限制合理长度。
- `merge` 动作至少需要两条字幕。
- `separator` 只能是 `newline` 或 `space`。
- 所选字幕必须在当前事件顺序中构成连续区间；存在未选字幕间隔时拒绝操作，避免合并后的大时间范围覆盖未选内容。

## 数据处理

### 说话人批量修改

后端读取当前任务事件，验证所有序号后一次性更新目标事件。除 `speaker_id`、`speaker_label` 外不修改时间、文本、词级时间戳和溯源字段。

已有说话人沿用其身份关系。新说话人选择当前任务中未使用的最小可用非负 ID，避免覆盖其他说话人。

### 字幕合并

后端按事件当前顺序处理所选字幕：

1. 使用所选事件的最早 `start` 和最晚 `end`。
2. 按时间顺序连接文本，换行模式使用真实换行 `\n`，空格模式使用单个空格；由字幕导出器负责转换为目标格式。
3. 第一条事件作为结果主体，合并词级时间戳、来源词 ID 和可合并的物理范围字段。
4. 清空结果的 `original_text`，因为合并文本是用户手动修订结果。
5. 删除其他所选事件。
6. 按事件顺序重新编号全部字幕。

未选中的事件保持原内容；由于选区必须连续，合并不会跨过未选字幕。

### 持久化

批量操作完成后同时更新：

- 内存任务结果。
- 任务历史中的 `result_json`。
- 主字幕文件。
- 已存在的 LLM 字幕文件。

用户修改后的 `event.text` 是最终版字幕的唯一文本来源。前端最终版列、SRT/VTT/ASS 导出和历史任务详情都必须读取这份事件状态，不能在批量编辑后重新使用旧的 ASR 或 LLM 文本覆盖它。

现有单条字幕编辑共用持久化辅助逻辑，避免单条编辑与批量编辑出现历史记录不同步的问题。

## 前端数据流

在 `App.state` 增加选区状态：

- `selectedSubtitleIndexes`：选中序号集合。
- `selectionAnchorIndex`：Shift 范围选择锚点。

渲染时间轴时为每行绑定选择状态和修饰键逻辑。工具条从选区集合派生，不额外维护选中数量。批量操作成功后：

1. 使用 API 响应替换事件列表。
2. 清空选区和锚点。
3. 重新渲染时间轴和统计信息。
4. 保留当前视图模式和最终格式选择。

操作失败时不替换本地事件列表和选区，仅显示错误提示。

## 异常处理

- 无效任务、序号或参数由 API 返回明确的 `400/404` 信息。
- 说话人批量修改验证失败时不修改任何事件。
- 合并验证失败时不删除任何事件。
- 文件重写失败时保留内存变更并报告错误；用户可再次导出或重试持久化。
- 音频播放、单条编辑、视图切换和历史加载的现有错误处理保持不变。

## 测试

### 后端

- 批量更新已有说话人，验证 ID 和标签同步。
- 创建新说话人，验证 ID 不冲突。
- 空说话人不进入候选集合的接口侧数据规则。
- 换行和空格合并，验证文本顺序、时间范围和字段处理。
- 合并后删除事件并重新编号。
- 拒绝少于两条、无效序号、重复序号和不连续选区。
- 从历史任务加载后批量修改仍能保存、重新加载和导出。

### 前端

- 检查 `Ctrl/Command` 多选、`Shift` 连续选择、全选和 `Esc` 清除。
- 检查选中行高亮和工具条按钮启用条件。
- 检查说话人候选过滤、添加新说话人和批量提交。
- 检查合并菜单的换行/空格请求参数。
- 检查输入框、下拉框和工具条按钮不会触发行播放或改变选区。

### 浏览器回归

- 普通点击仍能播放当前字幕片段。
- 原有双击编辑、播放按钮、音频失败回退、保存和导出行为不回归。
- 批量编辑后刷新历史任务，字幕内容和说话人仍保持修改结果。

## 实现边界

预期修改范围：

1. `vocal_subtitle/webui/static/index.html`：选区状态、快捷键、工具条、说话人菜单、合并菜单和 API 调用。
2. `vocal_subtitle/webui/models.py`：批量字幕操作请求模型。
3. `vocal_subtitle/webui/api.py`：批量操作端点、事件变更和持久化复用。
4. `tests/test_webui.py`：接口和持久化回归测试。
5. 如需隔离纯事件变换逻辑，新增小型 WebUI 字幕编辑辅助模块及对应单元测试。

不修改 pipeline 生成逻辑和字幕格式化规则。
