# 全局 ASR、上下文重识别与多引擎复核设计

## 1. 背景

当前字幕流程以 VAD 片段为输入执行片段 ASR，再将结果映射为字幕事件。短片段缺少上下文时，ASR 可能生成训练语料中的固定短语，或者在句子边界处发生截断、错位和过度切分。

测试文件 `test/Grow Up Show ～向日葵馬戲團-4min-人声-生成字幕.ass` 中多次出现 `ご視聴ありがとうございました.`。该句在部分位置只有约 0.60 秒，去除标点后 14 个字符，CPS 约为 23.33，并且在多个不连续位置重复出现。人工字幕对应位置没有这些内容，说明仅依赖独立短片段 ASR 无法稳定抵抗此类污染。

本设计引入四层证据，但不改变最终字幕的物理约束：

1. 全局 ASR：对完整音频提供全局词级时间戳和覆盖基准。
2. 片段 ASR：继续作为默认字幕识别结果，保持现有流程和边界能力。
3. 异常窗口重识别：只对可疑片段扩展前后文重新识别。
4. 多引擎交叉复核：只对高风险或结果冲突的异常窗口调用第二 ASR 引擎。

最终字幕必须依据词级时间戳、VAD/声学边界和物理时间线重新分段。上下文窗口可以合并用于识别，但不能直接作为一条字幕输出。

## 2. 目标与非目标

### 2.1 目标

- 识别并修复固定训练短语、重复幻觉和短时长高 CPS 片段。
- 使用全局词级 ASR 发现片段 ASR 未显式暴露的漏识别、错位和覆盖异常。
- 保留现有片段 ASR 作为默认主路径，避免全局结果直接覆盖当前字幕行为。
- 对异常窗口使用上下文重识别，恢复完整句子后再按词时间戳重新切分。
- 对主引擎、全局 ASR 和第二引擎的冲突提供可解释的裁决结果。
- 让缓存、诊断和回归测试能够区分不同识别策略和规则版本。

### 2.2 非目标

- 不把全局 ASR 文本直接当作最终字幕。
- 不把上下文窗口直接合并成单条字幕。
- 不用 CPS 单独删除真实的短语、语气词或短句。
- 不默认对完整音频运行多个 ASR 引擎。
- 不在本阶段重写现有 VAD、说话人聚类或字幕导出格式。

## 3. 现有工程基础

现有代码已经具备大部分可复用能力：

- `pipeline.py` 的全局路径可以对完整音频执行 ASR，并构造包含词级时间戳的 `GlobalTranscript`。
- `config.py` 默认启用全局 ASR，并支持 `word_timestamps`、语言锁定和幻觉过滤配置。
- `boundary_reasr.py` 已实现边界滑窗重识别和词级结果收集，可作为异常窗口重识别的基础。
- `boundary_arbitration.py` 已提供窗口结果仲裁能力，可扩展为多来源结果裁决。
- `asr/hallucination.py` 已支持训练短语、置信度、无语音概率、压缩率和相邻重复检测。
- `acoustic_validation`、物理时间线和最终事件校验可以作为最终时间边界约束。

需要补充的主要能力是：

- Unicode 正确的字幕质量指标和异常评分。
- 全局结果与片段结果的事件/词级对齐。
- 以异常事件为中心的上下文窗口调度。
- 第二 ASR 引擎的局部复核和统一裁决。
- 将日文训练短语、证据来源和裁决原因纳入统一诊断与缓存版本。

## 4. 总体架构

```text
音频 / 人声轨道
       |
       +--> VAD、物理时间线、声学骨架
       |
       +--> 全局 ASR --------------------+
       |       全局片段、词时间戳、置信度  |
       |                                  |
       +--> 片段 ASR ---------------------+--> 初始结果对齐与异常评分
                                               |
                         +---------------------+--------------------+
                         |                                          |
                       正常                                      异常/冲突
                         |                                          |
                   保留片段结果                         上下文窗口重识别
                                                                    |
                                                +-------------------+------------------+
                                                |                                      |
                                           主 ASR 复核                         第二引擎复核
                                                |                                      |
                                                +-------------------+------------------+
                                                                    |
                                                         多来源结果裁决
                                                                    |
                                               词级对齐、声学吸附、最终重新分段
                                                                    |
                                                              字幕事件 / ASS
```

### 4.1 全局 ASR

对 4 分钟音频执行一次完整识别，输出：

- 全局 ASR segment；
- `GlobalWord` 级别的文本、开始时间、结束时间和置信度；
- 语言和模型信息；
- 覆盖率、失败窗口、去重和对齐诊断。

全局 ASR 的职责是提供证据，不直接决定字幕文本和显示边界。对于长音频，可使用 30～60 秒宏观窗口加重叠实现，最终仍合并为同一个全局词流。

全局识别应在已确认语言后执行。日语任务使用 `ja`，避免在异常的 0.6 秒局部窗口中重新进行语言检测。

### 4.2 片段 ASR

片段 ASR 保持当前主路径，输入 VAD/合并后的语音段，输出当前字幕候选。它负责：

- 主要文本识别；
- 片段级词时间戳；
- 当前说话人和片段上下文关联；
- 与现有字幕流程的兼容性。

除非通过异常裁决流程替换，片段 ASR 结果继续作为默认输出来源。

### 4.3 异常窗口重识别

异常窗口不是新的字幕段，而是为了给 ASR 提供上下文的临时识别范围。窗口由异常事件向前后扩展得到，推荐初始参数：

- 左右基础上下文：`0.5～1.0s`；
- 同一上下文组最大范围：`8～12s`；
- 最大识别窗口：不超过 `15s`；
- 遇到长静音时可以包含静音，但不允许最终字幕跨越该静音自动合并。

例如异常事件位于 `02:37.90～02:38.50`，窗口可以扩展为 `02:35.50～02:43.90`。ASR 可以一次识别窗口内的三句对白，但最终必须使用词级时间戳还原为三条字幕。

### 4.4 多引擎交叉复核

第二引擎只在下列情况触发：

- 训练短语出现在无明显声学证据的区域；
- 片段 ASR 与全局 ASR 的文本或词时间戳严重冲突；
- 主引擎重识别后仍然无法确定文本；
- `no_speech_prob`、`avg_logprob`、压缩率或词置信度同时异常；
- 局部结果会删除、移动或合并多个相邻字幕事件。

第二引擎可以使用现有的 `whisper.cpp` 或 `FunASR` 适配器。它只复核同一个异常窗口，不重复处理整个 4 分钟音频。

## 5. 中间数据模型

所有判断必须在 ASS 导出前完成。建议在现有 `SubtitleEvent` 旁边维护以下诊断结构：

```python
@dataclass
class SubtitleEvidence:
    source: str                 # segmented | global | context_primary | context_secondary
    text: str
    start: float
    end: float
    words: list[WordTimestamp]
    confidence: float | None
    no_speech_prob: float | None
    avg_logprob: float | None
    compression_ratio: float | None
    engine: str
    window_id: str | None


@dataclass
class SubtitleReview:
    event_id: str
    trigger_reasons: list[str]
    evidence: list[SubtitleEvidence]
    decision: str               # keep | replace | split | drop | unresolved
    decision_reason: str
    score: float
    final_word_ids: list[str]
```

必须保留原始片段 ID、上下文窗口 ID 和全局词 ID，不能只比较最终文本字符串。这样可以处理一对多、多对一以及说话人重叠的情况。

## 6. 异常检测与触发策略

### 6.1 文本规范化

在比较文本前执行：

1. Unicode NFKC 规范化；
2. 移除 ASS 标签、空白和可忽略标点；
3. 日文全角/半角统一；
4. 保留原始文本用于最终显示；
5. 对中日韩字符、拉丁字母、数字分别统计有效字符。

### 6.2 CPS 指标

CPS 只作为异常评分，不作为直接删除条件。推荐初始规则：

- 时长小于 `0.8s` 且有效字符数至少 5：进入短片段候选；
- `CPS >= 15`：提高异常分数；
- `CPS >= 20` 且文本长度至少 8：进入高风险候选；
- 单字、语气词和带稳定词级证据的短片段可以豁免。

阈值需要通过日语样本回归校准，不应把所有 0.6 秒片段直接标记为幻觉。

### 6.3 训练短语与重复检测

训练短语词表至少包括：

```text
ご視聴ありがとうございました
感谢观看
感谢收看
Thanks for watching
字幕志愿者
```

词表匹配必须使用规范化文本，并支持句末标点、空格和全角变体。匹配结果只触发复核；只有在没有词级/声学证据时才允许直接丢弃。

同一规范化短语在多个相距较远的窗口中重复出现时，提高风险分数。重复检测不能误删真实片尾，因此必须结合音频证据和时间位置。

### 6.4 结果冲突

以下情况进入异常窗口复核：

- 当前片段文本与全局词流在重叠时间内的字符相似度低于阈值；
- 当前片段没有对应的全局词；
- 全局词流存在当前片段漏掉的连续词；
- 片段结束时间落在句子或词的中间；
- 相邻事件的文本拼接不完整；
- 事件时间与声学骨架的有效语音区域重叠不足。

## 7. 结果对齐与裁决

### 7.1 对齐顺序

1. 使用全局词的时间范围查找与片段事件重叠的候选词。
2. 使用规范化文本和时间重叠建立词级匹配。
3. 对日文使用字符级/词级混合相似度，不能依赖空格分词。
4. 允许一对多、多对一以及相邻事件合并后再拆分。
5. 保留说话人边界，不因文本相似而跨说话人合并。

### 7.2 裁决优先级

裁决不是简单多数投票，建议按以下顺序计算证据：

1. 词级时间戳是否落在有效声学语音区间；
2. 首词和末词能否与声学边界对应；
3. 全局 ASR、片段 ASR 和局部 ASR 的文本一致性；
4. 多引擎结果是否一致；
5. 词级置信度、`avg_logprob` 和 `no_speech_prob`；
6. 文本是否为训练短语或重复模式；
7. 句子完整性和语言合理性。

### 7.3 结果动作

- `keep`：现有片段有足够证据，保留文本并重新校正时间。
- `replace`：局部或多引擎结果更有证据，替换文本和词时间戳。
- `split`：上下文识别恢复了多个句子，按词级时间拆分。
- `drop`：文本没有有效词级或声学证据，删除候选事件。
- `unresolved`：证据冲突仍无法解决，保留低置信度诊断并进入人工复核队列，不自动生成无证据文本。

## 8. 最终时间轴约束

这是本设计的硬性原则。

最终字幕事件必须经过以下步骤：

1. 从裁决结果取得实际词级开始和结束时间。
2. 将首尾边界吸附到声学骨架允许的范围。
3. 保留句间和说话人之间的真实静音。
4. 不允许字幕覆盖没有语音证据的长静音。
5. 仅在显示格式需要时进行最小持续时间处理，不能通过延长时间制造语音证据。
6. 对事件重叠执行最终顺序校验，但保留合法的说话人重叠信息供内部诊断。
7. 最后才导出 ASS/SRT。

因此，`02:35.50～02:43.90` 的重识别窗口最终仍应按实际词时间生成多条字幕，而不是输出一条覆盖整个窗口的字幕。

## 9. 缓存与版本

全局、片段、上下文和第二引擎结果必须使用不同的缓存类型。缓存键至少包含：

```text
audio_hash
vocals_hash
engine
model
language
start
end
word_timestamps
condition_on_previous_text
asr_route_version
quality_gate_version
hallucination_filter_version
context_reasr_version
cross_engine_policy_version
```

变更训练短语、CPS 阈值、对齐策略或多引擎裁决逻辑时，必须提升对应版本，避免旧污染结果继续命中。

缓存命中后仍需执行当前版本的文本规范化和幻觉过滤，但如果缺少词级证据，不能把缓存文本当作已验证结果。

## 10. 失败处理与资源策略

- 全局 ASR 失败：保留现有片段 ASR，记录全局证据缺失，异常区域仍可执行局部复核。
- 片段 ASR 失败：使用全局词流和局部窗口结果尝试恢复。
- 主引擎局部复核失败：直接触发第二引擎；第二引擎失败则返回 `unresolved`。
- 两个引擎结果冲突：使用词级和声学证据裁决，不用文本长度或单纯多数决定。
- GPU 显存不足：第二引擎可以串行加载，复核完成后释放模型；不影响主路径。
- 第二引擎不可用：降级为全局 + 片段 + 局部主引擎复核，并在诊断中标记降级。

默认只对 4 分钟音频执行一次全局 ASR。多引擎只处理异常窗口，以控制延迟和显存占用。

## 11. 配置建议

建议在现有配置中增加独立的上下文复核配置，而不是复用普通字幕合并配置：

```yaml
asr:
  word_timestamps: true
  global_asr:
    enabled: true
    routing: auto

  context_reasr:
    enabled: true
    left_context_seconds: 0.8
    right_context_seconds: 0.8
    max_window_seconds: 15.0
    max_group_seconds: 10.0
    min_duration_trigger: 0.8
    cps_warning_threshold: 15.0
    cps_high_risk_threshold: 20.0
    primary_engine: faster-whisper
    secondary_engine: whisper-cpp
    secondary_on_conflict: true
    secondary_on_training_phrase: true
    version: context-reasr-v1
```

`context_reasr` 的窗口合并配置不能改变最终字幕合并规则。最终事件仍由词级映射、VAD 和物理时间线决定。

## 12. 测试方案

### 12.1 单元测试

- 日文、中文和全角标点的 CPS 计算；
- 训练短语的大小写、标点、空格和全角变体；
- 正常短语不会因 CPS 单独被删除；
- 相同短语在不同时间重复出现时能触发风险评分；
- 全局词流与片段事件的一对多、多对一对齐；
- 长静音不会因为上下文窗口而被输出字幕覆盖；
- 缓存版本变化后不会复用旧策略结果；
- 第二引擎不可用时的降级行为。

### 12.2 集成测试

使用 `Grow Up Show ～向日葵馬戲團-4min-人声` 音频和两份 ASS 作为回归样本，重点验证：

- 六处 `ご視聴ありがとうございました` 异常都能进入复核；
- 02:35～02:43 窗口能恢复多句对白并保持真实停顿；
- 03:01 附近不会输出覆盖真实对白的训练短语；
- 最终字幕仍按词级时间和声学边界分段；
- 正常的 `はぁ`、`え?`、`ください` 等短片段不会被规则批量删除；
- 输出事件都能关联到全局词、片段词或局部复核词证据。

### 12.3 质量指标

至少记录以下指标：

- 训练短语误保留率；
- 真实短语误删除率；
- 全局/片段/局部结果的词级对齐覆盖率；
- 最终字幕的物理语音覆盖率；
- 无语音字幕时长；
- 事件数量变化；
- 多引擎复核触发率和降级率；
- 全局 ASR、局部 ASR 和第二引擎耗时。

## 13. 实施阶段

### 阶段一：证据和异常评分

增加统一的中间证据结构、Unicode CPS、日文训练短语和重复/冲突评分，不改变当前字幕输出。

### 阶段二：全局结果对齐

将已有全局词流与片段事件进行对齐，生成诊断报告，先以 shadow mode 运行验证触发率和误报率。

### 阶段三：异常窗口重识别

复用边界滑窗识别能力，增加可疑事件组窗口，执行局部主引擎重识别，并按词级时间重新分段。

### 阶段四：多引擎复核

接入第二引擎适配器，仅处理高风险和主引擎冲突窗口；增加裁决、降级和资源释放逻辑。

### 阶段五：正式启用和回归

完成缓存版本升级、诊断报告、配置开关和回归测试后，将流程从 shadow mode 切换为正式修复模式。

## 14. 验收标准

实现完成后必须满足：

1. 全局 ASR、片段 ASR、异常窗口重识别和多引擎复核可以独立失败并正确降级。
2. 全局 ASR 只提供全局证据，不直接覆盖片段 ASR 的默认行为。
3. 多引擎只在异常窗口触发，不对整个音频重复运行多个引擎。
4. 上下文窗口可以包含多个句子和停顿，但最终字幕不会直接使用窗口边界。
5. 每条最终字幕都能追溯到词级时间戳和有效声学边界。
6. 无声区间中的训练短语不能进入最终字幕，除非获得稳定的词级和声学证据。
7. 正常短片段不会因为 CPS 单项指标被删除。
8. 旧缓存不会绕过新的异常检测、对齐和裁决逻辑。
9. 回归样本中的异常短语、错位文本和过度切分得到可解释的修复结果。
