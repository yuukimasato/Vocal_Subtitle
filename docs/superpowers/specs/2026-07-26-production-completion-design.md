# Vocal Subtitle 生产补齐与真实素材验收设计

## 目标

基于 `docs/Vocal_Subtitle-离线高精度字幕系统设计文档.md`，完成当前项目中影响生产使用的配置、API、WebUI、CLI 和字幕质量缺口，并使用 `test/` 目录中的真实音频及人工 ASS 完成端到端验收。

本次验收以“字幕完整优先”为产品原则：人工字幕可能出于语气、节奏或可读性删减语气词，因此人工 ASS 是时间轴、主要内容和说话人切换的参考基准，不是要求系统逐字复刻的删减模板。系统保留可听见的语气词、短词和重复表达属于可接受结果；丢失可听内容、物理越界、重复灌装和错误说话人归属属于缺陷。用户可以在 WebUI 或导出后自行删改不需要的语气词。

## 范围

### 配置和部署

- 修复 `default.yaml` 中 `pipeline.degradation` 的错误嵌套。
- 消除 `ConfigLoader` 与 dataclass 默认值不一致，配置缺省值只保留一个权威来源。
- 补齐四个场景 profile 的新配置段和字段，包括物理字幕仓、边界冗余、流式、speaker embedding、严格断句和 `expected_speakers`。
- 让 `feedback` 配置可通过 YAML 发现和覆盖。
- 保持基础 profile 可在无 GPU、无可选模型和无云端 LLM 时运行，并清晰记录 global 降级原因。

### 核心字幕链路

- 保持 global ASR 为离线 `auto` 的首选路径，明确区分 global、legacy 和 global fallback。
- 优化物理字幕仓、词到物理仓分配、跨仓词处理及严格断句，优先解决丢词、错误合并、尾部拉长和说话人切换丢失。
- 所有词必须能追溯到合法物理范围或明确的对齐警告；不得通过扩大物理范围来改善指标。
- 对人工基准中被删减的语气词使用“可听内容完整性”规则评估，不把额外但有声学证据的语气词判为重复缺陷。
- 输出事件的物理边界、来源词、speaker 和校验诊断在后处理、LLM、导出过程中保持不丢失。

### API、WebUI 和 WebSocket

- 补全 `SubtitleEventResponse` 和事件序列化中的物理归属、来源词、逻辑句、对齐警告和物理字幕仓字段。
- 使运行请求模型与端点行为一致，补齐批量运行端点或明确统一的批量契约。
- 增加 HF Token 的独立设置、状态查询和删除接口，响应只暴露存在状态，不暴露明文 Token。
- 明确缓存配置的持久化行为，运行时修改与重启后的 YAML/持久化状态保持一致。
- 验证任务创建、状态查询、WebSocket 进度、三阶段时间轴、字幕编辑保存和 ASS/SRT/VTT 导出。

### CLI

- 补齐 `run` 与 `batch` 的关键选项，包括 ASR 路径、模型、VAD、LLM、diarization、speaker role、skeleton 和骨架导出。
- 增加 `--config` 自定义配置入口，并保证与 API 使用相同的配置覆盖语义。
- 对 ASR 模型和路径做早期校验；保留 `segmented` 兼容入口并在帮助和诊断中明确其回归/灾备用途。
- 补充 feedback 命令组和生产运行参数的文档说明。

## 数据流和不变量

```text
test 音频
  -> 物理时间线 / 声学证据
  -> global diarization + global ASR
  -> 词级物理范围 / speaker 分配
  -> 物理字幕仓灌装
  -> 严格断句与后处理
  -> 最终物理校验
  -> ASS/SRT/VTT + API/WebSocket/CLI 结果
```

必须保持以下不变量：

1. 事件和词不得越过输入物理音频范围或不属于它的 `PhysicalClip`。
2. 不同 speaker 不能被同一事件合并；speaker 不确定时输出 unknown 或明确警告，不猜测身份。
3. 系统不得凭人工字幕的删减而删除有声学证据的短词、语气词或重复表达。
4. LLM 只能改写已分配的文本，不能新增来源词、时间、speaker、物理归属或跨事件内容。
5. 缓存键必须区分 global、legacy、配置指纹和质量规则版本。
6. 三条入口使用相同核心 Pipeline，不能各自实现不同的字幕边界语义。

## 质量评估

### 基准解释

人工 ASS 的每个事件用于评估主要内容、时间边界和说话人切换。评估器需要将“系统额外保留的语气词”与“真正重复/幻觉/错误灌装”区分开：

- 有对应声学词和合法物理归属的额外短词：接受，不计入冗余失败。
- 无声学来源、重复灌装、跨物理范围或跨 speaker 的额外词：失败。
- 人工 ASS 中未出现但音频中真实存在的内容：系统应保留，不能按缺少人工匹配直接判为错误。
- 主要内容缺失、词序破坏、事件错配和人工可确认的边界漂移：失败或进入质量报告。

### 发布门槛

- 可听内容词覆盖率不低于 99%。
- 无无来源重复词、无丢词、无物理越界、无跨 speaker 事件。
- 主要事件 Start/End MAE 不高于 50ms，P95 不高于 100ms；同时保留 5/10/20/50/100ms 误差分桶。
- 所有目标场景实际使用 global；发生 fallback 时必须在报告中标记并导致 global 质量门失败。
- `venv/bin/pytest -q` 全部通过。
- CLI 单文件、CLI batch、HTTP API、WebSocket 和 WebUI 关键交互均使用 `test/` 音频验证，输出可导出且诊断字段完整。

质量指标未达门槛时，必须保留逐场景报告、自动字幕、人工字幕、诊断统计和失败原因，不得以放宽门槛或静默 fallback 宣布生产可用。

## 测试策略

1. 先运行无模型单元/契约测试，覆盖配置、物理归属、API schema、CLI 参数和缓存隔离。
2. 对 `test/quality_manifest.yaml` 中的每个音频执行 global benchmark，保存 ASS、比较报告和诊断报告。
3. 对代表性素材执行 auto 和 segmented 对照，确认 auto 的 global 优先和明确 fallback 行为。
4. 使用 FastAPI 测试客户端验证 API 和 WebSocket；对任务创建、状态、事件字段、编辑保存、导出和 HF Token 状态进行检查。
5. 使用 Click 测试 runner 和真实 CLI 子进程验证 `run`、`batch`、`--config`、导出格式及错误退出码。
6. 只在所有测试完成后更新主设计文档的当前状态和验收报告；任何模型不可用、GPU 不足或授权缺失都记录为环境前置条件，不伪装成质量通过。

## 风险与处理

- 人工字幕的主观删减会造成事件数量差异：采用内容/声学证据分层比较，避免把系统完整输出误判为冗余。
- global ASR 资源不足：保留结构化 fallback，但发布质量门要求目标素材实际使用 global。
- 物理边界和词时间戳精度不足：优先保守保留整词并输出 warning，不截断文字或越界扩展。
- 可选依赖缺失：API、CLI 和 benchmark 必须给出稳定、可定位的错误分类。
