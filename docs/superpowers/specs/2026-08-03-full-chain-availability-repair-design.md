# 全链路可用性检测与修复设计

日期：2026-08-03

## 目标

基于当前仓库实际代码，让项目在本机可安装、可启动并完成一次真实音频字幕处理。覆盖 CLI、后端 API/WebSocket、WebUI 浏览器流程和识别质量相关的已有路径。范围限定为修复功能缺失、运行异常、安装/启动断链和影响识别质量的实现问题，不新增产品能力。

## 验收范围

- 安装：生产环境依赖可解析，虚拟环境入口可用，`ffmpeg` 和 CLI 入口可验证。
- CLI：`info`、`profiles`、单文件 `run`、`batch`、反馈命令的帮助/错误路径，以及至少一次真实音频处理。
- 后端：应用启动、静态资源、健康/配置/任务/字幕/导出相关 API、任务持久化和 WebSocket 事件链。
- 前端：上传、配置、启动任务、进度、结果、字幕编辑/导出、历史和质量工作区的实际浏览器交互。
- 识别质量：使用现有本地音频和已有质量样本复核漏识、错字、异常时间轴、非语音误识和降级路径；只调整已有路由、边界、质量门控或配置缺陷。

## 实施方式

采用“黑盒验收优先、失败点最小修复”的顺序：先跑静态检查和自动化基线，再执行 CLI 和 WebUI 实际流程；每个失败记录复现命令、根因、修复文件和回归测试。缺失依赖允许通过安装脚本或依赖声明补齐，外部 LLM 不作为基础可用性的必要条件。

## 错误处理与兼容性

保留现有 API 字段和 CLI 参数兼容性。环境、模型或可选引擎不可用时应给出明确可操作的错误/降级信息，不能静默成功、卡在运行状态或生成不可导出的结果。模型下载和安装脚本必须可重复执行，并避免把失效的解释器路径写入环境入口。

## 验证

- `python -m compileall`、JavaScript 语法检查、`pytest` 及按模块定向回归。
- 真实启动 WebUI 后用浏览器完成主流程，并检查浏览器 console、网络请求和关键导出结果。
- CLI 真实音频输出可解析，字幕时间轴单调且不越界；任务完成/失败状态和产物路径一致。
- 最终报告列出已修复问题、未能验证的外部依赖，以及剩余质量风险。
