# 离线生产运行链收敛设计

日期：2026-08-01  
范围：让当前离线字幕项目通过真实 CLI 完成从输入音频到字幕导出的全链路。  
后续阶段：黄金集质量测试和质量提升不包含在本设计的完成条件中。

## 1. 目标与非目标

### 1.1 目标

本阶段以项目可正常使用为首要目标，统一现有离线生产路径的运行契约：

- 使用 `Pipeline.run()` 作为离线任务的唯一主入口。
- 保留分段 ASR 作为主候选来源。
- 让 global ASR、Context Re-ASR、Qwen/FunASR 等能力按照当前职责进入 evidence、复核或回退路径。
- 确保复核不可用、可选模型缺失、超时和物理投影失败时，主候选仍可结构化降级并导出。
- 确保标准单块、骨架分段、长音频宏观切块和可选复核缺失等路径都能返回统一结果。
- 确保最终字幕只经过一套 finalizer，并能生成请求的字幕格式；会话模式继续生成统一事件来源的多格式文件。
- 保留 `PipelineStats` 和生产诊断，能够区分 authoritative、shadow、segmented fallback、review disabled 和失败原因。

第一阶段完成不要求黄金集通过，不调整黄金集阈值，不把模型可运行误报为质量准入。

### 1.2 非目标

- 不重新设计流式链路。
- 不把 global ASR 或任意副引擎改成直接导出来源。
- 不在本阶段切换 FunASR 或 Qwen 为发布默认主引擎。
- 不通过放宽质量门槛、吞掉主链异常或复用不明缓存来制造成功状态。
- 不针对黄金集中的漏识别、文本准确率和边界质量做专项优化；这些属于下一阶段。

## 2. 现状与约束

当前离线任务由 `Pipeline.run()` 编排，已经存在以下能力：

```text
人声分离
-> 物理探测/VAD
-> global ASR evidence（可选）
-> 分段或宏观切块 ASR
-> OfflineProductionCoordinator
-> 说话人、帧级衔接、语义合并、声学校验
-> finalizer 和多格式导出
```

骨架分段、宏观切块和单块路径分别在 `Pipeline.run()` 内完成主候选处理，并在后处理前调用离线生产复核。`OfflineProductionCoordinator` 已能输出 `EvidenceDecision` 的投影结果，也已有 shadow 和 segmented fallback 语义。设计因此采用收敛和补契约的方式，避免新增第二套离线编排器。

必须保持以下边界：

| 层 | 允许职责 | 禁止职责 |
|---|---|---|
| 物理层 | 音频加载、VAD、骨架、合法时间范围 | 直接生成或删除字幕文字 |
| 识别层 | 分段 ASR、global ASR、复核候选 | 绕过决策层导出 |
| 决策层 | 风险评估、复核调度、EvidenceDecision | 用单一可选模型静默删除主候选 |
| 展示层 | 说话人、语义组织、格式化、导出 | 破坏已确认的物理范围 |

## 3. 端到端运行契约

### 3.1 统一主线

```text
输入校验
  -> 可选人声分离
  -> 音频加载和物理探测
  -> 分段主 ASR
  -> global ASR evidence（配置启用时）
  -> OfflineProductionCoordinator
  -> 说话人/帧级/语义/声学后处理
  -> finalizer
  -> SRT/VTT/ASS 导出
  -> PipelineStats 和任务诊断持久化
```

global ASR 的成功只表示 evidence 已准备，不表示它成为最终字幕主链。分段主 ASR 的事件是 coordinator 的回退基线；任何可选能力失败不得清空该基线。

### 3.2 结果契约

离线成功结果至少保持以下字段：

- `subtitle_path`：请求格式的最终字幕文件。
- `events`：与导出文件相同来源、已最终化的事件。
- `stats`：包括时长、片段数、字幕数、ASR 路径、主/最终引擎和阶段耗时。
- `from_cache`：明确是否使用了完整管道缓存。
- 生产诊断：包括 `production_path`、`review_status`、物理投影统计、降级类别和降级原因（如有）。

会话目录模式下，SRT、VTT、ASS 必须从同一份最终事件导出，不能分别重新运行 finalizer 或各自修改边界。

### 3.3 降级规则

| 情况 | 运行结果 | 诊断要求 |
|---|---|---|
| 复核配置关闭 | 保留分段事件并继续后处理/导出 | `production_path=review_disabled` |
| 复核端口或模型不可用 | 保留主候选 | `review_status=unavailable`，记录具体原因 |
| 复核执行异常 | 保留主候选 | `production_path=segmented_fallback`，记录异常类别和摘要 |
| 物理投影失败 | 保留主候选，但标记降级 | 记录 `raw_event_bypass_count` 和投影失败原因；不得静默标记 authoritative |
| 无语音/空事件 | 返回空字幕和完整零值诊断 | 不当作异常；输出文件仍应可生成 |
| 输入不存在或不可读取 | 任务失败 | 抛出明确输入错误，不生成伪成功结果 |
| 主 ASR 失败且没有可用回退 | 任务失败 | 记录主引擎、回退尝试和最终失败原因 |

降级是可见的运行状态，不是质量通过。主候选的保留只保证可用性，后续黄金集仍需评价文本和时间质量。

## 4. 实施边界

### 4.1 代码改动方向

实施阶段按现有模块边界检查并修复：

- `vocal_subtitle/application/pipeline_runner.py`：确认每个离线路径都进入同一生产复核、后处理、finalizer 和导出契约。
- `vocal_subtitle/application/offline_production.py`：统一复核关闭、不可用、异常、空输入和物理投影失败的结果与诊断。
- `vocal_subtitle/application/pipeline_result.py`：确保生产路径和降级信息可序列化、可从缓存恢复。
- `vocal_subtitle/application/postprocess_runner.py` 及映射导出模块：确保最终事件只 finalized 一次，并被所有格式复用。
- 配置和 CLI：保留现有开关，确保默认离线档位可运行，且显式路径参数不会绕开降级契约。
- 对应测试：优先补充端到端分支契约和失败降级测试，不新增黄金集质量断言。

不做与端到端可用无关的目录迁移、历史文档清理或大规模重构。

### 4.2 默认策略

- 默认主候选继续使用当前发布基线 faster-whisper 路径和已有自动回退规则。
- global ASR 按现有配置运行时只做 evidence。
- `risk_only` 复核可运行但不要求副模型必须存在；副模型缺失时结构化降级。
- `full_quality` 只用于验收和对比，不作为普通任务的隐式强制路径。
- LLM 语义优化、说话人识别等可选模块缺失时不阻断基本字幕生成。

## 5. 测试与验收

### 5.1 自动化测试

先运行与本次改动直接相关的组件测试和离线链路测试，覆盖：

- 复核关闭时的主候选保留。
- 复核不可用、执行异常和物理投影失败时的结构化降级。
- 空输入返回完整零值诊断。
- 三种主处理形态的统一结果字段。
- 缓存结果恢复时不丢失生产路径和 ASR 诊断。
- 最终化只执行一次，导出事件与返回事件一致。

### 5.2 真实入口验收

使用当前环境可用的真实音频，通过 CLI 或等价的 `Pipeline.run()` 验证：

1. 标准单块路径成功生成请求格式字幕。
2. 骨架分段路径成功生成字幕并完成 authoritative 或明确 fallback。
3. 超过宏观切块阈值的长音频成功完成全局时间偏移和导出。
4. 复核模型缺失或可选依赖缺失时仍可生成字幕，并在诊断中标明 unavailable/degraded。
5. 输出字幕存在、可读取、时间合法，CLI 返回成功状态。

本阶段报告应明确区分：

- `runnable`：真实入口完成并产生输出。
- `degraded`：依赖缺失但保留主候选成功完成。
- `failed`：主链无法产生可用结果。
- `gated`：黄金集质量门禁通过；本阶段不声明这一状态。

## 6. 后续黄金集阶段

端到端链路完成后，使用与生产一致的主/副引擎、模型路径、review policy 和 route version 重新生成黄金输入，再运行质量门禁。后续质量工作按真实指标拆分为识别漏检、候选粒度、物理边界和字幕组织问题，不能将本阶段的降级成功直接解释为质量通过。
