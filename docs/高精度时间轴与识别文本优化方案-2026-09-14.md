# 高精度时间轴与识别文本优化方案

**代码基线：** `main` 分支，commit `d3d49d1`  
**分析依据：** 当前工作树中的实际 Python、YAML 和测试代码  
**目标：** 提升字幕识别文本准确率，以及词级和字幕级时间轴精度

> 当前工作树存在未提交修改，涉及 `vocal_subtitle/acoustic/validator.py`、`vocal_subtitle/application/run_lifecycle.py`、`vocal_subtitle/mapping/*` 等文件。以下方案以当前实际代码为主要依据。

## 1. 当前处理链路

当前主流程大致为：

```text
音频预处理
  → VAD / 声学骨架
  → 每个语音段独立 ASR
  → 可选全局 ASR evidence
  → evidence review
  → 合并与字幕切分
  → AcousticValidator 吸附修正
  → 最终去重与导出
```

相关代码位置：

- 分段 ASR：`vocal_subtitle/application/stage_runner.py`
- faster-whisper：`vocal_subtitle/asr/faster_whisper_engine.py`
- 全局 ASR：`vocal_subtitle/asr/global_transcriber.py`
- WhisperX：`vocal_subtitle/asr/whisperx_engine.py`
- 证据复核：`vocal_subtitle/asr/evidence_review.py`
- 词级物理对齐：`vocal_subtitle/physical/word_alignment.py`
- 声学边界校验：`vocal_subtitle/acoustic/validator.py`
- 最终后处理：`vocal_subtitle/application/postprocess_runner.py`

## 2. 主要瓶颈

当前系统已经具备多引擎识别、全局 evidence、局部重识别、WhisperX 对齐、声学骨架和物理边界仲裁等组件，但关键能力没有完全接通。

主要问题如下：

1. 主识别仍以 VAD 分段后的独立 faster-whisper 为核心。
2. 全局 ASR 默认主要作为 evidence，不能稳定替换主文本。
3. WhisperX 的强制对齐能力存在，但没有成为默认主路径。
4. Context re-ASR、Qwen、forced aligner、SED 和 semantic review 默认关闭。
5. `boundary_refiner`、`physical.word_alignment`、`AcousticValidator` 和 `TimeMapper` 都可能修改边界，最终裁决关系需要统一。
6. 当前缺少固定真实音频集上的 CER/WER、词级边界误差和字幕边界误差指标。

## 3. 识别文本优化方案

### 3.1 将 WhisperX 强制对齐接入主路径

代码中已有：

```text
vocal_subtitle/asr/whisperx_engine.py
vocal_subtitle/asr/global_transcriber.py
```

建议采用以下职责划分：

- faster-whisper large-v3：负责初始文本识别；
- WhisperX：对已识别文本进行词级强制对齐；
- WhisperX 失败：回退到 faster-whisper 原始词时间戳；
- 两者都不可用：回退到 segment boundary，并标记降级。

每个词应记录时间来源：

```text
whisperx_alignment
faster_whisper_word
segment_boundary
timing_degraded
```

建议把 WhisperX 对齐失败率和词级时间戳覆盖率写入运行诊断。

### 3.2 增加全局 ASR 主文本模式

当前 `stage_runner._run_asr()` 对每个 VAD segment 独立识别：

```python
engine.transcribe(segment_audio, sample_rate, language=resolved_language)
```

这种方式容易受到 VAD 边界影响，导致句首、句尾、跨段专有名词和上下文识别错误。

建议增加：

```yaml
asr:
  global_asr:
    routing: "global_primary"
```

在该模式下：

1. 以物理声学骨架生成带左右上下文的窗口；
2. 全局窗口 ASR 作为主文本来源；
3. 分段 ASR 作为补漏、冲突检测和局部恢复来源；
4. 对最终主文本运行 WhisperX 对齐；
5. 按物理骨架重新投影字幕边界。

现有配置已经支持：

```yaml
left_context
right_context
window_overlap
reproject_grouped_windows
```

因此重点是增加路由和结果选择逻辑，而不是重新设计数据结构。

### 3.3 对高风险区域启用 Context Re-ASR

当前配置：

```yaml
evidence_review:
  context_reasr_enabled: false
```

代码中已有 `WindowedASRContextReASR` 和 `ReviewScheduler`。建议只对高风险窗口进行重识别：

- `avg_logprob` 较低；
- `no_speech_prob` 较高但局部有明显能量；
- global 与 segmented 文本不一致；
- 文本密度异常；
- 词时间戳缺失或非法；
- 相邻片段疑似重复；
- 语言检测结果冲突。

重识别结果在置信度和多源证据均更好时替换主候选，否则保留原候选并记录复核原因。

### 3.4 增加术语、热词和初始提示

当前 `FasterWhisperEngine.transcribe()` 没有显式使用：

- `initial_prompt`
- `hotwords`
- 项目专有名词表
- 领域术语表

建议增加配置入口：

```yaml
asr:
  initial_prompt: null
  hotwords_file: null
  terminology_file: null
```

识别前传入热词和上下文提示，识别后继续使用 `text_normalizer.py` 做数字、专名和格式规范化。

重点覆盖：

- 人名；
- 品牌；
- 地名；
- 专业术语；
- 中英文混杂；
- 数字、型号和单位。

### 3.5 限制 LLM 文本修改范围

```yaml
llm_optimize:
  enabled: false
```

当前默认关闭是合理的。高精度识别场景建议保持以下约束：

- ASR 文本是事实源；
- LLM 只能提出错别字候选；
- 不允许翻译、重写、压缩或改变语义；
- 保存原始文本、修改文本和置信度；
- 低置信修改进入人工复核。

## 4. 时间轴优化方案

### 4.1 固定时间来源优先级

建议统一为：

```text
词级时间：
WhisperX alignment
  > faster-whisper word timestamp
  > segment boundary

字幕起止：
physical acoustic skeleton
  + physical word alignment
  + 相邻字幕约束
```

`vocal_subtitle/physical/word_alignment.py` 已经具备候选边界打分、局部能量和 evidence 特征，应作为主要边界决策入口。

`boundary_refiner` 和 `AcousticValidator` 应负责提供候选或校验，避免多个模块无序覆盖同一端点。

### 4.2 限制声学吸附范围

当前工作树中存在较大的吸附范围：

```python
max_snap_distance = 0.5
max_start_snap_distance = 0.45
```

过大的范围可能导致吞静音、跨句吸附和相邻字幕边界错误。

建议按置信度分档：

| 边界置信度 | 最大自动修正范围 |
|---|---:|
| 高 | 80–120ms |
| 中 | 不超过 200ms |
| 低 | 不自动移动，仅标记 |

超过 200ms 时，必须同时满足：

- 声学骨架连续；
- 原词时间戳缺失或明显异常；
- 相邻事件没有重叠；
- global evidence 文本一致；
- 局部 RMS 或能量确认通过。

### 4.3 灰度开启时间轴仲裁

当前：

```yaml
acoustic_validation:
  timeline_arbitration: false
```

代码中已有 `AcousticValidator._build_arbitration()`，包含 R1/R2/R3 逻辑。建议分阶段开启：

1. 只对 global evidence 与 segmented 文本相似度不低于 0.90 的事件应用 R1。
2. 加入局部噪声画像和 RMS 确认。
3. 最后再处理低置信区域。

不要一开始解除所有事件的吸附距离限制，避免文本错误被放大成时间轴错误。

### 4.4 修复无词级时间戳时的说话人切分

当前：

```yaml
diarization:
  word_split_on_turn: false
```

代码中的注释已经指出：无词级时间戳时，整段文本可能被压到首个说话人片段。

建议：

1. 先建立可靠的 segment text 与 word list 映射；
2. 有词级时间戳时，按词切分说话人事件；
3. 没有词级时间戳时，禁止按 speaker 硬拆文本；
4. 无法切分时保留整段，并标记：

```text
missing_word_timestamps
speaker_split_degraded
```

完成词表传递修复后，再开启：

```yaml
diarization:
  word_split_on_turn: true
```

### 4.5 使用 5ms 局部搜索提升边界精度

`BoundaryFusion` 的粗粒度网格目前为 10ms：

```python
grid_resolution = 0.01
```

建议保持粗分段使用 10ms，但在最终边界附近使用 5ms hop 的局部搜索。现有 RMS 检测已经使用：

```python
frame_ms = 10
hop_ms = 5
```

可复用该逻辑，在候选边界的 ±150ms 范围内寻找局部能量谷或起始斜率，最终时间保留到毫秒。

## 5. 建议的高精度配置

建议新增独立的“高精度模式”，不要直接改变所有场景的默认配置：

```yaml
asr:
  engine: "faster-whisper"
  model: "large-v3"
  beam_size: 5
  word_timestamps: true
  condition_on_previous_text: false

  global_asr:
    enabled: true
    routing: "global_primary"
    evidence_enabled: true
    left_context: 0.8
    right_context: 0.8
    window_overlap: 0.5

evidence_review:
  enabled: true
  shadow_mode: false
  context_reasr_enabled: true
  local_recovery_enabled: true
  unresolved_keeps_candidate: true

acoustic_validation:
  enabled: true
  timeline_arbitration: true
  max_snap_distance: 0.15
  max_start_snap_distance: 0.20
  allow_end_extend: true
  allow_end_shorten: true
  reproject_grouped_windows: true

diarization:
  enabled: true
  early_turns: true
  word_split_on_turn: true
```

其中 `word_split_on_turn: true` 必须在无词级时间戳的文本传递问题修复后启用。

## 6. 实施顺序

### 第一阶段：建立可测量的高精度识别链路

修改重点：

- 接通 WhisperX alignment；
- 输出每词 `time_source`；
- 增加 `global_primary` 模式；
- 对高风险窗口启用 Context Re-ASR；
- 补充文本和时间轴诊断字段。

目标：

- 词级时间戳覆盖率达到 95% 以上；
- `missing_word_timestamps` 显著下降；
- 最终文本不再完全依赖 VAD 切段。

### 第二阶段：统一时间轴裁决

修改重点：

- 统一 `word_alignment`、`boundary_refiner` 和 `AcousticValidator` 的优先级；
- 限制自动吸附范围；
- 灰度开启 `timeline_arbitration`；
- 修复无词级时间戳时的 speaker 切分。

目标：

- 句首和句尾误差控制在 100–150ms；
- 相邻字幕无重叠；
- 不吞真实静音；
- 声学修正不改变识别文本。

### 第三阶段：建立真实音频评测闭环

建议固定一批真实音频和人工标注结果，统计：

**文本指标：**

- CER；
- WER；
- 专有名词准确率；
- 数字准确率；
- 漏识别率；
- 幻觉率。

**时间轴指标：**

- word boundary MAE；
- subtitle start MAE；
- subtitle end MAE；
- 边界误差 P50/P90；
- 字幕重叠率；
- 静音吞入时长；
- 语音覆盖率。

**系统指标：**

- 每分钟音频处理耗时；
- GPU 显存；
- 二次识别比例；
- WhisperX 失败率；
- 缓存命中率。

没有这些指标，继续调整 `padding`、`max_snap_distance` 和 `min_silence_gap` 容易变成经验性调参。

## 7. 最高优先级事项

如果只实施一轮优化，建议按以下顺序完成：

1. **接通 WhisperX forced alignment**，让词级对齐进入主路径。
2. **增加 global-primary ASR 模式**，让连续上下文参与最终文本生成。
3. **统一 physical word alignment 与 acoustic validation 的边界裁决**。
4. **缩小默认自动吸附范围**，避免吸附跨句。
5. **对高风险区域启用 Context Re-ASR**。
6. **建立真实音频上的文本和时间轴误差评测**。

推荐的最终主链路为：

```text
faster-whisper large-v3
  → global context transcription
  → WhisperX forced alignment
  → physical word alignment
  → acoustic skeleton constrained projection
  → evidence review for residual risks
```

这条链路最符合当前项目已有代码结构，也最可能同时提升识别文本和时间轴精度。



## 8. 从既有离线全链路方案中补充的约束

### 8.1 统一决策出口

所有会改变最终字幕事件的结果，都应经过同一个决策和投影流程：

```text
物理证据 → 分段主候选 → 全局证据与风险评分 → Context Re-ASR/副引擎
→ EvidenceDecision → DecisionEventProjector → 语义合并、声学门禁和导出
```

当前 global ASR 成功时可能绕过 `OfflineProductionCoordinator`、`EvidenceDecision` 和 `DecisionEventProjector`，造成不同入口的质量规则不一致。建议明确 global 结果的两种角色：`global_signal` 只用于风险判断；`global_alternative` 只有通过词时间、语言、窗口归属和物理校验后，才允许进入替换候选集合。默认先启用 `global_signal`。

### 8.2 四层职责边界

| 层 | 职责 | 约束 |
|---|---|---|
| 物理层 | VAD、声学骨架、RMS、噪声画像和合法时间范围 | 不直接决定字幕文字 |
| 识别层 | 文本、词时间和置信度 | 不得绕过决策层导出 |
| 决策层 | 汇总证据并选择 keep/replace/split/drop/unresolved | 单一模型不得直接删除真实语音 |
| 展示层 | 说话人、语义合并、格式化和导出 | 不得突破物理边界或改变词归属 |

### 8.3 字幕粒度和词级证据约束

最终字幕以句子或短句组合为 cue 单位，内部始终保留词级数据：

1. 有词级证据时保留 `words`、词 ID、start、end 和 confidence。
2. 没有词级时间戳时不得伪造，标记 `time_source=segment_boundary` 并提升风险。
3. 拆分只能发生在硬边界、词边界、自然停顿或句末标点处。
4. 合并不能跨 speaker change、长静音、PhysicalClip 或 physical bin 边界。
5. 同一个词 ID 不能出现在两条最终事件中。
6. 有文本证据支持的 physical speech span 不应出现人为字幕空窗。
7. cue 末尾不应进入静音区，默认向内安全余量不超过 3ms。

### 8.4 能力准入和漏识别归因

多引擎“已实现”不等于“可作为默认生产路径”。建议按以下状态管理：

```text
implemented → runnable → benchmarked → gated → release-default
```

FunASR、Qwen、ForcedAligner、SED 和语义审查应先以 shadow 或 risk_only 运行，只有通过真实音频黄金集门禁后才进入默认配置。

每次黄金集运行都应区分漏识别发生在物理层、ASR 候选、EvidenceDecision、物理投影、后处理，还是评测匹配层，并输出 `real_speech_drop_rate`、物理覆盖率、候选生成率、决策动作计数、投影拒绝原因和最终 display 空窗率。

## 9. 更新后的落地优先级

1. 冻结 faster-whisper large-v3 基线，并建立真实音频漏识别归因。
2. 接通 WhisperX forced alignment，验证骨架、Chunk 和缝合路径中的词级时间不丢失。
3. 统一 global、segmented、Context Re-ASR 和副引擎的 EvidenceDecision 入口。
4. 修复无词级时间戳时的 speaker 切分和词表传递问题。
5. 统一 physical word alignment、boundary refiner 和 AcousticValidator 的最终裁决关系。
6. 灰度开启 timeline arbitration，并限制大范围自动吸附。
7. 通过黄金集门禁后，再逐步准入 Qwen、FunASR 及其他辅助证据能力。
8. 最后才让噪声画像和反馈 profile 自动影响生产参数。


## 10. TTS 高质量人声场景的专项策略

实际测试表明，在高质量 TTS 人声、单人、低噪声条件下，声学骨架能够较准确地匹配真实语音的开始和结束时间。该结果说明物理骨架不应只作为最终校验器，在此类场景应提升为时间轴的主要约束来源。

### 10.1 推荐处理方式

```text
TTS 音频
  → 声学骨架检测
  → 骨架段作为物理 speech span
  → ASR 只负责文本和词级顺序
  → WhisperX/词时间作为段内细化
  → cue 起止优先贴合骨架外边界
  → 物理覆盖和静音约束校验
```

推荐规则：

- cue start 优先取对应骨架段起点，再根据首词时间保留小范围前导余量；
- cue end 优先取对应骨架段终点，再根据末词时间向内收缩；
- 骨架段之间的静音是硬边界，字幕不得跨越；
- 同一骨架段内的微停顿不应直接拆成逐词字幕；
- 对单人 TTS 不需要启用复杂 speaker change 切分。

### 10.2 参数建议

TTS 模式可以使用比通用真人录音更严格的参数：

```yaml
acoustic_validation:
  skeleton_mode: true
  timeline_arbitration: true
  reproject_grouped_windows: true
  allow_start_pull_earlier: true
  allow_end_shorten: true
  allow_end_extend: true
  max_snap_distance: 0.15
  max_start_snap_distance: 0.20
  snap_start_margin: 0.01
  snap_end_margin: 0.003

# TTS 建议
# 通过场景 profile 覆盖，而不是修改通用默认值
scene_profile: tts_clean
```

实际数值仍应由音频采样率、TTS 引擎和停顿模式评测确定。`max_snap_distance` 不应因为 TTS 边界清晰就无条件放大；清晰骨架允许更大胆地信任边界，但错误骨架仍可能造成整句截断。

### 10.3 需要增加的诊断

TTS 场景应单独统计：

- 骨架段与人工真实起点误差；
- 骨架段与人工真实终点误差；
- cue 与骨架段的 start/end 偏差；
- 骨架覆盖率；
- 骨架跨句率；
- 骨架段内文本覆盖率；
- 不必要的微停顿拆分率。

如果骨架端点误差稳定低于 ASR 词端点误差，应以骨架端点作为 cue 边界基准，而不是继续对整句做平均平移。

### 10.4 与其他场景隔离

该策略适用于 TTS、配音和干净单人播报，不应直接套用到：

- 音乐现场；
- 有明显 BGM 或音效的影视对白；
- 多人重叠说话；
- 强混响或低信噪比录音。

因此应新增场景 profile 或运行参数，让 TTS 模式启用“物理骨架优先”，通用模式继续使用保守的 evidence + boundary arbitration。
