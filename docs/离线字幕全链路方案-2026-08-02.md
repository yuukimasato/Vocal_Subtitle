# Vocal Subtitle 离线字幕全链路方案（2026-08-02 代码审计与融合修订版）

日期：2026-08-02（整合自 2026-08-01 所有文档 + 当日代码审计）
范围：离线高质量字幕生产链；流式模式不纳入本文。
依据：当前工作区代码、`configs/default.yaml`、`vocal_subtitle/config/models.py`、2026-08-02 离线生产运行时验收报告、当前黄金集输入/门禁报告和相关测试。

> **本次修订重点**：区分“当前运行态”“验收覆盖态”和“目标收敛态”，修正 global evidence 的实际消费边界、骨架/Chunk 调用关系、当前黄金集结果、反馈学习与噪声画像的接入状态；实施顺序改为先冻结质量基线与诊断，再收敛统一决策出口，最后做自适应和反馈闭环。

## 0. 结论先行

项目经过多轮迭代，已拥有超过 15 条可独立启停的优化链路能力。当前主要问题不是缺少算法，而是同一批能力在不同入口上的责任边界、启用条件和证据消费方式还没有完全收敛。

**2026-08-02 代码审计结论**：项目已经具备 `PipelineContext`、`PhysicalTimeline`、`EvidenceReviewService`、`OfflineProductionCoordinator` 和 `DecisionEventProjector` 等融合骨架，但还没有形成所有入口共用的生产闭环。当前默认 global 成功路径仍绕过 EvidenceDecision；`global_evidence` 虽已保存并参与风险评分，却没有进入 `EvidenceDecisionEngine` 的替代候选集合；shadow review 会生成决策，但协调器明确返回 baseline 且不做物理投影。噪声画像、反馈学习和边界冗余也处于“局部接入、消费不统一”的状态。详见第 15 章。

### 方案合理性审阅

总体方向合理，但原路线需要以下四项修正后才适合作为实施依据：

| 判断 | 审阅结论 | 调整 |
|---|---|---|
| 先统一证据与决策出口 | 合理 | 不能只把 global 结果传给 coordinator；必须定义其是“风险信号”还是“可替代候选”，并接入相应决策输入 |
| 同时启用所有可选引擎 | 不合理 | 先保持 faster-whisper 基线，Context Re-ASR、Qwen、ForcedAligner、SED 逐级 shadow/门禁准入 |
| 以完整自然句作为硬门禁 | 过强 | 句子完整性是展示质量目标；短回应、口语碎片和重叠语音不能因无句末标点被判失败或删除 |
| 先做架构迁移再查漏识别 | 风险较高 | 内容漏识别是当前发布阻断项；miss attribution 与统一出口并行，但质量基线必须先冻结，防止迁移掩盖根因 |

因此本文采用两条并行 P0：**质量 P0** 先定位 `real_speech_drop_rate` 的责任阶段，**架构 P0** 再让所有会改变最终事件的路径经过同一决策与投影契约。两条 P0 均通过后，才准入自适应阈值和反馈 profile 自动消费。

### 目标统一离线生产链

```text
物理证据
  -> 分段主候选
  -> 全局证据与风险识别
  -> 风险窗口复核
  -> EvidenceDecision
  -> 物理时间线投影
  -> 说话人/语义/声学后处理
  -> 最终化与导出
```

### 当前与目标的关键差异

1. **当前默认不是分段主链**：`global_asr.routing: auto` 会先尝试 global；global 成功后结果标记为 `primary`，直接进入后处理和导出。
2. **当前 global evidence 只影响风险**：`_global_evidence` 会传到 `EvidenceRiskScorer`，但未传给 `EvidenceDecisionEngine.decide_bundle(review=...)`，因此当前不能据此执行 global `replace/split`。
3. **目标才是 global 证据化**：global 用于语言、上下文、覆盖、重复和冲突判断；只有通过来源角色、时间重叠和物理校验后，才可以作为替代候选参与决策。
4. **Context Re-ASR 先处理切段造成的风险**，异质副引擎只处理残余高风险窗口。
5. **EvidenceDecision 是唯一文本选择出口**，所有 `keep/replace/split/drop/unresolved` 都经过统一决策。
6. **DecisionEventProjector 是 authoritative 模式的唯一事件投影出口**；shadow 模式只允许观察，不能宣称已完成物理投影。
7. **声学校验放在语义合并之后**，作为最终字幕边界的物理门禁。
8. 在真实黄金集通过前，**FunASR、Qwen 和任何复核引擎只能按候选/复核能力管理**，不能标记为发布默认。

### 当前发布状态

**不可发布**。2026-08-02 最新离线生产配对验收结果（`docs/superpowers/reports/2026-08-02-offline-full-chain-runtime-validation.md`）：

| 验收轮次 | 主引擎 | 配对声明 | 实际复核 | real_speech_drop_rate | 结论 |
|---|---|---|---|---:|---|
| 10 场景 production run | faster-whisper large-v3 | secondary=qwen | authoritative；Context Re-ASR/Qwen 均在 4 个 case 的 decision candidate IDs 中出现 | 0.116667 | 未通过（阈值 0.05） |

本轮 10 个场景、8 个有人工作为参考；物理违规、跨静音、幻觉保留、决策追踪和 raw bypass 均通过。该运行通过覆盖参数启用了 `authoritative_mode`、Context Re-ASR 和 Qwen，不代表 `configs/default.yaml` 的 shadow 默认值已改变。阻断项集中在人工参考场景的真实语音漏识别/文本不匹配，需从声学分段、ASR 候选和匹配门禁三处归因。历史 tiny smoke 和旧 Qwen 路径只能作为测量错位记录。

## 1. 当前全链路架构

### 1.1 当前实际调用链（基于 `configs/default.yaml` 和 `PipelineRunMixin.run()`）

```text
输入音频/视频
  -> Stage 1  人声分离 (UVR BS-RoFormer)          [skip_separation 可跳过]
  -> 宏观切块 (>3min, 静音处切分)                   [macro_chunking.enabled: true]
  -> 路径分发  先试 global/auto 路径（global 成功时当前直接作为主输出）
       -> 早期检测: Silero VAD + ffmpeg 骨架 + 噪声画像 -> PhysicalShadow
       -> 语言探测路由: tiny faster-whisper 多窗口探测
       -> 全局 ASR transcript + CandidateEvidence
          （当前 global 成功时事件作为 primary；evidence 被保存但没有机会与 segmented baseline 同轮决策）
  -> global 失败或显式 segmented 时进入分段路径:
       a) skeleton_mode=true（默认）: ffmpeg 骨架分段
            -> 每骨架段走 _process_skeleton_segmented（骨架外层 + chunk pipeline 段内处理）
       b) 多块路径: macro_chunks 逐块 _process_chunk_pipeline + 缝合
       c) 单块路径: 整段 _process_chunk_pipeline
  -> OfflineProductionCoordinator（当前只在未被 global 成功短路的分段/骨架/Chunk 路径调用）:
       分段候选 + 全局证据 + 物理时间线
       -> 风险评分 -> Context Re-ASR（默认关）-> residual risk 再评分
       -> 异质副引擎（risk_only 门控 / full_quality 全量，Qwen 默认关）
       -> 次级证据（ForcedAligner/SED/语义，默认关）
       -> EvidenceDecisionEngine -> EvidenceDecision
       -> authoritative: DecisionEventProjector -> 物理范围校验/词分配/覆盖审计/分箱
       -> shadow: 返回 baseline events，physical_projection.mode=shadow_bypass
  -> 后处理: 全局说话人聚类(ECAPA) -> 帧级无缝 -> LLM 语义合并(级联；骨架/物理 bin 场景可能跳过)
       -> 声学校验(ffmpeg 骨架,方向感知吸附) -> EndTime 校验
  -> LLM 文本优化（默认关）
  -> finalize -> SubtitleBuilder -> SRT/VTT/ASS
```

> **代码事实**：`_process_skeleton_segmented` 是分段服务的兼容适配器，其 legacy 实现会对每个骨架段再次调用 `_process_chunk_pipeline(parallel_vad=False)`；因此不是完全独立的 ASR 实现，但骨架生成、段过滤、局部空结果处理和全局时间偏移仍与普通 Chunk 路径不同。

## 2. 统一职责模型

后续文档和代码按四层职责组织，不再按历史 Plan/Phase 编号。四层对应代码中的实际模块划分：

| 层 | 代码路径 |
|---|---|
| 物理层 | `vocal_subtitle/physical/` (16 模块: timeline, ir, shadow, noise_profile, evidence_adapter, context, coordinate, coverage, allocator, boundary_arbiter, decision_ir, decision_projection, events, ir_cache, subtitle_bins, word_alignment) |
| 识别层 | `vocal_subtitle/asr/` (engine adapters, global_transcriber, boundary_refiner, boundary_reasr, local_recovery, hallucination, review_engines) |
| 决策层 | `vocal_subtitle/asr/` (evidence_review, evidence_decision, risk_scoring, review_scheduler), `vocal_subtitle/application/` (offline_production) |
| 展示层 | `vocal_subtitle/mapping/` (subtitle_builder, time_mapper, end_time_validator), `vocal_subtitle/merging/` (llm_merge_engine, merge_engine), `vocal_subtitle/acoustic/` (validator) |

| 层 | 唯一职责 | 可以做什么 | 不可以做什么 |
|---|---|---|---|
| 物理层 | 描述音频中可能存在的语音和合法时间范围 | VAD、骨架、RMS、噪声画像、物理覆盖 | 直接决定字幕文字 |
| 识别层 | 产生文本、词时间和识别置信度 | 分段 ASR、global ASR、Context Re-ASR、副引擎 | 绕过决策层导出 |
| 决策层 | 汇总多源证据并选择候选 | 风险评分、复核调度、EvidenceDecision | 凭单一模型直接删除真实语音 |
| 展示层 | 把合法事件变成可读字幕 | 说话人、语义合并、格式化、导出 | 破坏已校验的物理范围 |

### 目标不变量与当前缺口

下列规则是目标契约，不应误写成当前所有路径都已经满足：

- 分段候选是稳定的生产基线，但 global 成功路径当前仍可直接导出，尚未经过统一 EvidenceDecision。
- `global_evidence` 当前只传给风险评分；要让 global 文本参与 `replace/split`，还必须把经过窗口归属和物理校验的 global candidates 传给决策引擎。不能把“已生成 CandidateEvidence”误写成“已参与最终选择”。
- global、Qwen、ForcedAligner、SED 和 semantic-review LLM 的结果在目标架构中都只能进入 EvidenceBundle/EvidenceDecision；其中 ASR 文本是候选，ForcedAligner/SED/semantic-review LLM 是辅助证据，不能混为同一种可替代文本。展示层 LLM merge 仍可在硬边界内组织 cue，但不能独立改词或改物理时间。
- `drop` 至少需要多源证据；`unresolved` 默认保留主候选并记录诊断。当前 EvidenceReview 已实现这类保守策略，但 global bypass 路径不受其覆盖。
- authoritative 分段复核和物理投影事件已有来源、物理范围和决策追踪；shadow 返回 baseline，global 直接输出也未经过该投影契约。
- 所有时间必须明确是窗口相对时间、全局词时间、物理范围还是显示时间；同一个 offset 只能应用一次。

### 字幕输出粒度约束（句子级别）

**最终字幕输出目标是句子级别时间轴，内部必须保留词级证据。** 这是一项展示契约和验收目标，不代表当前所有 ASR/后处理输出已经满足“每条都是完整自然句”。短回应、无标点口语和重叠对话允许以短句或 `unresolved` 形式保留，不能为了满足句末标点而删除真实语音。

#### 物理节奏优先原则

人脑理解依赖完整意群，但字幕观看不能在仍有语音时出现无字幕空白。最终 cue 必须同时满足两条原则：

1. **物理时间轴拥有切分权。** `PhysicalTimeline` 的 speech span、稳定静音、speaker change 和 PhysicalClip/bin 边界决定“能不能跨越”和最终 start/end；语义模型不能创造、删除或跨越物理边界。
2. **语义只在同一物理语流内拥有组织权。** 在没有硬边界的连续语流内，优先把碎片组织成完整意群；若意群超过时长、字符或行数上限，则在词边界和自然停顿处拆分。
3. **有语音就应有 cue。** 除无法归属的重叠语音或明确 `unresolved` 降级外，所有有文本证据支持的 physical speech span 都必须被某条最终 cue 覆盖，不得因分段、后处理或 display mapping 产生人为字幕空窗。
4. **末尾不携带静音。** 最终 `cue.end` 吸附到最后一个有效 physical speech span 的结束点。默认允许 `3ms` 的向内安全余量，即 `0ms <= speech_end - cue.end <= 3ms`，但不允许 `cue.end > speech_end` 形成可感知的尾随静音；`0ms` 精确吸附作为实验配置单独门禁。

停顿按物理证据分三级处理：

| 停顿类型 | 默认范围 | 动作 | 必须满足 |
|---|---:|---|---|
| micro pause | `<=50ms` | 优先自动合并 | 同一 PhysicalClip/physical owner、同 speaker、合并后不超时长/字符上限 |
| short pause | `50–400ms` | 可做语义合并 | 同一 PhysicalClip、无 speaker change、两侧共同构成完整意群；物理边界优先于间隙数值 |
| hard silence | 已形成 PhysicalClip/bin 边界，或无时间线时稳定静音 `>=400ms` | 强制拆分 | 禁止 LLM、短事件合并或最终化阶段跨越 |

`400ms` 是无可靠 `PhysicalTimeline` 时的统一保守 fallback：当前 `default.yaml` 的 Silero 最小静音为 `350ms`、ffmpeg 为 `400ms`，配置模型的未加载 fallback 为 `400ms`。这些数值不是替代 `PhysicalTimeline` 的固定真理；只要物理层已明确生成不同 owner/bin，即使数值小于 `400ms` 也必须拆分。

#### 输出粒度定义

| 级别 | 时间轴粒度 | 示例 | 是否允许 |
|------|-----------|------|----------|
| 逐词 | 每个词一条 cue | `0.0 → 0.3 你好` / `0.3 → 0.5 世界` | **禁止** |
| 碎片 | 半句话一条 cue | `0.0 → 1.2 我们今天` / `1.5 → 2.8 来讨论一下` | **目标禁止**；若 ASR/参考证据不足，应保留并标记诊断，不得静默删除 |
| 句子 | 完整自然句一条 cue | `0.0 → 2.8 我们今天来讨论一下这个项目的进展。` | **允许（目标）** |
| 短句组合 | 2 个极短句合并为一条 | `0.0 → 1.5 对。没错。` | **允许**（min_duration 规则） |

#### 内部词级精度保留（不对外暴露）

词级时间戳 (`WordTimestamp`) 在目标管道中必须全程保留，但当前只能确认 ASR adapter → CandidateEvidence → EvidenceDecision → DecisionEventProjector 的主通道已具备传递字段；宏块缝合、语义合并和最终化后的唯一性仍需黄金集验证。其作用是支撑终点精度，不是终点本身：

```
ASR 引擎输出词级时间戳
  → SubtitleEvent.words（内部保留完整词列表，含每个词的 start/end/confidence）
  → EvidenceWord（决策层的结构化词证据）
  → EvidenceDecision.final_words（决策输出保留所有词）
  → 物理投影时按词分配至 PhysicalSpan（确保每个词落在正确的物理区间）
  → SubtitleBuilder 以句子为 cue 单位输出，用首词 start / 末词 end 作为该句时间边界
```

词级数据的关键用途：

| 用途 | 说明 | 对应代码 |
|------|------|----------|
| 句子边界精确定时 | 长句拆分时，用词的 start/end 确定断点位置的精确时间 | [subtitle_builder.py:280-281](vocal_subtitle/mapping/subtitle_builder.py#L280-L281) |
| 物理投影校验 | 确保每个词落在合法的物理语音区间内 | [allocator.py](vocal_subtitle/physical/allocator.py) |
| 风险评分 | 缺少词级时间戳的候选自动提升风险等级 | [evidence_review.py](vocal_subtitle/asr/evidence_review.py) |
| 声学边界吸附 | 用首词/末词时间向物理骨架吸附，而非整句平移 | [validator.py](vocal_subtitle/acoustic/validator.py) |

#### 句子边界裁决规则

下面规则按优先级排列，高优先级规则优先于低优先级规则：

**硬边界（不可逾越）：**

| 优先级 | 条件 | 动作 | 约束来源 |
|--------|------|------|----------|
| 1 | 说话人切换 | 强制拆分，不得跨 speaker 合并句子 | `_same_speaker()` 检查，[subtitle_builder.py:655-672](vocal_subtitle/mapping/subtitle_builder.py#L655-L672) |
| 2 | PhysicalClip/bin 边界或稳定静音（fallback 默认 ≥0.4s） | 强制拆分，不得跨越硬静音合并 | `PhysicalTimeline` 优先；无时间线时参考 Silero `350ms` / ffmpeg `400ms`，并采用统一 `400ms` 保守 fallback |
| 3 | 物理字幕仓边界 | 不得跨 bin 合并，每个 bin 独立裁决 | [subtitle_bins.py:23-44](vocal_subtitle/physical/subtitle_bins.py#L23-L44) |

**软边界（按质量优化）：**

| 优先级 | 条件 | 动作 | 约束来源 |
|--------|------|------|----------|
| 4 | 自然句末标点 (`.!?！？。`) | 优先在此处断开，形成完整句子 | `_SENTENCE_END` 模式，[subtitle_builder.py:52](vocal_subtitle/mapping/subtitle_builder.py#L52) |
| 5 | 弱分隔符 (`,，;；`) | 仅在单句超长且无句末标点时使用 | `_WEAK_SPLIT`，降级路径，[subtitle_builder.py:62](vocal_subtitle/mapping/subtitle_builder.py#L62) |
| 6 | 字符边界 | 最后手段：按 max_chars 在字符边界处强制断开 | `_split_event_forced()`，[subtitle_builder.py:394-451](vocal_subtitle/mapping/subtitle_builder.py#L394-L451) |

#### 时长与字符数约束

| 参数 | 值 | 作用 |
|------|-----|------|
| `min_duration` | 0.8 秒 | 短于此值的句子合并至相邻句（不超过 max_duration） |
| `max_duration` | 5.0 秒 | 超过此值的句子在句末标点处拆分 |
| `max_chars_cjk` | 20 字/行 | 中文单行上限，超出自动换行 |
| `max_chars_latin` | 42 字符/行 | 英文单行上限，超出自动换行 |
| `max_lines` | 2 | 单条字幕最多行数，超过则拆分 |
| micro pause | gap ≤ 0.05s | 同一物理 owner、同 speaker 时优先合并 |
| short pause | 0.05s < gap < 0.4s | 仅同一 PhysicalClip 内按语义完整性考虑合并 |
| hard silence fallback | gap ≥ 0.4s | 无物理时间线时强制拆分；有时间线时以 owner/bin 边界为准 |

#### LLM 语义合并的粒度约束

LLM 语义合并（[llm_merge_engine.py](vocal_subtitle/merging/llm_merge_engine.py)）可以在句末标点不确定时决定"合并还是拆分"，但它**不能**：

- 改变词级时间戳（合并时保留所有原词的 start/end）
- 跨越硬边界合并（说话人切换、长静音、物理 bin 边界）
- 将一句话拆成无标点的碎片

合并后的时间范围 = `min(成员物理 start)` 到 `max(成员物理 end)`，不允许产生新的人工时间。

#### 声学校验对句子边界的保护（以当前代码为准）

声学校验（[validator.py](vocal_subtitle/acoustic/validator.py)）在句子级别操作，**做方向感知吸附和受约束的 micro-gap merge，不做内容级拆分**：

- 句子 start 按方向规则寻找语音起点；当前默认 `max_snap_distance` 由 `config/models.py` 为 `0.5s`，`default.yaml` 显式配置为 `0.15s`。
- 句子 end 在连续语音内部主要记录可能截尾；是否缩短/吸附受 `allow_end_shorten` 等配置和声学证据控制。
- 目标契约要求最后一条成员语音的 `physical_end` 成为 cue end 的唯一上界；默认 `snap_end_margin=0.003s` 只允许向内留出 3ms，不允许向静音区延长。
- **禁止**在句子中间因能量波动而拆分事件
- 当前允许把 gap `<=50ms`、speaker 均已知且相同、physical owner 兼容的相邻事件合并；该行为必须保留成员词和物理来源，并纳入 boundary trace

#### 必须强制的不变量

以下约束必须在代码中以契约形式落实，违反时抛出明确错误或记录结构化降级：

1. **最终导出事件优先形成完整自然句**；短回应、无标点口语和复核未解决事件可例外，但必须保留诊断。
2. **有词级证据的事件必须保留有效 `words`**；旧适配器无词时间时不得伪造词时间，应标记 `time_source=segment_boundary` 并提升风险。
3. **事件拆分优先在硬边界、词边界或句末标点处**，不能在词中间断开。
4. **事件合并不能跨越说话人、长静音或物理 bin 边界**。
5. **有原生词时间的事件从 ASR 输出到最终展示全程保留词 ID 和词时间**；无原生词时间的事件必须显式降级，任何环节不得伪造词时间。
6. **有词级证据的最终 cue 时间边界优先由首词 start 到末词 end 决定**；无词级证据时允许使用经诊断的 segment boundary，不得伪造词时间。
7. **同一个词不能出现在两条最终事件中**（去重以词 ID 为键）。
8. **最终化阶段必须保持硬边界和词归属。** 当前 `finalize_subtitle_events()` 会先执行 `strict_segmenter`，再通过 `SubtitleBuilder._merge_short_events()`/`_split_long_events()` 调整逻辑 cue 数量，最后再做 display mapping；`SubtitleBuilder.build()` 还会对导出副本做排版。目标是所有合并/拆分都记录成员词 ID、物理 bin、speaker 和 trace，不能跨硬边界。
9. **有文本证据支持的物理语音区间不得出现 display 空窗。** 相邻 cue 之间的空隙必须能由 PhysicalTimeline 证明为静音、speaker overlap 降级或无文本证据区间。
10. **最终 cue 不得包含尾随静音。** 默认 `cue.end` 不晚于对应 physical speech end，且向内偏差不超过 `3ms`；超出时必须记录结构化降级。

#### 落实检查清单

以下检查项需要在开发和验收阶段逐项验证：

| 编号 | 检查项 | 验证方式 |
|------|--------|----------|
| G1 | 最终事件优先形成可读语义单元；短回应、口语碎片、重叠语音允许保留 | 统计碎片率/阅读速度；不得以“缺少句末标点”作为删除或失败条件 |
| G2 | 所有事件 `len(words) >= 1`，每个词的 `start < end` | 自动化断言 |
| G3 | 同一词 ID 不在两条事件中同时出现 | 自动化去重检查 |
| G4 | 相邻事件 gap > 0 时，gap 对应物理静音（非人为截断） | 与声学骨架交叉验证 |
| G5 | LLM 合并后的时间边界 = 成员词的最小 start / 最大 end | 自动化断言 |
| G6 | 声学校验的事件数量变化可解释 | 自动化断言（输入输出 count 与 micro-gap merge trace 一致） |
| G7 | Finalizer/SubtitleBuilder 不跨硬边界合并事件（说话人/长静音/物理 bin），不改变词归属 | 自动化断言 |
| G8 | 最终 cue 的时间覆盖所有词的物理范围，不跨硬静音 | 与 PhysicalTimeline 交叉验证 |
| G9 | 降级路径（fallback）输出同样满足 G1-G12 | 异常注入测试 |
| G10 | 带词级时间戳与无词级时间戳的事件都不跨硬边界；无词时间路径必须标记降级 | 对比测试，不要求两类输入采用完全相同的拆分点 |
| G11 | 有文本证据的 physical speech span 不出现字幕空窗 | `audible_blank_rate=0`；逐 span 对 final cue coverage |
| G12 | cue 末尾不进入静音区 | `trailing_silence_ms=0`；允许 `speech_end-cue.end` 在 `[0,3]ms` |

#### 与现有架构的关系

本约束是对第 2 节"统一职责模型"中展示层职责的精确化。不引入新层，不影响物理层/识别层/决策层内部实现。各层的相关变更范围：

| 层 | 受影响组件 | 变更性质 |
|----|-----------|----------|
| 识别层 | ASR 引擎适配器 | 确保词级时间戳不被丢弃（R3 已有） |
| 决策层 | `EvidenceDecisionEngine` | 决策不得将单句拆为碎片，keep/split 必须验证句子完整性 |
| 展示层 | `finalize.py`、`SubtitleBuilder`、`LLMMergeEngine`、`AcousticValidator` | 按本约束落实硬检查，split/merge 结果必须可追溯到词 ID |
| 展示层 | `EndTimePostValidator` | 确保最终 cue 无时间倒序和 0 时长 |

## 3. 引擎组合与策略

### 3.1 ASR 引擎对比

| 引擎 | 模型 | 语言 | 实测结论 | 当前定位 |
|---|---|---|---|---|
| faster-whisper | large-v3 | 99+ 语言 | 唯一全程无链路失败的引擎；中文长音频覆盖完整但切分偏碎 | **默认主引擎（非中文/兜底）** |
| FunASR | Paraformer seaco-large | 中文专用 | 三项任务均"完成但只产 1 条字幕"，整段合并/严重漏识 | 中文主引擎候选，**必须质量门禁 + 副引擎保护** |
| Qwen | qwen3-asr-1.7b | 中文为主 | 窗口适配器已接好 | **异质副引擎第一候选**（中文） |
| whisper.cpp | ggml-tiny | 99+ | 物理覆盖失败，`display must cover physical end` | 从默认链移除，仅回归 |
| WhisperX | large-v3 + 对齐模型 | 多语言 | 未实测 | 全局路径可选对齐 |

### 3.2 引擎路由策略

当前默认配置 `engine: "auto"`，先由 tiny 探测语言，再按 `ASRRouter` 的策略选择 FunASR 或 faster-whisper；这只是引擎路由，不等于 global/segmented 路径选择。

FunASR 路由发生以下任一情况必须回退 faster-whisper 并记录原因：
- 语音覆盖率低于门槛
- 文本密度异常
- 单事件过长或整段合并异常
- 空结果、重复率异常、语言结果不一致
- 引擎执行失败、模型缺失或超时

FunASR 只在中文黄金集、异常长事件和覆盖指标都通过后，才可以变成中文 `release-default`。质量失败只回退一次，最终 engine 和失败原因可追踪。

### 3.3 引擎配对（EnginePair）

`faster-whisper` 和 `whisper.cpp` 都属于 Whisper family，不能在默认策略中互相作为异质副引擎（`same_family_policy: reject`）。

| 主引擎 | 副引擎 | 语言策略 |
|---|---|---|
| FunASR | Qwen | 中文优先；非中文自动改走 Whisper |
| Qwen | FunASR | 仅中文 |
| Qwen | Whisper | 多语言 |
| Whisper | Qwen | Qwen 支持的目标语言 |

## 5. 候选链路组合

### 5.1 方案 A：分段主链 + 全局证据 + 风险复核（目标推荐）

```text
分段主 ASR (骨架分段 → skeleton_segmented)
  + global ASR evidence (单独窗口；先作风险/覆盖证据，通过准入后才可作替代候选)
  -> risk scoring (EvidenceRiskScorer: low/medium/high/critical)
  -> Context Re-ASR ★ (边界重识别，修复切段截断；默认关闭，风险门控启用)
  -> residual high/critical 的异质副引擎 ★ (Qwen risk_only；默认关闭)
  -> EvidenceDecision (唯一决策出口：keep/replace/split/drop/unresolved)
  -> DecisionEventProjector (物理投影：词分配/覆盖审计/分箱)
  -> 后处理和声学门禁
```

优点：与当前 `OfflineProductionCoordinator`、EvidenceDecision 和物理 IR 实现最匹配；分段主候选具备局部可控、长音频可切块和明确 fallback；全局上下文和副引擎只在必要窗口消耗资源。它是目标收敛方案，不是当前 `global_asr.routing: auto` 的实际默认行为。

**必要的代码前提**：当前 `EvidenceReviewService` 只把 `global_evidence` 传给 `EvidenceRiskScorer.score_bundle()`，决策阶段的 `review=` 仅包含 Context Re-ASR/Qwen 候选。实施方案 A 时必须先明确两种 global 角色：

- `global_signal`：只产生 `global_text_conflict`、覆盖和重复风险，不可替换文本。
- `global_alternative`：满足词时间、语言、窗口归属和物理校验后，才进入 `EvidenceDecisionEngine` 的 alternatives；每次选择必须记录 source candidate ID。

两者是同一 `source="global"` 的消费角色，建议使用显式 role 字段或 diagnostics 标记，不必扩张 `EVIDENCE_SOURCES` 枚举。

默认先启用 `global_signal`，待独立对比证明收益后再准入 `global_alternative`。这样可以避免 global 的长上下文错误直接覆盖稳定的分段基线。

**★ 标记的步骤在当前默认配置中关闭**（`context_reasr_enabled: false`, `qwen_enabled: false`），需按 R5 路线逐步准入。这些是预留的架构插槽，不是已生效的生产路径。

### 5.2 方案 B：global ASR 主链 + 分段回填（当前默认尝试，目标降为 evidence）

优点：上下文连续性和句法完整性最好。
缺点：当前 global 成功后直接进入 `_post_process_events`，不经过 `OfflineProductionCoordinator`、`EvidenceDecision` 和 `DecisionEventProjector`；模型资源、覆盖、时间精度和长音频失败还会影响整段任务。因此它可以保留为全局证据/上下文来源，但不应继续作为绕过统一决策的默认生产出口。

### 5.3 方案 C：轻量分段链 + shadow 观察（低配档）

优点：低资源、低延迟。
缺点：上下文不足、复杂场景恢复能力弱。**只作为低配/快速档，不作为高质量默认链。**

### 5.4 方案比较

| 维度 | 方案 A（推荐） | 方案 B | 方案 C |
|---|---:|---:|---:|
| 当前代码匹配度 | 高 | 中 | 高 |
| 长句上下文 | 中高 | 高 | 低 |
| 长音频稳定性 | 高 | 中 | 高 |
| 资源消耗 | 中 | 高 | 低 |
| 降级可控性 | 高 | 中 | 高 |
| 当前质量证据 | 最完整 | 不足 | 仅适合回归 |

## 6. 场景化路由

| 场景 | 主要风险 | 推荐组合 | 关键策略 |
|---|---|---|---|
| TTS/干净单人 | 边界过度处理、碎片化 | faster-whisper 主 + global evidence | 低干预，保留词级时间 |

### R9：多引擎复核能力管理与引擎准入框架（P1，设计建议）

本节是后续设计，不是当前已实现的配置契约；当前可执行的 P0 以第 15.1-15.3 节为准。

#### R9.1 当前状态诊断

经过代码审计，当前多引擎复核框架已完成组件化和基本降级，但仍存在以下未收敛问题：

**a) 复核执行链已组件化，能力状态还没有统一输出**

`EvidenceReviewService.run()`（[evidence_review.py:61-299](vocal_subtitle/asr/evidence_review.py#L61-L299)）实现了五阶段顺序：

```
风险评分 → Context Re-ASR → residual risk 再评分 → 异质副引擎 → EvidenceDecision
```

但每阶段**对引擎可用性的处理方式不一致**：
- Context Re-ASR 不可用时打 `context_reasr_port_missing` 后继续，不阻断
- Qwen/secondary 不可用时已有 `secondary_port_missing`、`model_path_missing` 等诊断，但“选中、启用、实际运行”仍可能被报告合并误读
- `LazyQwenASR`、ForcedAligner、SED 已提供 availability；Context Re-ASR 和通用 Windowed 引擎仍缺少统一生命周期快照

**b) 引擎状态生命周期未建模**

当前代码已经出现以下状态，但还没有统一的生命周期字段：

| 实际状态 | 代码表现 | 是否需要建模 |
|---|---|---|
| 端口缺失 | `ReviewUnavailable("optional_component_disabled")` 或 `port_missing` | 是（已有） |
| 模型文件不存在 | `availability()`/`model_unavailable` | 是（已有，需统一报告） |
| 模型加载成功但推理失败 | `engine_timeout`, `engine_failed` | 是（已有，但分散） |
| 模型就绪但语言不匹配 | FunASR 非中文自动回退，Qwen 没有同类检查 | 是 |
| 模型就绪全功能可用 | 无显式标记 | 是 |

**c) `review_policy` 在两个维度混用**

`risk_only` vs `full_quality` 同时影响两个独立维度：
1. **候选选择**：只 review 高风险窗口 vs 全量窗口（语义正确）
2. **引擎选择**：`risk_only` 下 Qwen 只在 Context Re-ASR 后 residual high/critical 时调用（语义也正确）

但引擎选择应该独立为一个维度（"主+副配对" vs "主+副+第三引擎"），不应用 `review_policy` 一个开关同时控制覆盖范围和引擎数量。

#### R9.2 建议：五态引擎准入生命周期

目标是让每个可选引擎在 `EvidenceReviewRuntimePorts` 注册时提供统一 `availability()` 快照：

```
class EngineLifecycle(enum.StrEnum):
    UNAVAILABLE = "unavailable"       # 端口未连接、SDK 未安装
    MODEL_MISSING = "model_missing"   # 端口就绪但模型文件不可用
    READY_SHADOW = "ready_shadow"     # 模型就绪，仅生成 evidence，不改变输出
    READY_REVIEW = "ready_review"     # 模型就绪，风险窗口复核可用
    READY_DEFAULT = "ready_default"   # 模型就绪，已通过黄金集门禁，可作默认
```

**状态跃迁规则**：

| 从 | 到 | 条件 |
|---|---|---|
| `UNAVAILABLE` | `MODEL_MISSING` | adapter/port 已注册，但 `availability().reason=model_path_missing` |
| `UNAVAILABLE` | `READY_SHADOW` | adapter/port 已注册，依赖和模型存在，shadow smoke 通过 |
| `MODEL_MISSING` | `READY_SHADOW` | 模型下载完成 |
| `READY_SHADOW` | `READY_REVIEW` | shadow 阶段质量报告达标（无诡异输出，未见退化） |
| `READY_REVIEW` | `READY_DEFAULT` | 黄金集门禁通过，且与现有发布默认引擎的对比报告确认收益 |

**不可跃迁**：任何状态都不能跳过 `READY_SHADOW` 直接进入 `READY_REVIEW`。这是为了确保每个引擎在影响输出前都经过充分的观察期。

**回退规则**：

| 条件 | 动作 |
|---|---|
| 引擎超时 > 3 次/批次 | 自动降级到 `READY_SHADOW`，不再参与 review |
| 黄金集回归指标退化 | 回退到 `READY_SHADOW` 并阻塞发布 |
| 模型路径变更 | 重置为 `MODEL_MISSING`，需重新验证 |

### R10：黄金集优化路线（P0，本文新增）

#### R10.1 当前黄金集评估机制分析

`evaluate_golden_set()`（[golden_gate.py:50-167](vocal_subtitle/quality/golden_gate.py#L50-L167)）和 `run_quality_benchmark.py` 构成了当前的双层验收体系：

**门禁层** (`golden_gate.py`)：期望 vs 预测事件匹配 → 10 项布尔检查 → pass/fail
**基准层** (`run_quality_benchmark.py`)：实际音频运行管道 → 输出字幕 vs 人工字幕对比 → MAE/覆盖率

**当前指标的覆盖盲区**：

| 盲区 | 说明 | 实际影响 |
|---|---|---|
| 时间匹配阈值固定 `_similarity >= 0.35` | 即使文本完全不一致，只要 overlap > 0 + similarity >= 0.35 就算 matched | 假阳性：可能把"嗯好"匹配到"我们今天讨论的是..." |
| `_matched()` 没有最短 overlap 要求 | 0.001s 重叠也算匹配 | 边界触碰的事件被误判为匹配 |
| `reference_content_coverage` 只看字符覆盖不看时间覆盖 | 文本全部出现但时间轴完全错位也能得 1.0 | 时间精度未被惩罚 |
| 黄金集 10 个 case 中仅 1 个 `expected_non_speech` 事件 | 幻觉检测主要依赖单个合成非语音 case | `hallucination_retention_rate=0.0` 不能代表真实音乐、呼吸声和环境噪声场景 |
| 没有按语言/场景分组的指标 | 无法区分"中文访谈"和"英文单人"的独立质量 | 场景级退化被聚合掩盖 |
| 黄金集 case 缺少难度标注 | 所有 case 权重相同 | 简单 TTS case 和多人重叠 case 贡献相等的 pass/fail 信号 |

#### R10.2 建议：三层黄金集金字塔

```
Layer 1: 合成诊断集 (8-12 cases) — 每个 case 验证单一信号路径
  ├── pure_silence:    确保空输出
  ├── pure_tone:       非语音 → 零字幕（已存在）
  ├── short_word:      150ms 短词召回
  ├── repeated_phrase: 重复检测（已存在）
  ├── speaker_overlap: 两人同时说话 → unresolved 而非 drop
  ├── tail_speech:     最后一秒语音不被截断
  ├── fast_speech:     >6 chars/sec 的语速覆盖
  ├── punctuation_end: 句末标点后正确断句
  └── mixed_lang:      中英混合 → language=auto 不崩溃
  ↓
  Layer 2: 真实材料回归集 (当前 test/quality_manifest.yaml 的 10 cases，完善后)
  ├── 按场景分类：single_speaker × 3, multi_speaker × 3, non_speech × 2, edge × 2
  ├── 按语言分类：zh × 4, en × 2, mixed × 1
  ├── 按难度分级：easy/medium/hard
  └── 每 case 至少包含：expected_events + expected_word_count + expected_speaker_count
  ↓
Layer 3: 用户反馈回归集 (来自 feedback learning 的累积样本)
  └── 从用户修订中积累的高价值 case，按月更新
```

#### R10.3 门禁指标改进建议

**a) 当前 `_matched()` 匹配条件过于宽松**

```python
# 当前（golden_gate.py:38-43）：
def _matched(expected, predicted):
    return any(
        _overlap(expected, item) > 0  # 任意正重叠
        and _similarity(expected.get("text", ""), item.get("text", "")) >= 0.35
        for item in predicted
    )
```

建议新增最小重叠约束和分层匹配：

```python
def _matched_strict(expected, predicted, min_overlap_ratio=0.3):
    """匹配要求：重叠覆盖期望事件 30% 以上，且文本相似度 ≥ 0.5"""
    expected_dur = expected["end"] - expected["start"]
    return any(
        _overlap(expected, item) >= min_overlap_ratio * expected_dur
        and _similarity(expected.get("text", ""), item.get("text", "")) >= 0.5
        for item in predicted
    )
```

**b) 新增 `mean_time_error` 指标**

当前门禁只看覆盖率和物理违规率，没有时间精度指标。应增加：

| 新指标 | 计算方式 | 建议阈值 |
|---|---|---|
| `median_time_error_ms` | 匹配事件对的 start/end 时间偏差中位数 | ≤ 200ms |
| `speaker_confusion_rate` | speaker_id 不同的匹配事件比例 | ≤ 0.10 |
| `scene_level_pass_rate` | 按场景独立的 pass/fail，避免低难度 case 掩盖高难度 case | 每个难度级别都 pass |

## 10. 推荐生产主线详细说明

### P0：输入和音频准备
- 校验输入、采样率、声道和总时长。
- 人声分离能力保留，分离质量进入诊断。
- ASR 使用原始/分离后的主音频；VAD 可使用轻度清理副本。

### P1：物理证据和时间线
- Silero 为主要语音概率证据。
- ffmpeg/RMS 作为边界和能量辅助证据，复用一次检测结果。
- 生成 `PhysicalTimeline`、speech spans、噪声画像和覆盖诊断。

### P2：宏观切块和主 ASR
- 超过 3 分钟的长音频先做宏观切块。
- 分段主 ASR 使用受控上下文，避免一句话被骨架或 VAD 边界截断。
- 每个候选保留全局起止、词级时间、引擎、模型、语言、置信度和来源 ID。

### P3：全局证据和风险评分
- global ASR 以重叠窗口运行，先去重再进入全局证据。
- global 用于语言、上下文、覆盖、重复和冲突证据。
- global 成功结果不得在该阶段直接导出；必须和 segmented baseline 一起进入 EvidenceReview。
- 主候选风险等级：`low/medium/high/critical`。

### P4：风险窗口复核
- 复核顺序：主候选风险 → Context Re-ASR → residual risk 再评分 → 异质副引擎 → EvidenceDecision。
- 默认 `risk_only`；`full_quality` 仅用于验收对比。
- 副引擎缺失、超时或语言不匹配时保留主候选，记录结构化降级。

### P5：统一决策和物理投影
- `EvidenceDecision` 仅输出 `keep/replace/split/drop/unresolved`。
- `DecisionEventProjector` 按物理时间线重新分配词和事件。
- 物理覆盖、跨静音、越界、词倒序、重复词和决策追踪检查。

### P6：说话人和字幕组织
- 说话人聚类用于标签连续性，不修复 ASR 文本。
- 帧级衔接只处理同一 PhysicalClip/owner 内的小间隙，不得跨 physical bin、speaker change 或稳定静音。
- `<=50ms` micro pause 优先合并；`50–400ms` short pause 由语义完整性裁决，但仍受物理 owner、speaker、时长和字符上限约束。
- LLM 语义合并只决定同一物理语流内的 cue 组织，不改变未经校验的物理时间。
- 超长意群按“物理停顿 > 词边界 > 标点 > 字符上限”顺序寻找拆分点，禁止在词中间切割。

### P7：最终声学门禁和导出
- 顺序：帧级衔接 → 语义合并 → 声学校验 → EndTime 校验 → final validator → SRT/VTT/ASS。
- 声学校验必须作用于合并后的最终边界。
- 导出前将每条 cue end 限制到最后一个成员 physical speech span 的 end；默认允许向内 `0–3ms` 安全余量，不允许向静音区延长。
- 对所有有文本证据的 speech span 计算 final cue coverage，`audible_blank_rate` 必须为 0。
- 输出 `trailing_silence_ms`、`audible_blank_duration_ms`、`physical_pause_class` 和 `merge_reason`，使每次切分/合并可追溯。

## 11. 错误处理与降级规则

| 场景 | 行为 |
|---|---|
| 全局 ASR 失败 | 继续分段主路径，标记 evidence incomplete |
| 全局 ASR 成功 | 当前可直接作为 primary；目标先转为 `global_signal`，通过独立准入后才允许 `global_alternative` 参与 EvidenceDecision |
| 副引擎缺失/失败/超时 | 保留主候选，标记 secondary unavailable/degraded |
| 复核配置关闭 | 保留分段事件，`production_path=review_disabled` |
| 复核执行异常 | 保留主候选，`production_path=segmented_fallback` |
| authoritative 物理投影失败 | 先把 baseline 转为显式 keep decisions 后重新投影；fallback 投影仍失败则任务失败，禁止 raw event bypass |
| FunASR 非中文 | 自动路由 Whisper；显式强制时报告不匹配 |
| ForcedAligner 失败 | 保留文本，标记未对齐，不伪造时间 |
| SED/LLM 失败 | 缺少对应因子，不阻断主链 |
| 无语音/空事件 | 返回空字幕和完整零值诊断，不当作异常 |
| 输入不存在 | 任务失败，抛出明确输入错误 |

### 缓存键

缓存键固定包含：input_hash / audio_hash / sample_rate / physical_timeline_version / window / role / engine_family / engine / model / language / pair_route_version / review_policy_version / evidence_schema_version / risk_policy_version / decision_policy_version。任一策略、模型、物理时间线或契约版本变化都必须产生 cache miss。

## 14. 降级模式（Degradation Mode）详解

`configs/default.yaml` 中已配置但文档此前未说明的关键架构能力：

```yaml
degradation:
  mode: "full"                   # "full" | "degraded" | "minimal"
  per_module_timeout: 60
  ffmpeg_timeout: 30
  llm_api_timeout: 15
```

`_resolve_active_modules()` 在 `application/chunk_runner.py:22` 实现，根据 `degradation.mode` 动态禁用可选的资源密集型模块：

| 模式 | 宏块 | ffmpeg VAD | 边界精修 | 声学校验 | 说话人 | LLM 合并 | 场景 |
|---|---|---|---|---|---|---|---|
| `full` | 按配置 | 按配置 | 按配置 | 按配置 | 按配置 | 按配置 | 默认高质量，全模块按各自 enable 开关运行 |
| `degraded` | 开 | 开 | 开 | 开 | 按配置 | 关 | CPU/GPU 受限，跳过 LLM 合并和 LLM 优化 |
| `minimal` | 关 | 关 | 关 | 关 | 关 | 关 | 极限低配，仅 VAD + ASR + 规则合并 |

> **注意**：代码实现（[chunk_runner.py:68-113](vocal_subtitle/application/chunk_runner.py#L68-L113)）中 `minimal` 模式关闭了声学校验（`acoustic_validation: False`），与旧版本文档描述的"保留声学校验"不同。当前 `minimal` 模式仅保留核心 VAD + ASR + 规则合并链。`degradation.mode` 与文档第 8 节 R8 的三个离线档位（quality-first / full-quality / budget）是独立维度——前者控制单管道的资源使用，后者控制复核链的复杂度。

### 超时保护

复核窗口通过 `evidence_review.window_timeout_seconds` 和 `WindowExecutionCoordinator` 提供超时隔离；LLM/ffmpeg/引擎自身也有局部 timeout。`degradation.per_module_timeout` 等配置不能视为所有模块都已统一执行的全局超时，后续应把实际生效的 timeout 和降级原因写入 diagnostics。

### 与方案 C（budget 档）的关系

`minimal` 降级模式提供方案 C 的内置实现：关闭所有可选模块，仅保留 VAD + 分段 ASR + 规则合并 + 字幕构建的最小核心链（不含声学校验）。

## 15. 功能融合优化路线（按当前代码修订）

本章不再把所有问题都归类为“未连接”。当前代码已经接通了不少基础通道：`pair_decision` 会传入 `EvidenceReviewRuntimePorts`，`LazyQwenASR.availability()` 已能做模型/依赖预检，`FeedbackConfig` 可从顶层 `feedback` 配置读取，`NoiseProfile` 已进入 `PipelineContext`，`LocalNoiseProfile.candidate_features()` 也已参与物理词边界候选评分。真正需要优化的是**统一出口、统一策略、统一诊断和统一反馈消费**。

### 15.1 P0：Global primary → 统一决策出口

**当前状态**：`global_asr.routing: auto` 时，`PipelineRunMixin.run()` 会先尝试 `_run_global_transcription_path()`；如果 global 成功，事件直接进入 `_post_process_events()` 并标记 `role=primary`，不会经过 `OfflineProductionCoordinator`、`EvidenceDecisionEngine` 和 `DecisionEventProjector`。`GlobalASRService` 已产生 `_global_evidence`，但因为本轮不会再运行 segmented baseline，它没有进入同轮 review；即使 segmented fallback 后被传入 review，当前也只影响 risk scoring，不是 decision alternatives。

**为什么这是最高架构优先级**：文档目标要求“所有最终字幕都经过 EvidenceDecision/PhysicalTimeline”，但当前默认配置下最顺利的路径反而绕过该出口。只要这个缺口存在，后续 Qwen、噪声画像、反馈学习、声学校验都无法保证作用在同一条生产主线。实施时仍先冻结 15.3 的质量基线，再进行本节迁移。

**优化路线**：

1. 保留现有 global transcript → `CandidateEvidence(source="global")` 适配，不重复实现转接层。
2. 调整编排：quality-first 路径即使 global 成功也继续生成 segmented baseline；两者只做一次后处理，后处理必须在决策/投影之后。
3. 在 evidence contract 中明确 `global_signal` 与 `global_alternative` 消费角色（`source` 仍为 `global`）。第一阶段只把 global 用于风险、覆盖和冲突；第二阶段通过门禁后才把合格 global candidates 传给 `EvidenceDecisionEngine` 的 alternatives。
4. global alternative 的替换必须满足：时间重叠、语言兼容、有效词时间、物理校验、相似度下限，并保留 source candidate ID；不允许整段 global 结果无条件覆盖局部 baseline。
5. 如需保留 global 主链实验，必须显式配置 `asr_path=global`；但实验路径也应将 global events 包装为显式 decisions 再投影，诊断标记 `production_path=global_experimental`，而不是保留 bypass。
6. 黄金集默认继续强制 `global_asr.enabled=false/routing=segmented`，直到 global signal/alternative 分别通过同一门禁。

**完成标志**：默认 offline 输出中不再出现未经过 `production_path`、`decision_count`、`physical_projection` 的字幕事件；报告能分别统计 global signal 数、global alternative 数、实际被选中的 global 数和被拒绝原因。

### 15.2 P0：引擎配对与复核策略统一

**当前状态**：`engine_pair` 已能产出 `pair_decision`，并在 `_apply_evidence_review()` 中传入 `OfflineProductionRequest` 和 `EvidenceReviewRuntimePorts`。这说明“副引擎选择完全未连接”的旧判断已经过时。剩余问题是策略语义仍分散在 `engine_pair.policy`、`review_policy`、`qwen_enabled` 和 optional port availability 之间。

| 已接通 | 仍需收敛 |
|---|---|
| `EnginePairRouter.route()` 产出 primary/secondary/policy | `risk_only` 同时表达窗口覆盖范围和副引擎调用策略 |
| `secondary=LazyQwenASR/WindowedASREngine` 可进入 review ports | `secondary=auto` 选到 Qwen 但 `qwen_enabled=false` 时只记录意向，不运行 Qwen |
| `LazyQwenASR.availability()` 可报告模型路径/依赖问题 | golden report 尚未固定输出每个 engine 的 availability 快照 |

**优化路线**：

1. 保留 `engine_pair` 只负责“选哪个副引擎”；把“跑哪些窗口”交给 `evidence_review.cover_policy`。
2. 新增或文档化 `engine_policy`：`primary_only` / `primary_plus_secondary` / `full_fleet`。
3. 在每个 case 的 diagnostics 输出 `engine_status`，包括 context_reasr、secondary、qwen、forced_aligner、sed 的 `enabled/status/reason/model/windows_processed/windows_failed`。
4. `secondary=auto` 且 `qwen_enabled=false` 时诊断应写成 `selected_but_disabled`，避免误解为 Qwen 已参与质量提升。

**完成标志**：黄金集报告能清楚回答“哪个引擎被选中、哪个引擎实际运行、哪个引擎因何未运行”。

### 15.3 P0：内容召回与物理尾段修复

**当前状态**：2026-08-02 生产配对验收中，物理违规、跨静音、raw bypass、trace 都已通过；发布阻断集中在 `real_speech_drop_rate=0.116667`。由于当前 `_matched()` 只要求任意正时间重叠且文本相似度 ≥0.35，这个数值还是偏宽松口径，不能直接等同于真实召回率。这说明当前优先级不应继续泛泛增加模块，而应同时校准匹配器并定位“真实语音被漏掉或文本不匹配”的局部链路。

**优化路线**：

1. 冻结当前宽松匹配报告作为 baseline，再为 `golden_gate.py` 增加最小 overlap/overlap ratio；新旧口径并列一轮，避免指标断代。
2. 对 QS、181、培训测试、英文多人和重复短语场景输出 per-case miss table，按 `expected_event -> nearest physical span -> segmented/global/review candidates -> decision -> final event` 追踪。
3. 把 miss 分成四类：物理候选未覆盖、ASR 未产生候选、ASR 有候选但文本不匹配、EvidenceDecision/后处理/门禁匹配丢失。
4. 只对“物理覆盖缺口/尾段截断”启用局部宽松复检；不要用全局阈值放宽掩盖文本错误。

**完成标志**：real_speech_drop_rate 降至 ≤0.05，同时 physical_violation/cross_silence/raw_bypass 继续为 0。

### 15.4 P1：骨架分段与 Chunk Pipeline 语义收敛

**当前状态**：`_process_skeleton_segmented` 不是完全独立的 ASR 管线；其 legacy 实现对每个骨架段调用 `_process_chunk_pipeline(parallel_vad=False)`。真正不同的是：骨架先切段、过滤短骨架段、逐段建临时音频、跳过失败小段、再做全局 offset。

| 维度 | skeleton_segmented | chunk/macro path | 收敛目标 |
|---|---|---|---|
| 一级分段 | ffmpeg skeleton | macro chunk 或 VAD/merge | 明确 skeleton 是物理 clip，不是最终语义段 |
| 段内处理 | 复用 `_process_chunk_pipeline` | 直接 `_process_chunk_pipeline` | 共享 ASR、边界精修、冗余识别和 mapping 规则 |
| 失败处理 | 可跳过独立骨架段 | 单块失败通常影响整块 | 输出相同类型的 structured degradation |
| 时间偏移 | `offset_subtitle_event(source="skeleton:n")` | macro chunk offset | 统一 source id、offset id、去重键 |

**优化路线**：

1. 不必重写为全新 `_transcribe_segment()`；优先把 skeleton 和 macro chunk 的 offset/source/diagnostics schema 统一。
2. 明确骨架段为空 ASR 的跳过策略：必须写入 `empty_skeleton_segment_count` 和时间范围，防止真实短回应被悄悄丢弃。
3. 骨架模式下 LLM 语义合并当前因 `skeleton_constrained` 可能跳过，应记录 skipped reason 和 bin/skeleton 数量。

**完成标志**：同一段音频在 skeleton 与 segmented fallback 下的事件来源、词 ID、物理范围和失败诊断可直接对比。

### 15.5 P1：噪声画像从“特征”到“影子自适应”

**当前状态**：代码里存在两类噪声画像：轻量 `PipelineContext.NoiseProfile` 用于运行诊断，物理层 `LocalNoiseProfile` 可提供 `noise_db/noise_stability/noise_fallback` 给词边界候选评分。旧文档说“仅写诊断、不参与任何下游”不准确；但它确实还没有控制 VAD、ffmpeg skeleton 或 hallucination 阈值。

**优化路线**：

1. 短期只扩大诊断：在质量报告中输出 `noise_profile_diagnostics`、边界候选中的 `noise_*` 特征覆盖率和是否 fallback。
2. 中期做 shadow 自适应：基于噪声画像计算“建议阈值”，但只记录 `suggested_vad_threshold/suggested_skeleton_noise_db`，不改变输出。
3. 长期才允许 opt-in 应用阈值，并要求黄金集按噪声场景分组比较收益/退化。

**禁止项**：不得直接把高噪环境映射到固定更高 VAD 阈值作为默认行为；这会损害低声压和尾音召回。

### 15.6 P1：反馈学习从“写入 profile”到“运行前消费”

**当前状态**：反馈学习并非“无连接”：管道支持 `feedback_reference`，WebUI/CLI 有反馈学习入口，`ParamLearner` 已能更新 `overrides`，`UserProfileManager.merge_with_base()` 也能把 overrides 合入配置。当前缺口是正常生产运行前没有固定应用 active profile，反馈结果也没有进入黄金集回归。

**优化路线**：

1. 在运行入口明确是否应用 `config.feedback.active_profile`；若应用，诊断记录 profile、版本和 overrides hash。
2. 把 `feedback` 配置显式写入 `default.yaml`，不是为了功能生效，而是提高可见性和可审计性。
3. 将用户修订样本按月进入 Layer 3 用户反馈回归集；任何参数学习在通过该回归集前只能 shadow。
4. 引擎偏好学习延后到 P2，先稳定 VAD/merge/subtitle 参数学习。

**完成标志**：一次生产运行可以明确回答“有没有应用用户 profile、应用了哪些参数、这些参数是否通过回归”。

### 15.7 P2：声学校验与边界冗余共享修正链

**当前状态**：边界冗余运行在 ASR 后/Mapping 前，声学校验运行在后处理末尾；两者都可改变边界，但诊断链没有统一展示。声学校验当前还会做 micro-gap merge，因此“声学校验不改变事件数量”只能作为目标约束，不能当作当前事实。

**优化路线**：

1. 每次边界变化都追加 `boundary_trace`：`vad/ffmpeg -> merge -> boundary_refiner -> redundancy -> decision_projection -> llm_merge/frame_stitch -> acoustic_snap`。
2. 边界冗余输出的仲裁结果只作为声学校验参考，不允许让 LLM 直接改最终物理时间。
3. 声学校验若合并 micro-gap，必须记录 merge count、参与事件 ID 和是否跨 speaker/bin。

**完成标志**：任意最终 cue 的 start/end 都能追溯到原始 ASR 时间和每次物理/语义修正。

### 15.8 P0/P1：物理节奏驱动的字幕组织

**当前状态**：物理层、声学校验和 `AcousticValidator._merge_micro_gaps()` 已有 owner、speech end 和 `<=50ms` 合并基础，但展示层仍存在两套不完全一致的规则：

- `SubtitleBuilder._merge_short_events()` 在前一条或当前事件短于 `min_duration` 时，以 `gap<0.3s + same speaker` 合并，尚未检查 PhysicalClip/bin/owner，也不显式校验合并后的长度，可能在最终化阶段重新跨越已建立的物理边界。
- `merge_decision.hard_split_min_gap=1.2s` 表达语义合并区间上限，不应当作物理硬静音标准。
- `AcousticValidator` 的配置类裸实例默认 `snap_end_margin=10ms`，而 `configs/default.yaml` 加载后的运行时值是 `3ms`；可靠词边界时还可能跳过 end snap。这有利于防止尾音误切，但必须统一配置来源并另行证明最终 cue 没有进入静音区。
- 当前质量报告没有直接衡量“有声音但没有字幕”和“字幕末尾残留静音”。

**优化路线**：

1. 新增共享的 `PhysicalCueBoundaryPolicy`（名称可按现有代码风格调整），由 `SubtitleBuilder`、LLM merge、frame stitch 和 acoustic validator 共用，输入为 physical owner/bin、speaker、pause duration、成员词和长度约束。
2. 将停顿分类集中为 `micro_pause <=50ms`、`short_pause 50–400ms`、`hard_silence`；PhysicalClip/bin/owner 边界永远覆盖数值分类。
3. `_merge_short_events()` 合并前必须校验 physical owner/bin、speaker 和合并后上限；不能仅凭 `gap<0.3s`。
4. 最终化顺序固定为：物理分组 → 同组语义组织 → 超长拆分 → end clamp/snap → coverage 验证 → display mapping。display mapping 只能排版，不得再改变逻辑时间边界。
5. 增加 `audible_blank_rate` 和 `trailing_silence_ms` 门禁；对无词时间降级事件使用 physical span end，不得退回人为估算的 segment end。
6. 保留默认 `snap_end_margin=3ms`；另设 `0ms` 实验档，只有在尾音截断率不升高时才考虑发布。

**完成标志**：有文本证据的语音区间 `audible_blank_rate=0`；所有最终 cue 的 `trailing_silence_ms=0`；向内 end 偏差在 `[0,3]ms`；任何跨 pause 合并都有 owner/speaker/长度/语义证据和 trace。
