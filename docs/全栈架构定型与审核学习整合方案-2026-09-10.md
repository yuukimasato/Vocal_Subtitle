## 0. 结论(TL;DR)

1. **架构定型**:全栈分四个区块——Python 管线、浏览器编辑器、跨栈契约层、学习闭环。**契约冻结、实现各自演进**:跨区块只允许通过四份契约通信(manifest / journal / HTTP API / provider),任何一方内部重构都不破坏另一方。
2. **编辑器保持独立开源组件**(维持 v2 裁定),它只新增一个与后端无关的一等功能:**上下文丰富的编辑日志(edit-journal)**。学习侧全部在 Python `feedback/`,以 journal 为第三条触发通道接入,不另起炉灶。
3. **subtitle-editor 成为主审核界面**:webui 的 HTML/JS 审核前端退役,FastAPI 保留为纯 API;编辑器新增管线面板(feature-detect localhost),承担提交任务→看进度→载入产物→精修→导出的审核工作流。
4. **界面演进为可拖动/缩放/吸附停靠的浮动面板**:移植 `tools/floating-panel-kit` 的**无框架核心**(store+geometry,约 460 行)为原生 JS,零依赖不破;不引入 React。
5. **路线** V1(journal+统计进现有 user_profile)→ V2(指纹 KNN 扩展向量检索)→ V3(轻量序列模型,数据达标触发)→ V4(MCP 工具化)。现有 `feedback/` 已覆盖 V1/V2 的六成能力,新代码集中在 journal 摄取与事件级归因。

## 1. 目标与全栈稳定架构基线

### 1.1 目标

- 项目**正常可用**:从音频输入到字幕产出、人工精修、偏好回流的全链路是一条被真实使用的工作流,而非各自的孤岛。
- **较高识别质量**:管线侧(引擎路由、边界精修、证据复核)继续负责识别质量本身;学习闭环负责**用户偏好与系统性偏差**的收敛,并借 journal 免费获得人工终审 ground truth,反哺质量评估与数据集。

### 1.2 四区块与四契约

```
┌─────────────────────────────┐        ┌──────────────────────────────┐
│  A. Python 管线 (vocal_subtitle)      │        │  B. 浏览器编辑器 (subtitle-editor)     │
│  分离→VAD→合并→说话人→ASR→精修      │        │  波形打轴/cue编辑/ASS预览/浮动面板       │
│  →映射→后处理→字幕输出               │        │  管线面板/journal/撤销栈/草稿           │
└──────────┬──────────────────┘        └──────────┬───────────────────┘
           │ ① review-manifest-v1(管线→编辑器,per-cue 出处)  │
           │ ② HTTP API(编辑器→管线:提交/进度/载入;可选 journal sink)│
           │ ③ edit-journal-v1(编辑器→学习侧,人工行为数据)      │
           ▼                                    ▼
┌─────────────────────────────────────────────────────────────────┐
│  C. 跨栈契约层(冻结点)                        D. 学习闭环 (feedback/)          │
│  manifest / journal / OpenAPI / vad-provider 契约     ingest→归因→参数学习→指纹检索→D2样本  │
└─────────────────────────────────────────────────────────────────┘
```

**演进规则**(稳定架构的含义):

| 冻结(契约) | 可演进(实现) |
| --- | --- |
| `review-manifest-v1` 字段与语义 | 管线各阶段引擎、精修算法、输出格式细节 |
| `edit-journal-v1` 事件 schema | 编辑器 UI、面板系统、撤销实现 |
| webui HTTP API 现有路由 + 新增 journal sink | webui 前端(退役)、FastAPI 内部结构 |
| vad-provider / MCP 工具签名 | VAD 引擎、Agent 策略、V3 模型结构 |

契约只允许**追加可选字段**(向后兼容),破坏性变更必须升版本号并存双读。

## 3. 跨栈契约 schema 草案

### 3.1 `review-manifest-v1`(管线 → 编辑器)

**文件位置**:与字幕产物同目录,`<字幕同名>.manifest.json`(`cache/persistent_files/<task_id>/final/` 与 `cache/uploads/<hash>/` 各一份)。由后处理输出阶段(`persistence_manager` 写 final 时)一并生成。

```json
{
  "schema": "review-manifest-v1",
  "run_id": "run-20260910-…", "task_id": "…",
  "created_at": "2026-09-10T12:00:00Z",
  "input": { "filename": "lesson01.mp4", "sha256": "…", "duration": 3600.0 },
  "profile": "default",
  "engines": { "separation": "uvr", "vad": "silero", "asr": "funasr+qwen", "diarization": "speechbrain" },
  "subtitle": { "file": "final.srt", "format": "srt", "hash": "…", "stage": "final" },
  "cues": [
    {
      "index": 1,
      "source_stage": "asr | llm-optimized | final",
      "confidence": 0.87,
      "avg_logprob": -0.21,
      "words": [ { "w": "大家好", "t0": 12.10, "t1": 12.32 } ],
      "speaker_id": 0, "speaker_label": "主持人"
    }
  ]
}
```

- `words`/`speaker_*`/`avg_logprob` 为可选字段,有则填(复用现有 `SubtitleEvent`、`run_report-v1`、`metadata.json` 已有数据,不需要管线新增计算)。
- **编辑器加载**:模块版(http)经 `?manifest=` 参数或管线面板完成后直连载入;file:// standalone 无法 fetch 同目录 → **provenance 降级为 null,journal 照记**(架构上接受:审核工作流以 http 模块版为主,standalone 保持轻量独立形态)。

### 3.2 `edit-journal-v1`(编辑器 → 学习侧)

**粒度**:`actions.js` 的 `commit()`(=撤销步,尊重 coalesceKey);**内容**:字段级前后值 diff + 上下文,不存全量快照(原始字幕文件 + journal 可重放,重放性同时是校验工具和 V3 训练的 (state, action) 序列来源)。

**文件形态**:NDJSON,首行 session header,其后每行一个事件。`<字幕同名>.journal.jsonl`,多次会话追加。

```
{"schema":"edit-journal-v1","type":"header","session_id":"…","editor_version":"1.x",
 "started_at":"…","media":{"name":"lesson01.mp4"},"subtitle":{"name":"lesson01.srt","hash":"…"},
 "run_id":"run-20260910-…|null"}
{"schema":"edit-journal-v1","type":"event","session_id":"…","seq":17,"ts":"…",
 "actor":"human|agent|cli","command":"updateCueTimes","coalesce_key":"drag:cue-12",
 "targets":["cue-12"],
 "diff":[{"id":"cue-12","field":"end","before":12.40,"after":12.35}],
 "context":{
   "cue":{"duration_before":3.2,"gap_before":0.15,"gap_after":0.40,"chars":21,"cps_before":6.5},
   "audio":{"nearest_speech_boundary":{"t":12.41,"dist":-0.06},"local_energy":0.62,"vad_speech":true},
   "provenance":{"source_stage":"llm-optimized","confidence":0.87}
 }}
```

要点:

- `command` 直接取 actions 命令名;**删除整行(`removeCues`)、拆分、合并是"取舍思维"信号,schema 一等公民**;被拒绝的候选(如删掉的 ASR 行)由 diff 的 before 值+provenance 还原。
- `actor`:`window.agent.act` 与 harness 驱动的写操作自动标 `agent`;CLI `cueOps` 写文件标 `cli`(V1 可只实现 human+agent,字段先留)。
- `context.audio` 由编辑器本地计算(第一轮 Q6-A 范围):与最近语音边界的距离(内置 VAD)、局部能量、cue 时长/留白/CPS;`provenance` 由 manifest 有则填、无则 null。
- **localStorage 队列**:key 沿用 `vstEditor.` 命名空间模式(含 agent 命名隔离),**轮转上限**(建议 5000 事件或 2MB,触顶后 UI 提示导出);多标签页同文件以 session_id+seq 去重。
- **导出**:导出字幕时搭车下载 `.journal.jsonl`(默认开);设置面板提供"查看/清空/导出"(D11)。导出成功不清 journal(与草稿 discard 不同:草稿是"活",journal 是"账")。
- **学习侧摄取**(Phase 4):`vocal-subtitle feedback ingest-journal <files…>` → 校验 schema → 与原始字幕对齐重放校验 → 进 D2 候选样本库(沿用 `sample_manager` + 匿名化 + 审核队列)→ `diff_analyzer` 增加事件级归因入口。

### 3.3 HTTP API(编辑器 ↔ 管线)

复用现有 webui 路由(提交任务、进度、`GET /api/subtitle/...` 产物),新增/调整:

| 变更 | 内容 |
| --- | --- |
| 新增 | `GET /api/journal/sink`(能力探测,202)+ `POST /api/journal/sink`(批量事件,V1.5;CORS 允许 null origin 供 standalone file:// 使用) |
| 保留 | 任务提交/进度/产物相关路由不变(契约冻结) |
| 退役 | `ui-review.js` 审核前端入口从导航移除;`routes_subtitles.py` 的编辑端点(PUT subtitle/batch)标记 deprecated,一个里程碑后随前端一并删除(D13) |

### 3.4 面板系统(编辑器内部接口)

- `js/ui/panels/` 新增:`panelStore.js`(移植 kit `store.ts`+`geometry.ts`+`types.ts`,TS→JS,几何纯函数不变)、`panelLayer.js`(原生 DOM 渲染壳,Pointer Events 拖动/8 向缩放/24px 吸附/停靠,对齐 kit `FloatingPanelLayer.tsx` 行为)、`panelKit.test` 迁移 kit 既有 12 项几何测试到 `node --test`。
- 现有三大块(波形、cue 列表、ASS 预览)改为面板挂载,默认停靠布局 = 当前固定布局(迁移期视觉零变化);布局持久化走 localStorage,沿用 agent 命名空间隔离。
- `floating-panel-kit` 本体留在 `tools/` 不动(无 LICENSE、React 版继续在 subfx-replica-platform 演化);移植代码即编辑器自有 MIT 代码,geometry 测试同迁。

## 4. 学习侧架构(复用 `feedback/`)

| 用户记忆分层 | 落点(已存在) | 本方案增量 |
| --- | --- | --- |
| 程序性(技能/规则) | `param_learner`(EMA+钳制)、`locked_params` | 事件级归因喂入:"VAD 静音>200ms 处切割"类规则从 journal 统计中显式化 |
| 语义(偏好画像) | `user_profile.yaml`(overrides+history) | journal 第三通道写入;新增"提前/推后偏移、留白偏好、CPS 上限"等编辑器维度参数 |
| 情节(案例) | `sample_manager` D2 样本 + `audio_fingerprint`(MFCC+马氏 KNN) | journal 摄取成样本;V2 在指纹库上扩展 sqlite-vec 向量检索(片段特征→最近案例→预应用) |

- **对齐方式**:现有 `aligner.py`(DTW+语义)继续负责"成品对成品";journal 事件本身就是过程对齐,**不依赖 DTW**——这是本方案相对现状最大的数据增量。
- **V3 触发机制**(D16):`feedback/` 配置 `learning.v3_trigger = {min_samples, min_coverage, max_conflict_rate}`,ingest 后达标则 CLI/编辑器面板提示"数据足够,可训练轻量序列模型";数值待 V1 分布定。
- **V4**:编辑器 MCP server 已有 8 工具,追加 `predict`(V3 模型推理)与 `retrieve`(V2 检索)两个工具即完成"大模型代理"闭环。

## 5. 质量路径(对应"较高识别质量"目标)

1. **免费 ground truth**:每次人工精修的最终导出 = 该音频的金标准字幕。journal+manifest 使边界误差(P50/P90,ms)、文本改动率、check 通过率可自动统计,进 D2/D3 数据集——这是现状完全没有的评估闭环。
2. **北极星指标**:每个音频的**平均人工编辑事件数**(按小时音频归一)。V1 学习参数、V2 检索预应用后,该指标应单调下降;不降说明归因或特征有问题,先于 V3 修。
3. **分工边界**:识别质量本身(引擎路由、边界精修、证据复核、声学校验门控)仍是管线侧职责;学习闭环收敛的是**用户偏好与系统性偏移**,不替代前者。
