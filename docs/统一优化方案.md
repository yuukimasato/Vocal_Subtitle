## 二、根因链分析

### 2.1 结束时间偏差的累积路径

来自 [字幕分析报告.md](字幕分析报告.md) 第 2.4 节的追踪：

```
faster-whisper ASR 词级时间戳 (末词 .end 天生略早 ~10-30ms)
  → BoundaryRefiner 检测到尾随静音后主动收缩段尾 (20-200ms)  ← ⚠ 最大贡献
    → TimeMapper 钳位阻止 ASR 时间自然延伸                    ← ⚠ 二次伤害
      → AcousticValidator 吸附时再减 10ms margin              ← ⚠ 三次削减
        → 声学校验结果被 LLM 合并作废（B1）                    ← ⚠ 架构 bug
          → SubtitleBuilder int() 截断                         ← 微小
            ─────────────────────────────────────────────────
              最终累积偏差 = 120-1050ms（平均 359ms）
```

### 2.2 架构 Bug 的连锁影响

来自 [pipeline-optimization-plan.md](pipeline-optimization-plan.md) 问题 1：

```
帧级衔接 → 声学校验 → LLM合并 → LLM优化
              ↑           ↑
          校验+吸附     合并改变边界
          结果在此      校验结果作废
          被作废
```

声学校验的 `snap_end_margin` 削减和端点吸附在合并阶段全部白做，且合并后的新边界未经物理骨架校验。

## 五、Phase 2：管线架构修复

**文件**: `vocal_subtitle/pipeline.py`

### 5.1 修正后处理阶段顺序（修复 B1 架构 Bug）

**当前顺序**（三种路径均存在）：
```
帧级无缝衔接 → 声学校验 → LLM 语义合并 → LLM 文本优化
```

**修正后**：
```
帧级无缝衔接 → LLM 语义合并 → 声学校验 → LLM 文本优化
```

**原因**：LLM 合并改变事件边界（合并多条字幕为一条），必须在校验之前完成。声学校验是最终边界的物理关卡。

**实现**：将三个路径（骨架分段、多块、单块）中声学校验代码块从 LLM 合并之前移到之后。

### 5.2 抽取公共后处理方法（修复 B4 代码冗余）

```python
def _post_process_events(
    self,
    events: List[SubtitleEvent],
    vocals_path: Path,
    audio: np.ndarray,
    sample_rate: int,
    stats: PipelineStats,
    ffmpeg_unified_result: Optional[Dict] = None,
) -> List[SubtitleEvent]:
    """后处理管线（三种路径共用）

    执行顺序经过精心设计：
    1. 帧级无缝衔接 — 消除相邻字幕的帧级间隙
    2. LLM 语义合并 — 改变事件边界（合并相邻字幕）
    3. 声学标尺校验 — 对最终边界做物理骨架校验
       （必须在 LLM 合并之后，因为合并改变了边界）

    调用方：骨架分段模式、多块路径、单块路径
    """
    # 1. 帧级无缝衔接
    try:
        from .merging.llm_merge_engine import apply_frame_seamless_stitching
        events = apply_frame_seamless_stitching(
            events, max_stitch_gap=self.config.subtitle.max_stitch_gap
        )
    except Exception as e:
        logger.warning("Frame seamless stitching failed: %s", e)

    # 2. LLM 语义合并（改变边界 → 必须在声学校验之前）
    if (
        self.config.merge_decision.llm_tier != "rule_only"
        and len(events) > 1
    ):
        events = self._run_llm_merge(events, audio, sample_rate, stats)

    # 3. 声学标尺校验（最终物理关卡，校验合并后的边界）
    if self.config.acoustic_validation.enabled:
        try:
            from .acoustic_validator import AcousticValidator
            self._progress.start_stage("acoustic", description="声学校验")
            validator = AcousticValidator(self.config.acoustic_validation)
            events, validation_report = validator.validate(
                events,
                audio_path=vocals_path,
                audio=audio,
                sample_rate=sample_rate,
                ffmpeg_unified_result=ffmpeg_unified_result,  # 复用骨架
            )
            stats.diagnostic_report = validation_report
            stats.stage_timings["acoustic"] = self._progress.finish_stage()
        except Exception as e:
            logger.warning("Acoustic validation failed: %s", e)

    return events
```

三个调用方各简化为一行调用。

### 5.3 VAD 双引擎并行化（修复 B2）

在 `_process_chunk_pipeline` 中将 Silero VAD 和 ffmpeg VAD 并行执行：

```python
from concurrent.futures import ThreadPoolExecutor

# Stage 2 + 2.5: 并行执行 Silero VAD 和 ffmpeg VAD
with ThreadPoolExecutor(max_workers=2) as executor:
    future_silero = executor.submit(self._run_vad, audio, sample_rate)
    future_ffmpeg = executor.submit(unified_ffmpeg_pass, vocals_path)

    vad_segments = future_silero.result()
    ffmpeg_result = future_ffmpeg.result()

# 融合（逻辑不变）
if self.config.fusion.enabled:
    vad_segments = fusion_engine.fuse(vad_segments, ffmpeg_segments, ...)
```

**预期效果**：该阶段耗时从 `T_silero + T_ffmpeg` 降至 `max(T_silero, T_ffmpeg)`，减少 30-50%。

### 5.4 ffmpeg 骨架复用（修复 B3）✅

- `_process_chunk_pipeline` 返回值增加 ctx（含骨架）
- 后处理调用 `AcousticValidator.validate()` 时传入 `ffmpeg_unified_result`
- **三种路径均已复用骨架**：
  - 单块路径：直接传递 `ctx.ffmpeg_unified_result`
  - 骨架分段模式：`_process_skeleton_segmented` 返回全局 ffmpeg 结果，传入 `_post_process_events`
  - 多块路径：后处理前对完整音频做一次 `unified_ffmpeg_pass`，供声学校验复用

## 六、Phase 3：核心模块代码修复

### 6.1 BoundaryRefiner — 段尾收缩逻辑重写（修复 A1 主因）

**文件**: `vocal_subtitle/asr/boundary_refiner.py` 行 116-126

**问题**: 对所有 >50ms 的尾随静音一律向内收缩，不区分"刻意保留的 padding"和"真实多余静音"。

**当前逻辑**:
```python
if trailing_silence > 0.05 and last_word_conf >= cfg.min_boundary_confidence:
    shrink = min(trailing_silence - 0.02, cfg.max_shrink_ms / 1000)
    seg.end -= shrink
```

**修改后**:
```python
if trailing_silence > 0.05 and last_word_conf >= cfg.min_boundary_confidence:
    # 区分 "padding 尾随" 和 "真实拖尾静音"
    # trailing ≤ 100ms: 可能是语尾渐弱或刻意 padding，不收缩
    # trailing > 100ms: 明显多余静音，收缩但保留 50ms 余量
    if trailing_silence > 0.10:
        shrink = min(trailing_silence - 0.05, cfg.max_shrink_ms / 1000)
        seg.end -= shrink
    # else: 不收缩
```

**变更**: 触发阈值 0.05→0.10（100ms），保留余量 0.02→0.05（50ms）。

### 6.2 TimeMapper — 钳位逻辑优化

**文件**: `vocal_subtitle/mapping/time_mapper.py` 行 134-137

**问题**: 当 BoundaryRefiner 收缩段尾后，`speech_seg.end` 变小，钳位阻止 ASR 时间戳自然延伸。

**当前逻辑**:
```python
global_end = min(global_end, speech_seg.end + self.seamless_threshold)
```

**修改后**:
```python
# 钳位上限至少不低于 ASR 自身时间戳 - 50ms
# 防止段尾被 BoundaryRefiner 收缩后钳住 ASR 的正确结束时间
_clamp_ceiling = max(speech_seg.end, global_end - 0.05) + self.seamless_threshold
global_end = min(global_end, _clamp_ceiling)
```

### 6.3 AcousticValidator — 吸附方向保护

**文件**: `vocal_subtitle/acoustic_validator.py` 行 214-225

**问题**: 吸附后减去 `snap_end_margin`，当吸附是正确方向（延长）时反而造成回退。

**当前逻辑**:
```python
if nearest_end > event.end:
    event.end = nearest_end - cfg.snap_end_margin
```

**修改后**:
```python
if nearest_end > event.end:
    candidate_end = nearest_end - cfg.snap_end_margin
    # 保护：只在吸附能延长结束时间时才执行
    if candidate_end > event.end:
        event.end = candidate_end
    # 否则保持原值（相邻骨架边界很近，不强制缩短）
```

## 七、Phase 4：新增模块 + 集成

### 7.1 EndTimePostValidator（新建）

**文件**: `vocal_subtitle/mapping/end_time_validator.py`

**用途**: 在管线所有阶段完成后、字幕输出前，做最后一轮结束时间全局校验。

**校验规则**:
1. 兜底：`end > start`（异常修复为 +500ms）
2. 最小时长：`duration ≥ 200ms`
3. 微间隙合并：`gap < 30ms`（视频一帧 33ms@30fps）→ 延长前一条覆盖间隙
4. 最大间隙告警：同说话人 `gap > 1.5s` → 日志告警（可能漏检）

**集成位置**: `pipeline.py` 的 `run()` 方法，LLM 优化之后、字幕输出之前（`EndTimePostValidator.validate()` 调用）。

### 7.2 TextNormalizer（新建）

**文件**: `vocal_subtitle/asr/text_normalizer.py`

**用途**: 对 ASR 输出文本做规范化纠错，解决 A3（专有名词错误）和 A4（数字编号丢失）。

**纠错类别**:
1. **数字编号恢复**: `"One answer"` → `"1. Answer"`（句首 + 后续内容为独立主题时）
2. **专有名词纠错**: 内置词典 `{"mahood": "Mehood", "lusty": "Lestie", ...}`（可配置扩展）
3. **标点规范化**: 句末无标点自动补 `.`，修复多余空格
4. **批量处理**: `normalize_batch()` 支持批量调用

**集成位置**: `pipeline.py` 的 `_run_asr()` 方法，ASR 识别完成后立即调用。
