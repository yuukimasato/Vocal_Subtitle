# 字幕时间轴精度优化方案

> 基于 subtitle.ass（自动生成）与 60.ass（手动校正）的对比分析
>
> 分析日期：2026-07-04

---

## 一、问题诊断

### 1.1 时间轴偏差量化

对比 subtitle.ass（自动生成，49条）与 60.ass（Aegisub 手动校正，49条），逐条匹配后的统计：

| 指标 | Start 偏差 | End 偏差 |
|------|-----------|---------|
| **平均偏差** | **-109ms**（自动偏早） | **-71ms**（自动偏早） |
| **绝对平均误差** | **271ms** | **567ms** |
| **标准差** | 359ms | 933ms |
| **最大误差** | 1120ms | **4300ms** |
| **误差 > 300ms 的占比** | ~30% | **~55%** |

结论：**超过一半的字幕结束时间误差超过 300ms，其中部分极端案例偏离超过 4 秒**。

### 1.2 典型错误模式

通过逐条对比发现三种典型错误模式：

#### 模式 A：系统性的"切尾"（占比最高，~40%）

自动生成的字幕结束时间**系统性提前** 100-400ms，导致句尾被截断：

```
#19 "Got it. 1. Listen attentively."
Auto:  52.46 → 55.04  (实际内容到 55s 就截断)
Manual: 52.59 → 52.98  (拆分出 "Got it." 独立一行)
        53.33 → 55.31  (1. Listen attentively 正确结束)
→ 问题：自动版把两句合并，结束时间早于实际语音结束
```

#### 模式 B：VAD 边界偏移导致段对齐错误（~30%）

VAD 段的轻微偏移会被级联放大，导致相邻行的起止时间全部错位：

```
#14-16 "Good afternoon, Mehood Lestee Hotel, Wuhan HK Central Flagship Store front desk. This is Xiaoxi."
Auto:   38.40→41.90 + 41.90→43.88 + 43.88→44.91  (3行，边界错位)
Manual: 38.79→40.93 + 41.25→44.21 + 44.55→45.51  (3行，精确对齐波形)
→ 第14行 end 差 +970ms，第16行 end 差 -600ms
```

#### 模式 C：段内静音导致 ASR 时间戳漂移（~15%）

当 VAD 段内部包含较长的自然停顿（如换气、思考停顿），ASR 模型（faster-whisper）的内部注意力机制会产生时间戳偏移：

```
#10-11 "2. Identify yourself, state the hotel name..."
Auto:   31.65→31.81  ("2." 单独一行)
        31.81→35.39  (后续文本)
Manual: 31.77→36.11  (合并为完整的 "2. Identify yourself:")
        36.37→37.49  (state the hotel name...)
→ 段边界完全错位，偏离达 4.3 秒
```

### 1.3 根因分析

问题出在三个环节的累积效应：

```
VAD 边界 32ms 帧精度 (±16ms)
    ↓
+ RMS 精修 (±5ms 理论，实际因能量阈值不稳定)
    ↓
+ padding 仅 50ms（不足以覆盖边界模糊区）
    ↓
+ ASR 段内时间戳偏移（长段或含静音段时更明显）
    ↓
= 最终误差 100-400ms（甚至更大）
```

**核心矛盾**：当前流程是 VAD 先切段 → ASR 在段内识别。VAD 边界决定了 ASR 的"世界范围"，如果 VAD 边界本身有偏差，ASR 的时间戳再精确也无法修正。

---

### 1.4 核心方法论：先切后合（Split-Then-Merge）

#### 通过具体案例理解问题本质

以 60.ass（手动校正版）中的真实字幕为例：

**案例 1：「宁可多切，后用 LLM 合并」**

```
60.ass 目前的字幕（一句话跨越了内部静音）:
├─ 01:14.85 → 01:17.89  "Before ending the call, repeat key details"
│  └─ 总长 3.04s，但中间有 330ms 的自然停顿（换气/思考）

如果严格按静音区域切分:
├─ 01:14.85 → 01:16.09  "Before ending the call,"
│  └─ 持续 1.24s，干净的人声段
│
├─ [330ms 静音间隙: 01:16.09 → 01:16.42]
│
├─ 01:16.42 → 01:17.90  "repeat key details"
   └─ 持续 1.48s，干净的人声段
```

**关键判断**：这两段在**声学上**是两个独立的人声爆发（中间有明确的静音），但在**语义上**是一句完整的话。正确的处理策略是：

> 声学层先切分 → 每段各自精确 ASR → LLM 语义层判断是否合并

**案例 2：「长句内部虽有停顿，但语义不可拆分」**

```
60.ass 目前的字幕:
├─ 01:22.58 → 01:26.18  "So I have you down for a non-smoking king room
│                          tomorrow, is that right?"
│  └─ 总长 3.60s，一句完整的确认问句

内部可能存在的微小停顿:
├─ 01:22.58 → 01:24.20  "So I have you down for a non-smoking king room"
├─ [~150ms 停顿]
├─ 01:24.35 → 01:25.30  "tomorrow,"
├─ [~200ms 停顿]  
├─ 01:25.50 → 01:26.18  "is that right?"
```

这里即使声学层检测到了停顿，LLM 也应该判断**不拆分**——因为这是一句完整的确认问句，拆分后会破坏阅读体验。

#### 方法论总结

```
传统方案（当前 Pipeline）:
  音频 → VAD切段 → 合并策略(规则) → ASR → 字幕
         ↑                       ↑
    边界可能不精确        规则合并破坏精确边界

优化方案（Split-Then-Merge）:
  音频 → VAD+ffmpeg精细切段 → 每段独立ASR → LLM语义合并 → 字幕
         ↑                        ↑              ↑
    三方法融合确保         声学干净的输入    语义判断优于
    边界采样级精度         时间戳更准        规则合并
```

**核心原则**：

| 层 | 职责 | 工具 | 输出 |
|----|------|------|------|
| **声学层** | 精确检测静音边界，激进切分 | VAD + ffmpeg + RMS | 大量短片段（每个只含连续人声） |
| **识别层** | 在干净短片段上获得精确时间戳 | faster-whisper | 每段的文本 + 精确起止时间 |
| **语义层** | 判断哪些片段应合并为一条字幕 | LLM | 合并后的字幕（含精确时间轴） |

**声学层要"宁可多切，不可漏切"**——多切了，LLM 可以语义合并；切少了，时间轴就偏差了，LLM 无法修正时间。

#### LLM 语义合并的关键判断维度

对于两个相邻的语音片段 A 和 B，LLM 需要判断是否合并：

```
判断维度：
1. 语法完整性：A 是否是一个不完整的句子？（如 "Before ending the call," 显然未完）
2. 间隔时长：A 和 B 之间的静音有多长？
   - < 200ms：很可能是句内停顿 → 倾向合并
   - 200-600ms：可能是换气或句间停顿 → 需要语义判断
   - > 600ms：很可能是新句子 → 倾向不合并
3. 语义连续性：A+B 组合后是否形成完整语义单元？
4. 字幕时长：合并后的总时长是否合理？（目标 1-5s）
```

案例 1 的判断：
- "Before ending the call," → 语法不完整（悬挂从句）→ **合并**
- 间隔 330ms → 在语义判断区间内 → 需要 LLM
- "repeat key details" → 缺少主语，与上文互补 → **合并**
- 合并后总长 3.05s → 合理 ✓

案例 2 的判断：
- 每个片段语法不完整 → 语义上倾向合并
- 合并后是完整问句 → **合并**
- 合并后总长 3.60s → 合理 ✓

### 1.5 宏观分层：用长静音将长音频预先切块

#### 问题

上述"先切后合"架构解决了微观层面的时间轴精度。但对于**10分钟以上的长音频**，还存在宏观层面的问题：

```
30分钟音频
├─ 0-5分钟: 开场 + 话题A
├─ [3秒静音] ← 话题转换的自然停顿
├─ 5-15分钟: 话题B
├─ [5秒静音] ← 段落间隔
├─ 15-25分钟: 话题C
├─ [4秒静音]
├─ 25-30分钟: 总结
```

如果整段 30 分钟音频一次性处理，会有以下问题：

| 问题 | 说明 |
|------|------|
| **内存压力** | 30 分钟 16kHz mono WAV = ~57MB，加上模型占用，容易 OOM |
| **合并策略误判** | 相距 10 分钟的语音段，如果间隔被误判为短静音，可能被不合理合并 |
| **LLM batch 跨话题** | LLM 合并引擎可能收到跨越多个话题的片段，语义判断混乱 |
| **单点故障** | 处理 25 分钟处出错 → 整个任务失败 |
| **不可并行** | 一个长 Pipeline 无法利用多 GPU |

#### 方案：ffmpeg 长静音 → 宏观切块

用 ffmpeg silencedetect 找到 **>2 秒的长静音**，在这些位置将音频切分为独立的大块，每块作为一个独立的 Pipeline 运行：

```
30分钟音频
    │
    ▼ ffmpeg silencedetect (noise=-30dB, d=2.0s)
    │
    ├── 块1: 0:00 → 5:02  (302s)   ─→ Pipeline.run() → 字幕1
    ├── 块2: 5:05 → 14:58 (593s)   ─→ Pipeline.run() → 字幕2
    ├── 块3: 15:03 → 25:12 (609s)  ─→ Pipeline.run() → 字幕3
    └── 块4: 25:16 → 30:00 (284s)  ─→ Pipeline.run() → 字幕4
                                          │
                                          ▼
                                    时间偏移合并 → 完整字幕
```

#### 关键优势

**1. 保证语音完整性**

切分点选在静音中间，不会切断任何说话内容：

```
"今天的节目就到这里" [2.8秒静音] "欢迎收听下一期"
                     ↑ 在此切分 —— 两边的话都是完整的
```

对比 naive 方案（按时间等分）：
```
"今天的节目就到这" [被切断!] "里欢迎收听下一期"
                  ↑ 人为制造了识别困难
```

**2. 时间轴误差隔离**

```
不分块:
  块1的100ms边界误差 ──→ 可能影响下游合并判断 ──→ 级联错误

分块:
  块1: 100ms误差 ⊗ (隔离在块1内)
  块2: 50ms误差  ⊗ (隔离在块2内)
  块3: 80ms误差  ⊗ (隔离在块3内)
  → 各块的误差互不影响，不会跨块累计
```

**3. 内存友好 + 可并行**

| | 不分块 | 分块 |
|------|--------|------|
| 单次加载 | 30min 全部音频 | 每块 5min |
| 峰值内存 | ~57MB + 模型 | ~10MB + 模型 |
| GPU 利用 | 串行 | 可 2-3 路并行 |
| 失败恢复 | 全部重跑 | 只重跑失败的块 |

**4. LLM 合并引擎天然受益**

每个大块内部是一个完整的"话题单元"，LLM 合并时不会看到跨越 10 分钟的无关片段。这降低了 LLM 做出不合理合并决策的概率。

#### 递归切分策略

如果某块仍然太长（如 > 3 分钟），用更敏感的静音阈值递归切分：

```python
def split_audio_at_silence(
    audio_path: Path,
    target_chunk_duration: float = 60.0,   # 目标块时长
    max_chunk_duration: float = 180.0,     # 最大容忍块时长
    silence_thresholds: List[tuple] = [    # (noise_db, min_duration)
        (-30, 3.0),   # 第一轮：找 >3s 的静音
        (-35, 1.5),   # 第二轮：找 >1.5s 的静音（对仍然太长的块）
        (-40, 0.8),   # 第三轮：找 >0.8s 的静音
    ],
) -> List[tuple]:
    """递归策略：用越来越敏感的静音阈值切分，直到每块都足够短"""
    chunks = _split_at_silence(audio_path, *silence_thresholds[0])
    
    # 对仍太长的块，用下一级阈值递归切分
    result = []
    for chunk_start, chunk_end in chunks:
        duration = chunk_end - chunk_start
        if duration > max_chunk_duration and len(silence_thresholds) > 1:
            # 提取该块的音频片段，递归切分
            sub_chunks = split_audio_at_silence(
                extract_chunk(audio_path, chunk_start, chunk_end),
                target_chunk_duration,
                max_chunk_duration,
                silence_thresholds[1:],  # 下一级阈值
            )
            # 偏移回全局时间
            for sc_start, sc_end in sub_chunks:
                result.append((chunk_start + sc_start, chunk_start + sc_end))
        else:
            result.append((chunk_start, chunk_end))
    
    return result
```

#### 与微观切分的关系

两个层级的分工明确：

```
                    宏观切分                    微观切分
                   (方案零)                  (方案三+五)
                     │                           │
输入:   30分钟完整音频                             每个 ~60s 大块
检测:   ffmpeg 找 >2s 长静音          VAD+ffmpeg+RMS 找静音
输出:   4-6个独立大块                  每个大块内的纯人声小段
作用:   隔离误差、降内存、并行         精确时间轴、消除ASR漂移
后续:   每块独立 Pipeline              ASR → LLM语义合并

30min ──→ [大块1] ──→ VAD → 切分 → ASR → LLM合并 → 字幕1
          [大块2] ──→ VAD → 切分 → ASR → LLM合并 → 字幕2
          [大块3] ──→ VAD → 切分 → ASR → LLM合并 → 字幕3
          [大块4] ──→ VAD → 切分 → ASR → LLM合并 → 字幕4
                                                     │
                                              时间偏移 → 完整字幕
```

#### 适用场景

| 音频时长 | 是否需要宏观切分 | 说明 |
|---------|:---:|------|
| < 3 分钟 | ❌ 不需要 | 当前 Pipeline 直接处理即可 |
| 3-10 分钟 | ⚠️ 可选 | 如有 GPU 内存压力则开启 |
| 10-30 分钟 | ✅ 推荐 | 显著收益 |
| > 30 分钟 | ✅ 必须 | 不分块几乎无法处理 |

#### 对测试样本的实际分析

当前测试音频（139 秒，~2分20秒）检测到 4 处长静音：

```
静音分布:
  0.00s → 8.78s  (开头静音，8.78s)
  12.35s → 15.60s (段落间静音，3.24s)
  49.27s → 52.60s (段落间静音，3.33s)
  129.0s → 139.5s (结尾静音，10.52s)

有效语音块: 8.78→12.35 (3.6s), 15.60→49.27 (33.7s), 52.60→129.0 (76.4s)
```

对于这个 2 分钟的样本，宏观切分收益不大（只有一个 76s 的块可能需要递归切分）。但对于你设想的十几分钟、几十分钟的音频，这个方案的价值会非常显著。

> **结论**：宏观切分（静音边界预分块）是方案三（段内静音预切分）在更大尺度上的自然延伸。两者共同构成了"长静音切大块 → 短静音切小段 → LLM 语义合并"的三级分层架构。对于长音频，这几乎是必需的预处理步骤。

### 2.2 方案一：ffmpeg silencedetect 并行 VAD（核心新功能）

#### 原理

ffmpeg 内置 `silencedetect` 滤波器使用纯能量（dB）阈值判断静音，与 Silero VAD 的神经网络方法形成互补：

| 维度 | Silero VAD | ffmpeg silencedetect |
|------|-----------|---------------------|
| 判断依据 | 声学特征 + 神经网络 | 纯能量 (dB RMS) |
| 边界精度 | ~32ms（帧级） | ~1ms（采样级） |
| 低音量语音 | ✅ 可识别 | ❌ 可能丢失 |
| 乐器残留 | ✅ 较鲁棒 | ❌ 可能误检 |
| 对纯静音 | 有时边界偏松 | ✅ 精准 |
| 计算开销 | 需 GPU/CPU 推理 | 极低（C 实现） |

**两者互补**：Silero VAD 擅长区分"人声 vs 噪声"，ffmpeg 擅长精确检测"有声 vs 静音"的物理边界。

#### 实现方案

在 `vocal_subtitle/vad/` 下新增 `ffmpeg_vad.py`：

```python
"""ffmpeg silencedetect VAD 引擎

基于 ffmpeg silencedetect 滤波器的语音活动检测。
纯能量阈值判断，与神经网络 VAD 互补。

协议: 通过 CLI 子进程调用 ffmpeg（GPL），不构成衍生作品。
"""

import logging
import subprocess
import re
from pathlib import Path
from typing import List
import numpy as np

from .base import SpeechSegment, VADEngine

logger = logging.getLogger(__name__)


class FFmpegSilenceVAD(VADEngine):
    """ffmpeg silencedetect 引擎
    
    使用 ffmpeg 内置 silencedetect 滤波器检测语音区间。
    优势：采样级精度、零模型加载开销、不受 SOCKS 代理影响。
    劣势：纯能量判断，不区分人声与乐器残留。
    
    推荐用法：与 Silero VAD 并行使用，通过边界融合层取优。
    """

    def __init__(self):
        pass

    @property
    def name(self) -> str:
        return "ffmpeg-silence"

    def load_model(self) -> None:
        """ffmpeg 无需加载模型"""
        pass

    def detect(
        self,
        audio_path: Path,
        threshold: float = -35.0,     # dB, 更灵敏的默认值
        min_speech_duration_ms: int = 250,
        min_silence_duration_ms: int = 400,
    ) -> List[SpeechSegment]:
        """检测音频文件中的语音区间
        
        Args:
            audio_path: 音频文件路径
            threshold: 静音阈值 (dB)，默认 -35dB（-30 保守，-35 灵敏）
            min_speech_duration_ms: 最小语音时长
            min_silence_duration_ms: 最小静音时长
        
        Returns:
            SpeechSegment 列表
        """
        # silencedetect 输出的是静音区间，需要反转得到语音区间
        silence_intervals = self._detect_silence(
            audio_path,
            noise_db=threshold,
            min_silence_duration=min_silence_duration_ms / 1000.0,
        )
        
        # 反转：静音区间 → 语音区间
        total_duration = self._get_duration(audio_path)
        speech_segments = self._invert_intervals(
            silence_intervals, total_duration,
            min_speech_duration=min_speech_duration_ms / 1000.0,
        )
        
        return [
            SpeechSegment(start=s, end=e, confidence=0.9)
            for s, e in speech_segments
        ]

    def detect_on_array(
        self,
        audio: np.ndarray,
        sample_rate: int,
        threshold: float = -35.0,
        min_speech_duration_ms: int = 250,
        min_silence_duration_ms: int = 400,
    ) -> List[SpeechSegment]:
        """在 numpy 数组上检测（通过临时 WAV 文件）
        
        为避免重复写文件，生产环境建议直接调用 detect()。
        """
        import tempfile
        from ..utils.audio_utils import AudioUtils
        
        with tempfile.NamedTemporaryFile(suffix=".wav", delete=False) as f:
            tmp_path = Path(f.name)
        
        try:
            AudioUtils.save_audio(audio, tmp_path, sample_rate)
            return self.detect(
                tmp_path,
                threshold=threshold,
                min_speech_duration_ms=min_speech_duration_ms,
                min_silence_duration_ms=min_silence_duration_ms,
            )
        finally:
            tmp_path.unlink(missing_ok=True)

    # ---- 内部方法 ----

    @staticmethod
    def _detect_silence(
        audio_path: Path,
        noise_db: float = -35.0,
        min_silence_duration: float = 0.4,
    ) -> List[tuple]:
        """调用 ffmpeg silencedetect 检测静音区间
        
        Returns:
            [(silence_start, silence_end), ...] 单位：秒
        """
        cmd = [
            "ffmpeg", "-y", "-loglevel", "info",
            "-i", str(audio_path),
            "-af", (
                f"silencedetect="
                f"noise={noise_db}dB:"
                f"d={min_silence_duration}"
            ),
            "-f", "null", "-",
        ]
        
        result = subprocess.run(cmd, capture_output=True, text=True, timeout=120)
        
        # 解析 stderr 中的 silencedetect 输出
        # silence_start: 12.5
        # silence_end: 15.2 | silence_duration: 2.7
        intervals = []
        current_start = None
        
        for line in result.stderr.split("\n"):
            start_match = re.search(r"silence_start:\s*([\d.]+)", line)
            end_match = re.search(r"silence_end:\s*([\d.]+)", line)
            
            if start_match:
                current_start = float(start_match.group(1))
            elif end_match and current_start is not None:
                end_time = float(end_match.group(1))
                intervals.append((current_start, end_time))
                current_start = None
        
        logger.info(
            "ffmpeg silencedetect (%.0fdB, min=%.2fs): %d silence intervals",
            noise_db, min_silence_duration, len(intervals),
        )
        return intervals

    @staticmethod
    def _invert_intervals(
        silence_intervals: List[tuple],
        total_duration: float,
        min_speech_duration: float = 0.25,
    ) -> List[tuple]:
        """反转静音区间为语音区间
        
        Args:
            silence_intervals: [(start, end), ...] 静音区间
            total_duration: 音频总时长
            min_speech_duration: 最小语音段时长（过滤过短段）
        
        Returns:
            [(speech_start, speech_end), ...]
        """
        if not silence_intervals:
            return [(0.0, total_duration)]
        
        speech = []
        prev_end = 0.0
        
        for s_start, s_end in silence_intervals:
            if s_start - prev_end >= min_speech_duration:
                speech.append((prev_end, s_start))
            prev_end = s_end
        
        # 最后一段（最后一段静音结束后）
        if total_duration - prev_end >= min_speech_duration:
            speech.append((prev_end, total_duration))
        
        return speech

    @staticmethod
    def _get_duration(audio_path: Path) -> float:
        """获取音频时长"""
        cmd = [
            "ffprobe", "-v", "quiet",
            "-show_entries", "format=duration",
            "-of", "csv=p=0",
            str(audio_path),
        ]
        result = subprocess.run(cmd, capture_output=True, text=True, timeout=10)
        return float(result.stdout.strip())
```

### 2.3 方案二：三方法边界融合引擎（核心新功能）

#### 原理

三种检测方法各有盲区，融合后可互补：

```
Silero VAD    ffmpeg silence    RMS Energy Scan
    │               │                  │
    ▼               ▼                  ▼
┌─────────────────────────────────────────────┐
│              边界融合引擎                     │
│                                             │
│  策略：                                      │
│  1. 三方法各自检测语音/静音区间               │
│  2. 对每个边界点，三种方法投票                │
│  3. 至少 2/3 方法一致 → 采纳                  │
│  4. 仅 1/3 方法标记 → 标记为"低置信度"，      │
│     使用更宽的 padding 补偿                   │
│  5. 对高置信度边界，取三种方法的最紧边界       │
│     （即最早 onset + 最晚 offset）             │
└─────────────────────────────────────────────┘
```

#### 实现方案

在 `vocal_subtitle/vad/` 下新增 `boundary_fusion.py`：

```python
"""边界融合引擎

融合 Silero VAD、ffmpeg silencedetect、RMS Energy Scan 
三种方法的检测结果，输出高置信度的语音段边界。

算法:
1. 时间轴离散化（10ms 网格）
2. 每种方法投票：该网格是否为语音
3. 2/3 多数决 → 高置信度
4. 对高置信边界，向前/后扫描找到精确跃迁点
"""

import logging
from dataclasses import dataclass
from typing import List, Optional, Tuple
import numpy as np

from .base import SpeechSegment

logger = logging.getLogger(__name__)


@dataclass
class FusionConfig:
    """融合配置"""
    grid_resolution: float = 0.01       # 时间网格精度（秒），10ms
    min_consensus: int = 2              # 最少共识方法数（共3种方法）
    high_conf_padding: float = 0.03     # 高置信边界的 padding
    low_conf_padding: float = 0.12      # 低置信边界的 padding
    min_speech_duration: float = 0.25   # 最小语音段（秒）


class BoundaryFusion:
    """三方法边界融合器"""

    def __init__(self, config: Optional[FusionConfig] = None):
        self.config = config or FusionConfig()

    def fuse(
        self,
        silero_segments: List[SpeechSegment],
        ffmpeg_segments: List[SpeechSegment],
        audio: np.ndarray,
        sample_rate: int,
    ) -> List[SpeechSegment]:
        """融合三种检测结果

        Args:
            silero_segments: Silero VAD 检测结果
            ffmpeg_segments: ffmpeg silencedetect 检测结果
            audio: 音频数组
            sample_rate: 采样率

        Returns:
            融合后的高置信度语音段列表
        """
        cfg = self.config
        total_duration = len(audio) / sample_rate

        # Step 1: 生成 RMS 能量检测结果（第三种方法）
        rms_segments = self._detect_by_rms_energy(
            audio, sample_rate,
            speech_threshold_ratio=3.0,
            min_speech_duration=cfg.min_speech_duration,
        )

        # Step 2: 时间轴离散化 + 投票
        num_bins = int(total_duration / cfg.grid_resolution) + 1
        votes = np.zeros(num_bins, dtype=np.int8)

        self._vote(votes, silero_segments, cfg.grid_resolution)
        self._vote(votes, ffmpeg_segments, cfg.grid_resolution)
        self._vote(votes, rms_segments, cfg.grid_resolution)

        # Step 3: 多数决 → 高/低置信度语音网格
        speech_mask = votes >= cfg.min_consensus
        high_conf_mask = votes >= 3  # 三方法全票

        # Step 4: 连续语音网格 → 语音段
        fused = self._mask_to_segments(
            speech_mask, high_conf_mask, votes,
            cfg.grid_resolution, total_duration,
            cfg.min_speech_duration,
        )

        # Step 5: 根据置信度应用不同的 padding
        fused = self._apply_adaptive_padding(
            fused, audio, sample_rate,
            high_conf_padding=cfg.high_conf_padding,
            low_conf_padding=cfg.low_conf_padding,
        )

        logger.info(
            "Fusion: Silero=%d + FFmpeg=%d + RMS=%d → %d segments",
            len(silero_segments), len(ffmpeg_segments),
            len(rms_segments), len(fused),
        )
        return fused

    # ---- 内部方法 ----

    def _vote(
        self,
        votes: np.ndarray,
        segments: List[SpeechSegment],
        resolution: float,
    ) -> None:
        """将检测结果投射到投票网格"""
        for seg in segments:
            start_bin = int(seg.start / resolution)
            end_bin = int(seg.end / resolution)
            start_bin = max(0, start_bin)
            end_bin = min(len(votes), end_bin + 1)
            votes[start_bin:end_bin] += 1

    @staticmethod
    def _detect_by_rms_energy(
        audio: np.ndarray,
        sample_rate: int,
        speech_threshold_ratio: float = 3.0,
        min_speech_duration: float = 0.25,
        frame_ms: int = 10,
        hop_ms: int = 5,
    ) -> List[SpeechSegment]:
        """基于 RMS 能量的纯能量语音检测

        比 ffmpeg silencedetect 更细粒度（10ms 帧 + 5ms hop）。
        """
        from ..utils.audio_utils import AudioUtils

        total_samples = len(audio)
        frame_size = int(frame_ms / 1000 * sample_rate)
        hop_size = int(hop_ms / 1000 * sample_rate)
        if frame_size < 1:
            return []

        # 估计静音 RMS 阈值
        silence_rms = AudioUtils.estimate_silence_rms(audio, sample_rate, percentile=20)
        speech_threshold = max(silence_rms * speech_threshold_ratio, 1e-6)

        # 逐帧计算 RMS
        frame_times = []
        is_speech = []
        for i in range(0, total_samples - frame_size + 1, hop_size):
            frame = audio[i : i + frame_size]
            rms = float(np.sqrt(np.mean(frame ** 2)))
            frame_times.append(i / sample_rate)
            is_speech.append(rms > speech_threshold)

        if not is_speech:
            return []

        # 连续语音帧 → 语音段
        segments = []
        in_speech = False
        seg_start = 0.0

        for i, speech in enumerate(is_speech):
            t = frame_times[i]
            if speech and not in_speech:
                seg_start = t
                in_speech = True
            elif not speech and in_speech:
                if t - seg_start >= min_speech_duration:
                    segments.append(SpeechSegment(
                        start=seg_start, end=t, confidence=0.7,
                    ))
                in_speech = False

        if in_speech:
            final_t = frame_times[-1] + frame_ms / 1000
            if final_t - seg_start >= min_speech_duration:
                segments.append(SpeechSegment(
                    start=seg_start, end=final_t, confidence=0.7,
                ))

        return segments

    def _mask_to_segments(
        self,
        speech_mask: np.ndarray,
        high_conf_mask: np.ndarray,
        votes: np.ndarray,
        resolution: float,
        total_duration: float,
        min_duration: float,
    ) -> List[SpeechSegment]:
        """连续语音网格 → SpeechSegment 列表"""
        segments = []
        in_speech = False
        seg_start = 0.0
        seg_high_conf = True

        for i, is_speech in enumerate(speech_mask):
            t = i * resolution
            if is_speech and not in_speech:
                seg_start = t
                in_speech = True
                seg_high_conf = True
            elif is_speech and in_speech:
                if not high_conf_mask[i]:
                    seg_high_conf = False
            elif not is_speech and in_speech:
                duration = t - seg_start
                if duration >= min_duration:
                    confidence = 0.95 if seg_high_conf else 0.65
                    segments.append(SpeechSegment(
                        start=seg_start, end=t,
                        confidence=confidence,
                    ))
                in_speech = False

        if in_speech:
            duration = total_duration - seg_start
            if duration >= min_duration:
                segments.append(SpeechSegment(
                    start=seg_start, end=total_duration,
                    confidence=0.95 if seg_high_conf else 0.65,
                ))

        return segments

    def _apply_adaptive_padding(
        self,
        segments: List[SpeechSegment],
        audio: np.ndarray,
        sample_rate: int,
        high_conf_padding: float,
        low_conf_padding: float,
    ) -> List[SpeechSegment]:
        """根据置信度应用不同 padding，并用 RMS 精修边界"""
        from ..utils.audio_utils import AudioUtils

        for seg in segments:
            is_high_conf = seg.confidence >= 0.9
            pad = high_conf_padding if is_high_conf else low_conf_padding

            # 先用 RMS 能量精修边界
            AudioUtils.refine_speech_boundaries(
                [seg], audio, sample_rate,
                window=0.15,
                speech_silence_ratio=2.5,
            )

            # 再应用 padding
            seg.start = max(0.0, seg.start - pad)
            seg.end = min(len(audio) / sample_rate, seg.end + pad)

        return segments
```

### 2.4 方案三：段内静音预切分（解决模式 C 的根本方案）

#### 原理

当前流程对 VAD 段**内部**的自然停顿（换气、思考停顿）不敏感——这些停顿如果较长（如 0.5-1.5s），会让 ASR 模型在段内遇到"相对长"的静音，导致时间戳偏移。

**解决**：在 VAD 段内部，用 10ms RMS 能量扫描再次检测 > 阈值的静音间隙，在这些间隙处将段**预切分**为更短的子段，然后分别送入 ASR。

```
当前方案：
  VAD段 [████████░░░░░░░█████████████] → 一整块送ASR
                                          ↑ 内部0.8s静音影响时间戳

优化方案：
  VAD段 [████████] [█████████████] → 切分为2块，分别ASR
                  ↑ 在静音处切割
```

#### 实现

在 `MergeStrategy` 中新增 `_pre_split_at_silence_gaps()`:

```python
def _pre_split_at_silence_gaps(
    self,
    segments: List[SpeechSegment],
    audio: np.ndarray,
    sample_rate: int,
    silence_gap_threshold: float = 0.5,  # 内部静音 > 0.5s 则切分
    frame_ms: int = 10,
) -> List[SpeechSegment]:
    """在 VAD 段内部的静音间隙处预切分
    
    目的：避免段内长静音导致 ASR 时间戳漂移。
    """
    from ..utils.audio_utils import AudioUtils
    
    silence_rms = AudioUtils.estimate_silence_rms(audio, sample_rate)
    frame_size = int(frame_ms / 1000 * sample_rate)
    hop_size = max(1, frame_size // 2)
    
    result = []
    for seg in segments:
        start_sample = int(seg.start * sample_rate)
        end_sample = int(seg.end * sample_rate)
        
        # 逐帧扫描段内的静音区间
        silence_starts = []
        silence_ends = []
        in_silence = False
        silence_begin_sample = 0
        
        for i in range(start_sample, end_sample - frame_size + 1, hop_size):
            frame = audio[i : i + frame_size]
            rms = float(np.sqrt(np.mean(frame ** 2)))
            is_silent = rms < silence_rms * 2.0
            
            if is_silent and not in_silence:
                silence_begin_sample = i
                in_silence = True
            elif not is_silent and in_silence:
                silence_duration = (i - silence_begin_sample) / sample_rate
                if silence_duration >= silence_gap_threshold:
                    silence_starts.append(silence_begin_sample / sample_rate)
                    silence_ends.append(i / sample_rate)
                in_silence = False
        
        # 在静音间隙处切分
        if not silence_starts:
            result.append(seg)
        else:
            sub_starts = [seg.start] + silence_ends
            sub_ends = silence_starts + [seg.end]
            
            for sub_s, sub_e in zip(sub_starts, sub_ends):
                if sub_e - sub_s >= self.config.min_segment_length:
                    result.append(SpeechSegment(
                        start=sub_s, end=sub_e,
                        confidence=seg.confidence,
                    ))
    
    logger.info(
        "Pre-split: %d → %d segments (silence gap > %.1fs)",
        len(segments), len(result), silence_gap_threshold,
    )
    return result
```

### 2.5 方案四：ASR 边界后精修

#### 原理

ASR 输出词级时间戳后，用词的起止时间**回修**语音段的实际边界。具体地：

1. 如果 ASR 第一个词的 start > VAD 段 start + 某个阈值（说明段首有静音），将段 start 前移到第一个词之前
2. 如果 ASR 最后一个词的 end < VAD 段 end - 某个阈值（说明段尾有静音），将段 end 后移到最后一个词之后
3. 但在段之间保留足够的间隔容差

```python
def refine_segment_with_word_timestamps(
    segments: List[SpeechSegment],
    asr_results: List[List[TranscriptionSegment]],
    max_shrink_ms: float = 200,   # 最多向内收缩 200ms
    max_extend_ms: float = 100,   # 最多向外扩展 100ms
) -> List[SpeechSegment]:
    """用 ASR 词级时间戳精修语音段边界
    
    每个段独立处理：检查段内 ASR 首词和末词的时间戳，
    如果段边界与词边界差距过大，适当调整。
    """
    refined = []
    for seg, asr_segs in zip(segments, asr_results):
        if not asr_segs:
            refined.append(seg)
            continue
        
        # 找第一个有词的 ASR 段
        first_words = None
        last_words = None
        for asr in asr_segs:
            if asr.words:
                if first_words is None:
                    first_words = asr.words
                last_words = asr.words
        
        if first_words is None:
            refined.append(seg)
            continue
        
        # 段首精修
        first_word_start = first_words[0].start  # 段内偏移
        if first_word_start > 0.05:  # 段首有 > 50ms 静音
            shrink = min(first_word_start - 0.02, max_shrink_ms / 1000)
            seg.start += shrink
        
        # 段尾精修
        if last_words:
            last_word_end = last_words[-1].end
            seg_duration = seg.end - seg.start
            trailing_silence = seg_duration - last_word_end
            if trailing_silence > 0.05:  # 段尾有 > 50ms 静音
                shrink = min(trailing_silence - 0.02, max_shrink_ms / 1000)
                seg.end -= shrink
        
        refined.append(seg)
    
    return refined
```

### 2.6 方案五：LLM 语义合并引擎（替代规则合并）

#### 核心思路

当前 `MergeStrategy._merge_adjacent()` 使用纯规则（`gap < min_silence_gap` → 合并），这在两种情况下会出错：

1. **该合的没合**：两个片段间隔稍大于阈值但语义连续，规则不合并 → 字幕碎
2. **不该合的合了**：两个片段间隔小于阈值但属于不同句子，规则合并了 → 时间轴模糊

**改进**：将声学合并（VAD段合并）与语义合并（字幕行合并）**完全分离**：

```
当前流程:
  VAD → MergeStrategy(规则) → ASR → TimeMapper → 字幕
         ↑
    规则合并在这里，一锤定音，后面的 LLM 只能改文本

优化流程:
  VAD → 精细化切段（不合并，保留所有静音边界）→ ASR → 粗字幕 
       → LLM 语义合并引擎 → 最终字幕
         ↑
    合并决策完全交给 LLM，基于语义而非静音秒数
```

#### LLM 语义合并 Prompt 设计

```python
MERGE_DECISION_PROMPT = """You are a subtitle merging expert. 
Given a sequence of subtitle fragments with precise timestamps, 
decide which adjacent fragments should be merged into a single subtitle line.

Rules:
- Merge ONLY if the combined text forms a COMPLETE semantic unit (a full sentence or clause).
- Do NOT merge if the gap between fragments represents a natural sentence boundary.
- Do NOT merge if the combined duration would exceed 5 seconds.
- Do NOT merge if the speakers are different.
- A trailing comma or incomplete clause (e.g., "Before ending the call,") 
  STRONGLY suggests merging with the next fragment.

Input format: JSON array of fragments
Output format: JSON array of merge groups

Example:
Input:
[
  {"id": 1, "start": 14.85, "end": 16.09, "speaker": "A", 
   "text": "Before ending the call,"},
  {"id": 2, "start": 16.42, "end": 17.90, "speaker": "A", 
   "text": "repeat key details"},
  {"id": 3, "start": 22.58, "end": 23.80, "speaker": "B", 
   "text": "So I have you down for a non-smoking"},
  {"id": 4, "start": 24.00, "end": 24.80, "speaker": "B", 
   "text": "king room tomorrow,"},
  {"id": 5, "start": 25.00, "end": 26.18, "speaker": "B", 
   "text": "is that right?"}
]

Output:
{
  "merge_groups": [
    {"ids": [1, 2], "reason": "Fragment 1 ends with comma, incomplete clause. 
      Combined with fragment 2 forms complete instruction: 
      'Before ending the call, repeat key details.'"},
    {"ids": [3, 4, 5], "reason": "Three fragments form one complete confirmation 
      question. Natural micro-pauses within the sentence, not sentence boundaries."}
  ]
}
"""
```

#### 静音间隙作为合并决策的辅助信号

在发给 LLM 的输入中附带间隙信息：

```python
def build_merge_input(
    events: List[SubtitleEvent],
    audio: np.ndarray,
    sample_rate: int,
) -> List[dict]:
    """构建 LLM 合并决策的输入
    
    每个片段附带：
    - 精确时间戳（来自 VAD+ffmpeg 融合）
    - ASR 文本
    - 与下一段的静音间隙时长
    - 间隙中的 RMS 能量（辅助判断是换气还是句间停顿）
    """
    from ..utils.audio_utils import AudioUtils
    silence_rms = AudioUtils.estimate_silence_rms(audio, sample_rate)
    
    fragments = []
    for i, event in enumerate(events):
        frag = {
            "id": i + 1,
            "start": round(event.start, 2),
            "end": round(event.end, 2),
            "duration": round(event.duration, 2),
            "speaker": event.speaker_label or "unknown",
            "text": event.text,
        }
        
        # 与下一段的间隙信息
        if i < len(events) - 1:
            next_event = events[i + 1]
            gap = next_event.start - event.end
            frag["gap_to_next_sec"] = round(gap, 3)
            
            # 间隙能量分析
            if gap > 0.01:
                gap_rms = AudioUtils.get_segment_rms(
                    audio, event.end, next_event.start, sample_rate,
                )
                # 能量比：大于2倍静音阈值说明间隙中有声音（可能是呼吸声）
                frag["gap_energy_ratio"] = round(gap_rms / max(silence_rms, 1e-8), 1)
                frag["gap_is_silent"] = gap_rms < silence_rms * 2.0
            else:
                frag["gap_to_next_sec"] = 0
                frag["gap_is_silent"] = True
        
        fragments.append(frag)
    
    return fragments
```

#### 合并后时间轴计算

LLM 决定合并后，时间轴取首片段 start + 末片段 end：

```python
def apply_llm_merge(
    events: List[SubtitleEvent],
    merge_groups: List[dict],
) -> List[SubtitleEvent]:
    """应用 LLM 的合并决策
    
    合并后的事件:
    - start = 组内第一个片段的 start
    - end = 组内最后一个片段的 end
    - text = 组内所有文本拼接
    - 中间的小间隙被自然包含在字幕时间范围内
    """
    # 构建 id → event 映射
    event_map = {i + 1: event for i, event in enumerate(events)}
    
    merged = []
    for group in merge_groups:
        ids = group["ids"]
        first = event_map[ids[0]]
        last = event_map[ids[-1]]
        
        # 拼接文本（组内片段间的静音间隙被自然包含）
        combined_text = " ".join(
            event_map[id].text for id in ids
        )
        
        merged.append(SubtitleEvent(
            index=len(merged) + 1,
            start=first.start,
            end=last.end,
            text=combined_text,
            speaker_id=first.speaker_id,
            speaker_label=first.speaker_label,
        ))
    
    return merged
```

### 2.7 方案七：全局声学标尺校验（后置物理验证模块）

#### 核心原理与定位

将 ffmpeg `silencedetect` 的输出作为**"物理基准线"（Acoustic Ground Truth）**。它不参与复杂的语义理解，只负责回答一个核心问题：**在某一时刻，物理波形上到底是有声音还是没声音？**

通过将 VAD 切片段和最终字幕时间轴与这条物理基准线进行对齐比对，可以量化误差，并实现强制兜底修正。

```
全局音频
   │
   ▼ (仅需一次 ffmpeg CLI 调用，约 1-2 秒)
┌──────────────────────────────────────────────────┐
│ 步骤 1: ffmpeg 声学骨架提取                        │
│ 使用 silencedetect 获取全局精确的语音/静音边界点    │
│ 输出: Timeline_Physics [(t1_start, t1_end), ...] │
└──────────────────────┬───────────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────────┐
│ 步骤 2: VAD 边界交叉校验                           │
│ 将 Timeline_Physics 与 Silero VAD 输出对比         │
│ 检测 VAD 是否存在"切尾"或"幻觉静音"                │
└──────────────────────┬───────────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────────┐
│ 步骤 3: 字幕时间轴物理吸附与兜底修正                │
│ 将 LLM 合并后的字幕时间轴向 Timeline_Physics 吸附  │
│ 消除最后 50-100ms 的物理级偏差                     │
└──────────────────────────────────────────────────┘
```

#### 优势互补：为何用 ffmpeg 做校验最合适？

| 校验维度 | ffmpeg silencedetect (物理标尺) | Silero VAD / Whisper (神经网络) |
|---------|-------------------------------|-------------------------------|
| 判定依据 | 纯能量阈值 | 声学特征 + 语义注意力机制 |
| 精度 | 采样级 (~1ms) | 帧级 (~32ms) 或 词级 (~50ms) |
| 抗幻觉能力 | **极强**（没能量就是没声音） | 弱（易受上下文影响产生"幻听"时间戳） |
| 局限性 | 无法区分换气声与有效人声 | 能理解语义，但边界可能模糊 |

> **结论**：用神经网络做"切分与语义理解"，用 ffmpeg 做"物理边界兜底校验"，是完美的互补组合。

#### 4.1 构建全局声学基准线

执行一次激进的 ffmpeg 扫描（低阈值，短静音容忍），获取所有声学事件边界。注意这里的阈值比宏观切分时更敏感——目的是捕获**所有**物理声音事件（包括微弱的换气声），而非仅用于切块的粗粒度静音。

```python
def build_global_acoustic_skeleton(
    audio_path: Path,
    noise_db: float = -40.0,          # 比宏观切分更敏感（-30dB → -40dB）
    min_silence_duration: float = 0.1  # 容忍 100ms 静音（捕获细微停顿）
) -> List[tuple]:
    """构建全局物理声学基准线
    
    使用比宏观切分时更敏感的阈值，捕获所有物理声音事件（含换气）。
    返回的 skeleton 是"声学事实"，不包含任何模型判断。
    
    Returns:
        [(speech_start, speech_end), ...] 单位：秒
    """
    # 调用 ffmpeg silencedetect，解析输出
    silence_intervals = FFmpegSilenceVAD._detect_silence(
        audio_path, noise_db=noise_db, min_silence_duration=min_silence_duration
    )
    
    # 反转为语音区间
    total_duration = FFmpegSilenceVAD._get_duration(audio_path)
    speech_skeleton = FFmpegSilenceVAD._invert_intervals(
        silence_intervals, total_duration, min_speech_duration=0.05  # 保留短至50ms的语音爆发
    )
    return speech_skeleton
```

#### 4.2 字幕边界物理吸附修正

当 LLM 输出最终字幕后，检查每个字幕的 Start 和 End。如果它们落在物理静音区，或者偏离物理语音边界过远，进行强制拉扯。

```python
def physical_snap_validation(
    events: List[SubtitleEvent],
    speech_skeleton: List[tuple],
    max_snap_distance: float = 0.15  # 最多吸附 150ms
) -> List[SubtitleEvent]:
    """字幕时间轴向物理声学骨架吸附
    
    规则:
    1. 如果字幕 start 落在静音区，向前/后找最近的语音边界，拉扯对齐。
    2. 如果字幕 end 落在静音区，向前找最近的语音边界，拉扯对齐（防止切尾）。
    3. 吸附距离超过 max_snap_distance 的不强制拉扯（可能是合理的句间停顿），
       但标记为 "需人工复核"。
    """
    for event in events:
        # 校验 Start
        is_start_in_speech, nearest_speech_start = _find_boundary_in_skeleton(
            event.start, speech_skeleton
        )
        if not is_start_in_speech and abs(nearest_speech_start - event.start) <= max_snap_distance:
            event.start = nearest_speech_start
            
        # 校验 End
        is_end_in_speech, nearest_speech_end = _find_boundary_in_skeleton(
            event.end, speech_skeleton
        )
        if not is_end_in_speech and abs(nearest_speech_end - event.end) <= max_snap_distance:
            event.end = nearest_speech_end
            
    return events


def _find_boundary_in_skeleton(t: float, skeleton: List[tuple]) -> tuple:
    """判断时间点 t 是否在语音段内，并返回最近的边界
    
    Returns:
        (is_in_speech: bool, nearest_boundary: float)
    """
    for s_start, s_end in skeleton:
        if s_start <= t <= s_end:
            return True, t  # 在语音区内
        if t < s_start:
            return False, s_start  # 在静音区，返回下一个语音起点
    # t 在所有语音段之后
    return False, skeleton[-1][1] if skeleton else t
```

#### 4.3 漂移检测与诊断报告

除了自动修正，还可以输出诊断报告，帮助定位 Pipeline 中哪一步出了问题：

```python
def generate_diagnostic_report(
    events: List[SubtitleEvent],
    speech_skeleton: List[tuple]
) -> dict:
    """生成物理校验诊断报告
    
    可用于:
    - 质量监控：批量处理时自动标记有问题的输出
    - 算法迭代：统计哪种错误模式占比最高，针对性优化
    - 用户反馈：当用户说"字幕时间不准"时，直接查看报告定位根因
    """
    report = {
        "total_events": len(events),
        "start_in_silence": 0,       # start 误落在静音区
        "end_in_silence": 0,         # end 误落在静音区
        "end_truncated": 0,          # 切尾：end在静音但后面紧跟语音
        "start_out_of_range": 0,     # start 偏离所有语音段 > 200ms
        "end_out_of_range": 0,       # end 偏离所有语音段 > 200ms
        "events_flagged": [],        # 需人工复核的事件 ID 列表
    }
    
    for event in events:
        # 检查 start 是否误落在静音区
        if not _is_time_in_speech(event.start, speech_skeleton):
            report["start_in_silence"] += 1
            
        # 检查 end 是否误落在静音区
        if not _is_time_in_speech(event.end, speech_skeleton):
            report["end_in_silence"] += 1
            # 如果后面 200ms 内有语音，说明发生切尾
            if _has_speech_in_range(event.end, event.end + 0.2, speech_skeleton):
                report["end_truncated"] += 1
                report["events_flagged"].append({
                    "id": event.index,
                    "issue": "end_truncated",
                    "current_end": event.end,
                    "text_preview": event.text[:50],
                })
                
    # 计算健康度评分
    total_checks = len(events) * 2  # 每事件检查 start 和 end
    issues = report["start_in_silence"] + report["end_in_silence"]
    report["health_score"] = round((1 - issues / max(total_checks, 1)) * 100, 1)
    
    return report


def _is_time_in_speech(t: float, skeleton: List[tuple]) -> bool:
    """判断时间点是否在语音段内"""
    for s_start, s_end in skeleton:
        if s_start <= t <= s_end:
            return True
    return False


def _has_speech_in_range(t1: float, t2: float, skeleton: List[tuple]) -> bool:
    """判断 [t1, t2] 区间内是否有语音"""
    for s_start, s_end in skeleton:
        if s_start < t2 and s_end > t1:
            return True
    return False
```

#### 在整体架构中的融合定位

该模块作为一个**独立的后置校验器**，插入在 Phase 3（精细化兜底）与 Phase 4（高精度收尾）之间：

```
Phase 1 (基础修正)：宏观切块 + 段内预切分 + 自适应 Padding
Phase 2 (语义合并)：LLM 判断 + 帧级无缝衔接
Phase 3 (物理兜底)：全局 ffmpeg 声学标尺校验  ← 本模块
    ├── 此时字幕的语义和粗略时间轴已定
    ├── 跑一次 ffmpeg 获取物理基准线（1-2秒）
    ├── 对所有字幕端点执行 physical_snap_validation
    └── 输出诊断报告，标记异常事件
Phase 4 (高精度收尾)：三方法融合细化
```

**执行时机**：LLM 语义合并完成后、最终字幕输出前。此时字幕内容已确定，只需校验时间轴的物理正确性。

#### 该方案的核心收益

| 收益 | 说明 |
|------|------|
| **消除切尾顽疾** | 模式 A（系统性提前截断 100-400ms）将被彻底治愈。ffmpeg 发现字幕 End 落在静音区且前方紧邻高能量语音，强制将其拉回语音结束点 |
| **极低计算成本** | 只需一次 ffmpeg CLI 调用（约 1-2 秒），无需加载模型，性价比极高 |
| **可解释性强** | 用户反馈"字幕时间不准"时，可直接查看诊断报告，明确是 VAD 漏切还是 ASR 漂移，便于迭代上游算法 |
| **与现有方案互补** | 方案一用 ffmpeg 做检测（与 VAD 并行），本方案用 ffmpeg 做校验（在 LLM 合并后兜底）。两次 ffmpeg 调用可复用结果，不增加额外开销 |
| **独立可插拔** | 作为后置模块，不影响现有 Pipeline 的任何环节。出问题时直接禁用即可回退 |

### 2.8 方案六：增加默认 padding 并改为自适应

#### 问题

当前 `padding = 0.05`（50ms）过小。从对比数据看，超过 55% 的字幕结束时间偏差 > 300ms。增大基础 padding 并结合 RMS 能量自适应调整。

#### 改进

```python
# MergeConfig 改进
@dataclass
class MergeConfig:
    min_silence_gap: float = 0.4
    max_segment_length: float = 30.0
    padding: float = 0.10          # 50ms → 100ms（基础值加倍）
    adaptive_padding: bool = True  # 新增：根据边界能量自适应调整
    padding_min: float = 0.05      # 最小 padding
    padding_max: float = 0.20      # 最大 padding（能量模糊时放宽）
    min_segment_length: float = 0.5
```

自适应 padding 逻辑：

```python
def _adaptive_padding(
    self, segments: List[SpeechSegment],
    audio: np.ndarray, sample_rate: int,
) -> List[SpeechSegment]:
    """根据边界附近的能量分布自适应调整 padding
    
    原理：
    - 边界处能量急剧下降（清晰边界）→ 小 padding (50ms)
    - 边界处能量缓慢下降（模糊边界）→ 大 padding (200ms)
    """
    cfg = self.config
    if not cfg.adaptive_padding:
        return segments
    
    for seg in segments:
        # 扫描边界 ±100ms 的能量梯度
        onset_slope = self._energy_slope_at(
            audio, sample_rate, seg.start, direction="forward",
        )
        offset_slope = self._energy_slope_at(
            audio, sample_rate, seg.end, direction="backward",
        )
        
        # 梯度越陡 → 边界越清晰 → padding 越小
        def slope_to_padding(slope):
            if slope > 10:     # 非常清晰的边界
                return cfg.padding_min  # 50ms
            elif slope > 3:    # 中等清晰
                return cfg.padding       # 100ms
            else:              # 模糊边界
                return cfg.padding_max   # 200ms
        
        seg.start -= slope_to_padding(onset_slope)
        seg.end += slope_to_padding(offset_slope)
    
    return segments
```

### 3.1 方案五补充：混合合并策略（Fast-Slow Path）

#### 问题

若采用 faster-whisper large-v3 配合激进切分，10 分钟音频可能切出 200-300 个片段。每次合并都请求 LLM（即使 batch 处理），延迟和 API 费用会非常可观。

#### 解决：快慢路径分流

```
合并决策分流:

  相邻片段间隔 < 200ms  ──→ 快路径（规则强制合并）
    │                       人耳无法感知 <200ms 间隔
    │                       合并后字幕视觉连贯
    │
  相邻片段间隔 200-1200ms ──→ 慢路径（LLM 裁决）
    │                       临界区：需要语义判断
    │
  相邻片段间隔 > 1200ms   ──→ 硬规则（强制不合并）
                            超过1.2秒已构成"句号"心理预期
```

```python
@dataclass
class MergeDecisionConfig:
    """合并决策分流配置"""
    fast_merge_max_gap: float = 0.20      # <200ms: 规则强制合并
    llm_decision_min_gap: float = 0.20    # 200-1200ms: LLM裁决
    llm_decision_max_gap: float = 1.20
    hard_split_min_gap: float = 1.20      # >1200ms: 强制不合并
    max_combined_duration: float = 5.0    # 合并后字幕不超过5秒


def merge_decision_pipeline(
    fragments: List[dict],
    config: MergeDecisionConfig,
) -> List[dict]:
    """三级合并决策流水线
    
    预期：减少 70%+ 的 LLM 调用次数，不牺牲精度。
    """
    # ---- 第一级：规则快路径 ----
    rule_merged = []
    for frag in fragments:
        gap = frag.get("gap_to_next_sec", 999)
        next_is_same_speaker = (
            frag.get("speaker") == 
            (fragments[frag["id"]] if frag["id"] < len(fragments) else {}).get("speaker")
        )
        
        should_fast_merge = (
            gap < config.fast_merge_max_gap
            and next_is_same_speaker
            and not frag.get("text", "").rstrip().endswith((".", "?", "!", "。", "？", "！"))
        )
        frag["_fast_merge"] = should_fast_merge
    
    # 执行快路径合并
    fast_merged = _apply_fast_merges(fragments)
    
    # ---- 第二级：硬规则排除 ----
    llm_candidates = []
    for i, frag in enumerate(fast_merged):
        gap = frag.get("gap_to_next_sec", 999)
        if config.llm_decision_min_gap <= gap <= config.llm_decision_max_gap:
            llm_candidates.append(frag)
        elif gap > config.hard_split_min_gap:
            frag["_hard_split"] = True  # 强制不合并
    
    # ---- 第三级：LLM 裁决（仅对临界区） ----
    if llm_candidates:
        llm_groups = _call_llm_merge_decision(llm_candidates)
    else:
        llm_groups = []
    
    # 合并所有决策
    return _apply_all_decisions(fast_merged, llm_groups)

# 预期效果:
# 200个片段 → 快路径处理 ~60% → 硬规则排除 ~20% → LLM仅裁决 ~20%（约40个）
# LLM调用次数从 200次 降至 ~40次（减少 80%）
```

### 3.2 方案三补充：动态 RMS 阈值（防止语尾渐弱被系统性切尾）

#### 问题

方案中 RMS 能量扫描使用全局静音阈值（如 `silence_rms * 2.0`）。但人声的**语尾渐弱（Fade-out）**——如"嗯..."、"是吧"、"对——"——能量可能降到接近静音水平，被误判为静音边界而切掉，导致 ASR 直接丢失句尾关键词（这正是当前模式 A 错误的根因之一）。

#### 解决：相对动态阈值 + 低置信尾部标记

```python
def refine_boundary_with_dynamic_threshold(
    audio: np.ndarray,
    sample_rate: int,
    seg_start: float,
    seg_end: float,
    lookback_ms: int = 500,        # 用前500ms做能量基准
    fade_out_protection: bool = True,
) -> tuple:
    """动态 RMS 阈值精修边界
    
    核心改进：不依赖全局绝对阈值，而是根据当前段前500ms的
    平均能量动态计算。对语尾渐弱做特殊保护。
    
    Returns:
        (refined_end, is_low_confidence_tail)
    """
    center_sample = int(seg_end * sample_rate)
    lookback_samples = int(lookback_ms / 1000 * sample_rate)
    
    # 取该段尾部前500ms的能量作为动态基准
    ref_start = max(0, center_sample - lookback_samples - int(0.15 * sample_rate))
    ref_end = max(0, center_sample - int(0.05 * sample_rate))  # 排除末尾50ms
    
    if ref_end <= ref_start:
        return seg_end, False
    
    ref_audio = audio[ref_start:ref_end]
    baseline_rms = float(np.sqrt(np.mean(ref_audio ** 2)))
    
    # 动态阈值：基准能量的 25%（而非全局静音阈值）
    # 这样即使说话声音整体偏小，也能正确保留语尾
    dynamic_threshold = baseline_rms * 0.25
    
    # 从边界向后扫描
    search_window = int(0.2 * sample_rate)  # ±200ms
    search_start = max(0, center_sample - search_window)
    search_end = min(len(audio), center_sample + search_window)
    
    frame_size = int(0.01 * sample_rate)  # 10ms
    hop = max(1, frame_size // 2)
    
    # 找最后一个 RMS > dynamic_threshold 的帧
    last_voice_sample = center_sample
    is_fade_out = False
    
    fade_frames = 0
    for i in range(search_start, search_end - frame_size + 1, hop):
        frame = audio[i : i + frame_size]
        rms = float(np.sqrt(np.mean(frame ** 2)))
        
        if rms > dynamic_threshold:
            last_voice_sample = i + frame_size
            fade_frames = 0
        else:
            fade_frames += 1
    
    # 检测语尾渐弱模式：尾部连续多帧低于阈值但在全局静音之上
    if fade_out_protection and fade_frames >= 5:  # ≥50ms 持续低能量
        is_fade_out = True
        # 不切！保留原始边界，标记为低置信度
        # ASR 后对此段做 forced alignment 二次确认
        return seg_end, True
    
    refined_end = last_voice_sample / sample_rate
    return refined_end, False


def post_asr_forced_alignment(
    segment_audio: np.ndarray,
    asr_text: str,
    sample_rate: int,
    low_confidence_tail: bool,
) -> bool:
    """对低置信度尾部做强制语音活动检测
    
    如果 ASR 在该段识别出了文本，但尾部能量极低，
    不要直接丢弃文本——用更敏感的阈值重新确认。
    
    Returns:
        True 如果尾部确实有语音（保留文本），False 如果确实是静音
    """
    if not low_confidence_tail or not asr_text:
        return True  # 保留现有结果
    
    # 取尾部 200ms
    tail_samples = int(0.2 * sample_rate)
    tail = segment_audio[-tail_samples:] if len(segment_audio) > tail_samples else segment_audio
    
    # 用极低阈值重检（正常语音能量的 10%）
    tail_rms = float(np.sqrt(np.mean(tail ** 2)))
    global_rms = float(np.sqrt(np.mean(segment_audio ** 2)))
    
    # 尾部RMS > 全局RMS的10% → 有语音
    return tail_rms > global_rms * 0.10
```

### 3.3 方案〇补充：宏观切块的边界重叠与相位对齐

#### 问题

ffmpeg silencedetect 按 >2s 静音切块，切点落在静音中点。但如果换气声（吸气）或极轻语助词（"那个..."）恰好在切点附近，可能被截断。

#### 解决：±200ms 回卷 + 重叠区能量低谷缝合

```python
def split_with_overlap(
    audio_path: Path,
    silence_intervals: List[tuple],
    rollback_ms: int = 200,
) -> List[dict]:
    """带重叠的宏观切块
    
    每个切分点前后各保留 200ms 重叠区。
    相邻块在重叠区内寻找能量最低点作为最终缝合线，
    确保 100% 不会切断任何发音。
    """
    sample_rate = 16000
    rollback_samples = int(rollback_ms / 1000 * sample_rate)
    
    chunks = []
    prev_end = 0.0
    
    for silence_start, silence_end in silence_intervals:
        # 切分点选在静音中点
        split_point = (silence_start + silence_end) / 2.0
        
        # 回卷：块的结束点 = 切分点 + 200ms
        chunk_end = split_point + rollback_ms / 1000
        chunks.append({
            "start": prev_end,
            "end": chunk_end,
            "overlap_with_prev": prev_end > 0,  # 与上一块有重叠
        })
        
        # 下一块的起始点 = 切分点 - 200ms（回卷）
        prev_end = split_point - rollback_ms / 1000
    
    # 最后一块
    chunks.append({
        "start": prev_end,
        "end": None,  # 到音频末尾
        "overlap_with_prev": True,
    })
    
    return chunks


def stitch_overlapping_chunks(
    chunk_a_events: List[SubtitleEvent],
    chunk_b_events: List[SubtitleEvent],
    overlap_region: tuple,  # (overlap_start, overlap_end)
    audio: np.ndarray,
    sample_rate: int,
) -> List[SubtitleEvent]:
    """缝合两个有重叠的大块的字幕结果
    
    在重叠区内找 RMS 能量最低点作为最终缝合线，
    确保不切断任何语音。
    """
    from ..utils.audio_utils import AudioUtils
    
    overlap_start, overlap_end = overlap_region
    
    # 在重叠区内以 10ms 步长扫描，找能量最低点
    frame_size = int(0.01 * sample_rate)
    hop = frame_size // 2
    start_sample = int(overlap_start * sample_rate)
    end_sample = int(overlap_end * sample_rate)
    
    min_rms = float("inf")
    stitch_point = (overlap_start + overlap_end) / 2  # 默认中点
    
    for i in range(start_sample, end_sample - frame_size + 1, hop):
        frame = audio[i : i + frame_size]
        rms = float(np.sqrt(np.mean(frame ** 2)))
        if rms < min_rms:
            min_rms = rms
            stitch_point = i / sample_rate
    
    # 缝合：stitch_point 之前归块A，之后归块B
    stitched = []
    for event in chunk_a_events:
        if event.end <= stitch_point:
            stitched.append(event)
        elif event.start < stitch_point:
            # 跨缝合点的事件 → 截断到缝合点
            event.end = stitch_point
            stitched.append(event)
    
    for event in chunk_b_events:
        if event.start >= stitch_point:
            stitched.append(event)
        elif event.end > stitch_point:
            event.start = stitch_point
            stitched.append(event)
    
    return stitched
```

### 3.4 方案四补充：ASR 边界的双向精修（扩展 + 收缩）

#### 问题

方案四只提到了"收缩"（shrink）——段首有静音则向内收缩。但反向操作（扩展）同样关键。人声的 Attack 时间（爆破音 /p/ /b/ 的前置闭锁阶段）通常需要 20-50ms，如果 VAD 边界恰好切在爆破释放之前，ASR 可能只识别到不完整的音节。

#### 解决：三帧能量斜率校验法

```python
def refine_boundary_bidirectional(
    audio: np.ndarray,
    sample_rate: int,
    boundary_time: float,
    direction: str,  # "onset" | "offset"
    check_frames: int = 3,      # 检查前3帧
    frame_ms: int = 10,
) -> float:
    """ASR边界双向精修：三帧能量斜率校验
    
    原理：
    - 在边界前后各取3帧（每帧10ms），计算能量变化斜率
    - 阶跃跳变（Step Jump）：能量在1-2帧内急剧变化 → 边界精确，锁定
    - 缓慢爬升/下降：能量渐变 → 宁向外扩，不向内缩
      （保护辅音的 Attack/Release 阶段）
    
    Args:
        direction: "onset" 检查段首，"offset" 检查段尾
    
    Returns:
        精修后的边界时间
    """
    center_sample = int(boundary_time * sample_rate)
    frame_size = int(frame_ms / 1000 * sample_rate)
    total_frames = check_frames * 2  # 前后各check_frames帧
    
    # 采集边界前后的能量值
    energies = []
    for i in range(-check_frames, check_frames):
        frame_start = center_sample + i * frame_size
        frame_end = frame_start + frame_size
        if frame_start >= 0 and frame_end <= len(audio):
            frame = audio[frame_start:frame_end]
            energies.append(float(np.sqrt(np.mean(frame ** 2))))
        else:
            energies.append(0.0)
    
    if not energies or len(energies) < total_frames:
        return boundary_time
    
    # 计算前后能量比
    if direction == "onset":
        pre_energy = max(energies[:check_frames])   # 边界前的最大能量
        post_energy = max(energies[check_frames:])   # 边界后的最大能量
    else:  # offset
        pre_energy = max(energies[:check_frames])    # 边界前的最大能量
        post_energy = max(energies[check_frames:])   # 边界后的最大能量
    
    energy_ratio = post_energy / max(pre_energy, 1e-8)
    
    # 决策
    if energy_ratio > 5.0:
        # 阶跃跳变：边界非常清晰
        # 锁定在跳变处，不加不减
        return boundary_time
    elif energy_ratio > 2.0:
        # 中等变化：轻微外扩
        adjustment = 0.02 if direction == "onset" else -0.02
        return boundary_time - adjustment if direction == "onset" else boundary_time + adjustment
    else:
        # 缓慢变化：较大外扩（保护辅音Attack/Release）
        # 对于 onset：段首向前扩展（确保捕获爆破音前置闭锁）
        # 对于 offset：段尾向后扩展（确保捕获语尾渐弱）
        adjustment = 0.05 if direction == "onset" else -0.05
        return boundary_time - adjustment if direction == "onset" else boundary_time + adjustment
```

### 3.5 方案二补充：整数采样点索引统一（避免浮点精度毛刺）

#### 问题

三种检测方法的输出形式不同：
- Silero VAD：浮点秒数（Python float）
- ffmpeg silencedetect：浮点秒数（subprocess 文本解析）
- RMS Energy Scan：NumPy 采样点索引

直接用浮点数比较会产生 `0.0000001` 秒级别的差异，导致 10ms 网格投票时出现边界毛刺。

#### 解决：统一转换为采样点索引

```python
class BoundaryFusion:
    """三方法边界融合器（整数采样点版本）"""
    
    def __init__(self, config: Optional[FusionConfig] = None):
        self.config = config or FusionConfig()
        self._sample_rate = 16000  # 统一使用
    
    def _to_sample_index(self, time_sec: float) -> int:
        """时间 → 采样点索引（整数）"""
        return int(time_sec * self._sample_rate)
    
    def _to_time(self, sample_idx: int) -> float:
        """采样点索引 → 时间"""
        return sample_idx / self._sample_rate
    
    def _vote_by_sample_index(
        self,
        votes: np.ndarray,       # shape: (total_samples // grid_samples,)
        segments: List[SpeechSegment],
        grid_samples: int,       # 网格精度（采样点数），如 160 = 10ms@16kHz
    ) -> None:
        """使用整数采样点索引投票，规避浮点精度问题"""
        for seg in segments:
            start_idx = self._to_sample_index(seg.start) // grid_samples
            end_idx = (self._to_sample_index(seg.end) + grid_samples - 1) // grid_samples
            start_idx = max(0, start_idx)
            end_idx = min(len(votes), end_idx)
            # 整数索引，精确对齐，无浮点毛刺
            votes[start_idx:end_idx] += 1
```

### 3.6 微观切分的下限保护（防止单词/音节被切碎）

#### 问题

激进切分（方案三）将 VAD 段在内部静音处切分。但如果静音间隙恰好出现在单词内部（如中文双字词的短暂停顿、英文辅音连缀），切分会导致 ASR 模型因上下文缺失而识别错误或产生幻听。

#### 解决：最小语音段下限保护

```python
# MergeConfig 补充
@dataclass
class MergeConfig:
    # ... 现有字段 ...
    
    # 微观切分保护
    min_fragment_duration: float = 0.15    # 最小语音片段 150ms
                                            # 短于此值的片段强制与相邻段合并
    min_fragment_merge_preference: str = "next"  # "prev" | "next" | "shorter_neighbor"
    
    # 单字/单词保护
    protect_single_word: bool = True       # 禁止在单词中间切分
    min_word_gap_ms: int = 80             # 单词内部允许的最大"静音"（清辅音间隔）


def apply_minimum_fragment_protection(
    segments: List[SpeechSegment],
    config: MergeConfig,
) -> List[SpeechSegment]:
    """微观切分下限保护
    
    规则：
    1. 片段 < 150ms → 强制与相邻较短片段合并
    2. 两个片段间距 < 80ms 且都不是完整单词 → 合并
       （可能是单词内部清辅音的短暂能量谷）
    """
    if len(segments) <= 1:
        return segments
    
    result = []
    i = 0
    while i < len(segments):
        seg = segments[i]
        
        if seg.duration >= config.min_fragment_duration:
            result.append(seg)
            i += 1
            continue
        
        # 片段过短：与相邻较短的片段合并
        prev_gap = (seg.start - result[-1].end) if result else 999
        next_gap = (
            segments[i+1].start - seg.end if i+1 < len(segments) else 999
        )
        
        if config.min_fragment_merge_preference == "next" and next_gap < 0.5:
            # 与下一片段合并
            next_seg = segments[i+1]
            merged = SpeechSegment(
                start=seg.start,
                end=next_seg.end,
                confidence=min(seg.confidence, next_seg.confidence),
            )
            result.append(merged)
            i += 2
        elif result and prev_gap < 0.3:
            # 与前一片段合并
            result[-1].end = max(result[-1].end, seg.end)
            i += 1
        else:
            # 无法合并，保留（宁可碎片化也不要丢内容）
            result.append(seg)
            i += 1
    
    return result
```

### 3.7 帧级无缝衔接（消除字幕闪烁）

#### 问题

LLM 语义合并后，非句尾字幕的结束时间与下一句的开始时间之间可能存在微小间隙（几十毫秒）。在播放器渲染时，这会导致字幕短暂消失再出现（闪烁），影响视觉连贯性。

#### 解决：非句尾字幕自动衔接到下一句

```python
def apply_frame_seamless_stitching(
    events: List[SubtitleEvent],
    max_stitch_gap: float = 0.12,  # 最多衔接 120ms 的间隙
) -> List[SubtitleEvent]:
    """帧级无缝衔接
    
    对非句尾字幕（不以 .!?。！？ 结尾），
    将其结束时间延伸至下一句开始时间。
    
    这消除了字幕闪烁，是专业字幕工具的标配逻辑。
    """
    # 句尾标点集合
    sentence_endings = {".", "!", "?", "。", "！", "？", "…", "——"}
    
    for i in range(len(events) - 1):
        curr = events[i]
        nxt = events[i + 1]
        gap = nxt.start - curr.end
        
        # 只在正间隙且容差范围内做衔接
        if 0 < gap <= max_stitch_gap:
            # 当前字幕不以句尾标点结束 → 非句尾，可以衔接
            text_ends_with_terminal = (
                curr.text.rstrip()[-1] in sentence_endings
                if curr.text.rstrip() else False
            )
            
            if not text_ends_with_terminal:
                curr.end = nxt.start  # 无缝衔接
    
    return events
```

### 3.8 环境底噪自适应采样

#### 问题

固定 RMS 阈值（如全局 `silence_rms * 2.0`）在不同录音环境中表现不一致。酒店前台（安静）和户外街道（嘈杂）的底噪水平可能差 10 倍。

#### 解决：每个宏观大块独立采样底噪

```python
def estimate_noise_floor_per_chunk(
    audio: np.ndarray,
    sample_rate: int,
    chunk_duration: float,
) -> dict:
    """每个宏观大块独立采样环境底噪
    
    在块的开头和结尾（通常是静音区域）采样底噪，
    比全局固定阈值更适应不同录音环境。
    
    Returns:
        {
            "noise_rms": float,           # 底噪 RMS
            "speech_threshold": float,    # 语音判定阈值
            "is_noisy_environment": bool, # 是否嘈杂环境
        }
    """
    # 取块首 500ms 和块尾 500ms 作为底噪采样区
    head_samples = int(min(0.5, chunk_duration * 0.05) * sample_rate)
    tail_start = int(max(0, chunk_duration - 0.5) * sample_rate)
    
    head = audio[:head_samples] if head_samples > 0 else np.array([0.0])
    tail = audio[tail_start:] if tail_start < len(audio) else np.array([0.0])
    
    # 去除离群值（可能的小杂音）后取中位数
    def robust_noise_estimate(segment: np.ndarray, frame_ms: int = 10) -> float:
        frame_size = int(frame_ms / 1000 * sample_rate)
        if len(segment) < frame_size:
            return float(np.sqrt(np.mean(segment ** 2)))
        rms_vals = []
        for i in range(0, len(segment) - frame_size + 1, frame_size):
            rms_vals.append(float(np.sqrt(np.mean(segment[i:i+frame_size] ** 2))))
        rms_vals.sort()
        # 取 30%-50% 分位数（鲁棒估计，排除偶发杂音）
        mid = len(rms_vals) // 2
        return float(np.median(rms_vals[max(0, mid-5):min(len(rms_vals), mid+5)]))
    
    head_noise = robust_noise_estimate(head)
    tail_noise = robust_noise_estimate(tail)
    noise_rms = min(head_noise, tail_noise)  # 取较安静的
    
    # 判定环境类型
    is_noisy = noise_rms > 0.02  # 经验阈值
    
    # 嘈杂环境提高语音检测阈值（防止误检），安静环境降低
    speech_ratio = 4.0 if is_noisy else 2.5
    
    return {
        "noise_rms": noise_rms,
        "speech_threshold": max(noise_rms * speech_ratio, 1e-6),
        "is_noisy_environment": is_noisy,
    }
```

### 3.9 修正后的实施优先级

综合以上工程落地细节，调整实施顺序：

| 阶段 | 内容 | 理由 |
|------|------|------|
| **P0** | 自适应 Padding（方案六）+ 段内预切（方案三含动态RMS阈值+下限保护） | 最小改动，最大收益。先把"大水漫灌"的误差降下来 |

### 3.11 方案七补充：声学标尺校验的边界条件处理

#### 问题

方案七用 ffmpeg silencedetect 构建物理基准线时，使用比宏观切分更敏感的阈值（-40dB, min_silence=0.1s）。但以下边界情况需要特殊处理：

1. **换气声误判**：深呼吸或叹气产生的声音事件可能被 ffmpeg 标记为"语音"，但它们不应成为字幕吸附的目标
2. **语尾渐弱与基准线的冲突**：方案三的动态 RMS 阈值保护了语尾渐弱，但 ffmpeg 物理标尺可能将其判定为静音——两种判断冲突时需要仲裁
3. **多说话人重叠**：两人同时说话时，物理波形连续，但字幕需要分别显示——物理标尺无法区分

#### 解决：分级置信度 + 仲裁策略

```python
@dataclass
class AcousticValidationConfig:
    """声学标尺校验配置"""
    # ffmpeg 骨架提取参数
    skeleton_noise_db: float = -40.0       # 骨架提取阈值（敏感模式）
    skeleton_min_silence: float = 0.1      # 最小静音（秒）
    skeleton_min_speech: float = 0.05      # 最小语音爆发（秒）
    
    # 吸附参数
    max_snap_distance: float = 0.15        # 最多吸附 150ms
    snap_start_margin: float = 0.02        # start 吸附后保留 20ms 前导余量
    snap_end_margin: float = 0.01          # end 吸附后保留 10ms 尾随余量
    
    # 冲突仲裁
    confidence_threshold: float = 0.6      # 低于此置信度不强制吸附
    rms_override_threshold: float = 0.15   # RMS 动态阈值 vs ffmpeg 冲突时，
                                            # 若 RMS 检测到语尾渐弱（能量比 < 此值），
                                            # 则 RMS 判断优先
    
    # 诊断
    generate_report: bool = True
    flag_threshold_ms: float = 200         # 偏差超过此值标记为"需复核"


def validate_with_arbitration(
    events: List[SubtitleEvent],
    speech_skeleton: List[tuple],
    audio: np.ndarray,
    sample_rate: int,
    config: AcousticValidationConfig,
) -> tuple:
    """带仲裁的物理校验
    
    处理 ffmpeg 物理标尺与动态 RMS 判断之间的冲突。
    
    Returns:
        (validated_events, report)
    """
    report = {
        "snapped_starts": 0,
        "snapped_ends": 0,
        "rms_overrides": 0,       # RMS 判断覆盖 ffmpeg 判断的次数
        "skipped_low_confidence": 0,
        "events_flagged": [],
    }
    
    for event in events:
        # ---- Start 校验 ----
        is_start_in_speech, nearest_start = _find_boundary_in_skeleton(
            event.start, speech_skeleton
        )
        if not is_start_in_speech:
            distance = abs(nearest_start - event.start)
            if distance <= config.max_snap_distance:
                # 吸附前检查：目标边界附近是否有 RMS 检测到的微弱语音
                rms_has_speech = _rms_energy_check(
                    audio, sample_rate, nearest_start,
                    window_ms=50, threshold_ratio=2.0,
                )
                if rms_has_speech or distance < 0.03:
                    # RMS 确认有语音 或 偏差极小 → 执行吸附
                    event.start = nearest_start + config.snap_start_margin
                    report["snapped_starts"] += 1
                else:
                    report["rms_overrides"] += 1
            elif distance <= 0.5:
                # 偏差较大但在合理范围，标记但不强制吸附
                report["events_flagged"].append({
                    "id": event.index,
                    "issue": "start_deviation",
                    "deviation_ms": round(distance * 1000),
                })
        
        # ---- End 校验（防止切尾）----
        is_end_in_speech, nearest_end = _find_boundary_in_skeleton(
            event.end, speech_skeleton
        )
        if not is_end_in_speech:
            distance = abs(nearest_end - event.end)
            if distance <= config.max_snap_distance:
                # 检查：最近的语音边界是否在 event.end 之后（说明发生切尾）
                if nearest_end > event.end:
                    # 切尾检测：字幕结束在静音区，后面还有语音
                    # 强制扩展到语音结束点
                    event.end = nearest_end - config.snap_end_margin
                    report["snapped_ends"] += 1
                elif distance < 0.05:
                    # 微小偏差（字幕结束略超语音边界），微调即可
                    event.end = nearest_end - config.snap_end_margin
                    report["snapped_ends"] += 1
            elif distance <= 0.5 and nearest_end > event.end:
                # 可能切尾但偏差超出吸附范围 → 标记人工复核
                report["events_flagged"].append({
                    "id": event.index,
                    "issue": "possible_truncation",
                    "deviation_ms": round(distance * 1000),
                    "text_preview": event.text[:50],
                })
    
    return events, report
```

#### 与方案一 ffmpeg 调用的复用

方案一（ffmpeg 并行 VAD）和方案七（声学标尺校验）都需要调用 ffmpeg silencedetect。两次调用的参数不同，但可以**合并为一次调用，解析两次结果**：

| 调用参数 | 方案一（检测用） | 方案七（校验用） | 合并策略 |
|---------|----------------|----------------|---------|
| `noise` | -35dB | -40dB | 跑两次，或一次 -40dB 跑完，方案一从结果中过滤 |
| `d` (min_silence) | 0.4s | 0.1s | 跑 0.1s 跑完，方案一过滤掉 < 0.4s 的静音区间 |
| 用途 | 与 VAD 并行检测 | 后置物理校验 | **一次 ffmpeg 调用，两种解析** |

```python
def unified_ffmpeg_pass(audio_path: Path) -> dict:
    """统一的 ffmpeg silencedetect 调用
    
    跑一次 ffmpeg，输出两种粒度的结果，避免重复调用。
    """
    # 以校验模式（更敏感）跑一次
    raw_intervals = FFmpegSilenceVAD._detect_silence(
        audio_path, noise_db=-40.0, min_silence_duration=0.1,
    )
    total_duration = FFmpegSilenceVAD._get_duration(audio_path)
    
    return {
        # 方案七用：所有 > 0.1s 的静音 → 反转得到完整声学骨架
        "skeleton": FFmpegSilenceVAD._invert_intervals(
            raw_intervals, total_duration, min_speech_duration=0.05,
        ),
        # 方案一用：过滤后 > 0.4s 的静音 → 反转得到 VAD 级语音段
        "coarse_speech": FFmpegSilenceVAD._invert_intervals(
            [(s, e) for s, e in raw_intervals if e - s >= 0.4],
            total_duration, min_speech_duration=0.25,
        ),
        # 原始静音区间（供其他模块使用）
        "raw_silence_intervals": raw_intervals,
    }
```

### 5.2 方案间交互：执行顺序与冲突裁决

#### 5.2.1 方案四（ASR边界精修）与方案七（物理吸附）的冲突

**冲突场景**：方案四基于 ASR 词级时间戳将边界**向外扩展**（保护辅音 Attack），方案七基于 ffmpeg 物理标尺将边界**向内吸附**（对齐语音端点）。两者可能在同一端点产生相反方向的修正。

**裁决规则**（按优先级）：

```
优先级 1 (最高): 方案四的"三帧斜率阶跃"检测
  如果方案四检测到能量阶跃跳变 (energy_ratio > 5.0)，
  → 锁定方案四的结果，方案七不覆盖。
  理由：阶跃跳变是物理边界的精确标记，ffmpeg 的 dB 阈值反而不够精细。

优先级 2: 方案七的"物理静音保护"
  如果方案七检测到字幕端点落在静音区，
  → 方案七覆盖方案四。
  理由：端点落在绝对静音中一定是错误的，无论 ASR 如何判断。

优先级 3 (默认): 取两者中更保守的
  如果两者修正方向相同 → 取修正量较小的（防止过度修正）。
  如果两者修正方向相反 → 取方案四（语义信息优先于纯能量）。
```

代码实现：

```python
def resolve_boundary_conflict(
    asr_refined_time: float,
    asr_energy_ratio: float,
    physical_nearest: float,
    physical_is_silence: bool,
    original_time: float,
) -> float:
    """方案四 vs 方案七 边界冲突裁决
    
    Returns:
        最终边界时间
    """
    # 优先级1: 阶跃跳变 → ASR结果锁定
    if asr_energy_ratio > 5.0:
        return asr_refined_time
    
    # 优先级2: 绝对静音 → 物理标尺覆盖
    if physical_is_silence:
        return physical_nearest
    
    # 优先级3: 取保守值
    asr_delta = abs(asr_refined_time - original_time)
    physical_delta = abs(physical_nearest - original_time)
    
    if asr_delta <= physical_delta:
        return asr_refined_time
    else:
        return physical_nearest
```

#### 5.2.2 方案二（三方法融合）与方案一（ffmpeg 并行）的关系

**当前问题**：文档未说明方案二是否替代方案一。

**明确关系**：

- **方案一**：让 ffmpeg silencedetect 作为独立 VAD 引擎运行，产出 `ffmpeg_segments`

#### 5.2.3 方案三（预切分）Split-Merge 循环的效率分析

**问题**：激进切分 → 大量片段 → 大量 ASR 调用 → LLM 合并时再合回去。这个"切了又合"的循环是否有净收益？

**量化分析**（以 10 分钟酒店对话为例）：

```
当前方案 (粗切分):
  VAD段: ~50 个
  ASR调用: 50 次
  每段平均包含: 2.3 个句子
  段内静音: 平均 0.8 处 >0.5s 的停顿
  → ASR 在含静音段内时间戳偏移风险高

激进切分 (方案三):
  预切分段: ~120 个 (50 × (1 + 0.8×1.5))
  ASR调用: 120 次
  每个片段内部几乎无静音 → ASR 时间戳精确
  → 方案五 Fast-Path: ~70 个自动合并 (<200ms)
  → 方案五 Hard-Split: ~20 个强制不合并 (>1200ms)  
  → 方案五 LLM裁决: ~30 个临界段
  → 最终字幕: ~45 条

成本对比:
  当前: 50 ASR + 0 LLM = 基准
  优化: 120 ASR + 30 LLM = 约 +140% ASR 成本 + LLM API 费用
  收益: end 误差从 567ms → ~100ms
```

**结论**：Split-Merge 循环的额外 ASR 成本（~2.4倍）是可接受的，因为：
1. 每段更短 → ASR 每段更快（faster-whisper 在短段上几乎线性加速）
2. 时间戳精度提升是规则/参数调优无法实现的
3. 如果成本敏感，可通过 `pre_split_threshold` 参数控制切分粒度

### 5.4 方案五：本地 NLP 模型选型与说话人标注

#### 5.4.1 本地 NLP 模型空白

文档 3.1 节提到 `local_nlp_gap_range: [0.15, 0.60]`——在此间隙范围内优先使用本地 NLP 模型判断合并，减少云端 LLM 调用。但**未指定使用什么本地模型**。

**推荐方案**（按复杂度递增）：

| 方案 | 模型 | 准确率 | 延迟 | 适用场景 |
|------|------|:--:|:--:|------|
| A（简单规则） | 纯规则（标点 + 间隙） | ~75% | <1ms | 离线/低成本 |
| B（轻量模型） | `sentence-transformers` ( paraphrase-multilingual-MiniLM ) | ~88% | ~50ms | 中英文混合 |
| C（本地 LLM） | Qwen2.5-3B / Llama-3.2-3B 量化版 | ~95% | ~200ms | 高质量离线 |

**推荐默认使用方案 A+B 混合**：

```python
def local_merge_decision(
    frag_a: ASRFragment, frag_b: ASRFragment, gap: float
) -> Optional[bool]:
    """本地合并决策：规则 + 轻量语义模型
    
    Returns:
        True=合并, False=不合并, None=无法判断（升级到云端LLM）
    """
    # 第一层：规则（零成本）
    if frag_a.text.rstrip()[-1] in {',', '，', '、', ';', '；'}:
        return True  # 标点未完 → 一定合并
    if frag_b.text[0].islower() and gap < 0.4:
        return True  # 下一段小写开头 + 短间隙 → 倾向合并
    if gap > 0.8 and frag_a.text.rstrip()[-1] in '.!?。！？':
        return False  # 句尾标点 + 长间隙 → 不合并
    
    # 第二层：轻量语义模型（低成本）
    if 0.15 <= gap <= 0.60:
        similarity = compute_semantic_similarity(frag_a.text, frag_b.text)
        if similarity > 0.8:
            return True
        elif similarity < 0.3:
            return False
        # else: 不确定 → 升级到云端 LLM
    
    return None  # 无法本地判断
```

### 5.5 容错与降级策略

文档缺少**每个模块失败时的降级路径**，这对生产环境至关重要。

#### 5.5.1 逐模块降级矩阵

| 模块 | 失败模式 | 降级策略 | 对最终结果的影响 |
|------|---------|---------|:--:|
| **方案〇** 宏观切块 | ffmpeg 失败 / 找不到静音 | 整段作为一个大块处理 | 无精度影响，仅性能下降 |
| **方案一** ffmpeg VAD | ffmpeg 崩溃 / 超时 | 仅使用 Silero VAD | 丢失物理标尺参考，后续方案二/七退化 |
| **方案一** Silero VAD | 模型加载失败 | 仅使用 ffmpeg 结果 | 丢失神经网络判断，纯能量检测可能漏低音量语音 |
| **方案三** 预切分 | RMS 扫描异常（全静音文件） | 跳过预切分，原始 VAD 段直接送 ASR | 可能恢复模式 C（段内静音漂移）错误 |
| **ASR** faster-whisper | OOM / 模型崩溃 | 降级到 tiny 模型重试当前段 | 识别准确率下降，但时间戳保持 |
| **方案四** 边界精修 | 无词级时间戳（ASR 不支持） | 跳过精修，保持原始边界 | 轻微精度损失（~30ms） |
| **方案五** LLM 合并 | API 超时 / 返回格式错误 | Fast-Path 规则全权代理（不调用 LLM） | 合并决策变为纯规则（回退到当前水平） |
| **方案五** 本地 NLP | 模型未安装 | 间隙 < 200ms 合并，> 600ms 不合并，中间升级到云端 LLM | LLM 调用次数增加 |
| **方案六** 帧衔接 | 无相邻字幕（单条结果） | 跳过 | 无影响 |
| **方案七** 物理校验 | ffmpeg 骨架提取失败 | 跳过校验，输出警告 | 丢失最终的物理兜底修正 |
| **方案二** 三方法融合 | 某方法失败 → 仅 2/1 方法可用 | 降低 `min_consensus` 为可用方法数 | 置信度下降，padding 变宽 |

### 5.9 配置参数一致性校验

#### 5.9.1 参数冲突检测

文档 3.10 的 YAML 配置中存在隐式依赖和潜在冲突。建议增加配置校验层：

```python
def validate_config_consistency(config: dict) -> List[str]:
    """校验配置参数一致性，返回警告列表"""
    warnings = []
    
    # 检查1: ffmpeg 统一调用时，方案一和方案七的参数兼容性
    acoustic = config.get("acoustic_validation", {})
    ffmpeg_vad = config.get("vad", {})
    
    if acoustic.get("unified_ffmpeg_pass") and ffmpeg_vad.get("ffmpeg_enabled"):
        # 统一模式下，两个阈值中取更敏感的
        skeleton_db = acoustic.get("skeleton_noise_db", -40)
        vad_db = ffmpeg_vad.get("ffmpeg_noise_db", -35)
        if vad_db > skeleton_db:
            warnings.append(
                f"统一ffmpeg模式下，方案一阈值({vad_db}dB) > 方案七阈值({skeleton_db}dB)。"
                f"将使用方案七的阈值({skeleton_db}dB)运行，方案一从中过滤。"
            )
    
    # 检查2: 预切分阈值不应小于最小片段时长
    merging = config.get("merging", {})
    pre_split = merging.get("pre_split_threshold", 0.5)
    min_frag = merging.get("pre_split_min_fragment", 0.15)
    if pre_split < min_frag:
        warnings.append(
            f"pre_split_threshold ({pre_split}s) < pre_split_min_fragment "
            f"({min_frag}s)，可能出现无限递归切分。"
        )
    
    # 检查3: max_snap_distance 不应超过合并间隙
    max_snap = acoustic.get("max_snap_distance", 0.15)
    fast_merge = config.get("merge_decision", {}).get("fast_merge_gap", 0.20)
    if max_snap > fast_merge:
        warnings.append(
            f"max_snap_distance ({max_snap}s) > fast_merge_gap ({fast_merge}s)。"
            f"物理吸附范围覆盖了快路径合并范围，可能导致已合并字幕被拉扯分离。"
        )
    
    # 检查4: 宏观切块重叠量 > 2× 预切分最大段长
    macro = config.get("macro_chunking", {})
    overlap = macro.get("overlap_ms", 200) / 1000
    max_seg = merging.get("max_segment_length", 20)
    if overlap > max_seg:
        warnings.append(
            f"宏观切块重叠 ({overlap}s) > 单段最大长度 ({max_seg}s)，"
            f"重叠区内可能无法找到合适的缝合点。"
        )
    
    return warnings
```

#### 5.12.1 嘈杂环境下的前置降噪机制

**现有覆盖**：3.8 节（环境底噪自适应采样）通过调整 RMS 阈值来适应不同底噪水平，但这是**被动适应**——不去除噪声，只提高判定门槛。

**未覆盖的盲区**：突发高能量噪音（关门声、键盘敲击、物品坠落）无法通过阈值调整解决。这类噪音的 RMS 能量可能超过正常语音，导致：
- ffmpeg silencedetect 将其标记为"语音段"（方案一/七误判）
- RMS 能量扫描在噪音处形成虚假边界（方案三误切）
- 物理吸附将字幕端点拉到噪音边界（方案七误吸）

**建议方案**：在 VAD 处理前增加一个**可选的轻量级前置降噪模块**，作为整个 Pipeline 的"第 -1 级"。

```python
# 新增：前置降噪模块
@dataclass
class DenoiseConfig:
    """前置降噪配置"""
    enabled: bool = False                # 默认关闭（纯净录音不需要）
    engine: str = "rnnoise"              # "rnnoise" | "deepfilternet" | "spectral_gate"
    
    # RNNoise 配置（最轻量，适合实时处理）
    rnnoise_model: str = "standard"      # "standard" | "custom"
    rnnoise_vad_threshold: float = 0.5   # RNNoise 自带 VAD，可复用
    
    # DeepFilterNet 配置（更高降噪质量，但更重）
    deepfilternet_model: str = "deepfilternet3"
    
    # 谱减法配置（零模型依赖，纯信号处理）
    spectral_gate:
      noise_reduction_db: float = 12.0
      noise_estimation_frames: int = 10
    
    # 突发噪音专用处理
    burst_noise_protection: bool = True  # 检测并抑制 <200ms 的突发高能事件
    burst_noise_threshold_db: float = 15.0  # 超过局部 RMS 此值视为突发噪音
    burst_noise_max_duration_ms: int = 200


class AudioPreprocessor:
    """音频预处理管线（前置降噪）"""
    
    def __init__(self, config: DenoiseConfig):
        self.config = config
    
    def process(self, audio: np.ndarray, sample_rate: int) -> tuple:
        """对输入音频执行降噪
        
        Returns:
            (denoised_audio, noise_mask, quality_report)
        """
        report = {"denoise_applied": False, "burst_events_detected": 0}
        
        if not self.config.enabled:
            return audio, None, report
        
        # Stage 1: 突发噪音检测与抑制
        if self.config.burst_noise_protection:
            audio, burst_count = self._suppress_burst_noise(audio, sample_rate)
            report["burst_events_detected"] = burst_count
        
        # Stage 2: 稳态降噪（RNNoise / DeepFilterNet / 谱减法）
        if self.config.engine == "rnnoise":
            audio = self._apply_rnnoise(audio, sample_rate)
        elif self.config.engine == "deepfilternet":
            audio = self._apply_deepfilternet(audio, sample_rate)
        elif self.config.engine == "spectral_gate":
            audio = self._apply_spectral_gate(audio, sample_rate)
        
        report["denoise_applied"] = True
        return audio, None, report
    
    def _suppress_burst_noise(
        self, audio: np.ndarray, sample_rate: int
    ) -> tuple:
        """突发噪音抑制
        
        检测能量在极短时间内（<200ms）急剧上升后回落的事件，
        识别为突发噪音（关门、键盘等），用局部邻域插值替代。
        """
        cfg = self.config
        frame_ms = 10
        frame_size = int(frame_ms / 1000 * sample_rate)
        hop = frame_size // 2
        
        # 计算逐帧 RMS
        rms_vals = []
        for i in range(0, len(audio) - frame_size + 1, hop):
            rms = float(np.sqrt(np.mean(audio[i:i+frame_size] ** 2)))
            rms_vals.append(rms)
        
        if not rms_vals:
            return audio, 0
        
        # 局部中位数 RMS（鲁棒估计）
        median_rms = float(np.median(rms_vals))
        burst_threshold = median_rms * (10 ** (cfg.burst_noise_threshold_db / 20))
        
        # 检测突发噪音帧
        burst_count = 0
        in_burst = False
        burst_start_frame = 0
        
        max_burst_frames = int(cfg.burst_noise_max_duration_ms / frame_ms)
        
        for i, rms in enumerate(rms_vals):
            if rms > burst_threshold and not in_burst:
                burst_start_frame = i
                in_burst = True
            elif rms <= burst_threshold and in_burst:
                burst_duration = (i - burst_start_frame) * frame_ms / 1000
                if burst_duration <= cfg.burst_noise_max_duration_ms / 1000:
                    # 确认为突发噪音 → 插值替代
                    start_sample = burst_start_frame * hop
                    end_sample = i * hop + frame_size
                    self._interpolate_burst(audio, start_sample, end_sample)
                    burst_count += 1
                in_burst = False
        
        return audio, burst_count
    
    @staticmethod
    def _interpolate_burst(
        audio: np.ndarray, start: int, end: int
    ) -> None:
        """用邻域线性插值替代突发噪音段"""
        if start < 4 or end > len(audio) - 4:
            return
        # 用噪音前后的邻域采样点做线性插值
        pre_samples = audio[max(0, start-50):start]
        post_samples = audio[end:min(len(audio), end+50)]
        
        pre_rms = float(np.sqrt(np.mean(pre_samples ** 2))) if len(pre_samples) > 0 else 0
        post_rms = float(np.sqrt(np.mean(post_samples ** 2))) if len(post_samples) > 0 else 0
        target_rms = (pre_rms + post_rms) / 2
        
        # 生成匹配邻域能量的舒适噪声
        burst_len = end - start
        replacement = np.random.randn(burst_len).astype(np.float32) * target_rms * 0.3
        audio[start:end] = replacement
```

#### 5.12.2 混合语种与代码切换处理

**现有覆盖**：无。faster-whisper 的 `language` 参数仅支持单一语言；方案五的 LLM 合并 Prompt 未涉及语种切换逻辑。

**问题场景**：酒店前台对话中频繁出现中英文夹杂（"Mehood Lestee Hotel"、"non-smoking king room"、"我是 front desk 的 Xiaoxi"）。当 faster-whisper 在语种切换边界处，词级时间戳置信度可能剧烈波动（下降 30-50%），导致方案四的边界精修信任了不可靠的时间戳。

**建议方案**：三层防护。

**第 1 层：ASR 语种切换检测**

```python
def detect_language_switches(
    words: List[dict],
    confidence_drop_threshold: float = 0.3,
) -> List[int]:
    """检测词级时间戳中的语种切换点
    
    语种切换的特征：
    1. 连续 2+ 个词的置信度骤降 >30%
    2. 词间出现异常长间隙（模型在"思考"语言切换）
    3. 降信词之后恢复正常（切换完成）
    
    Returns:
        语种切换位置索引列表（词索引）
    """
    switch_points = []
    confidences = [w.get("confidence", 1.0) for w in words]
    
    for i in range(1, len(confidences) - 2):
        # 置信度骤降检测
        avg_before = sum(confidences[max(0,i-2):i]) / min(i, 2)
        avg_after = sum(confidences[i:i+3]) / 3
        
        if avg_before - avg_after > confidence_drop_threshold:
            switch_points.append(i)
    
    return switch_points
```

```python
def smooth_multilingual_timestamps(
    words: List[dict],
    switch_points: List[int],
    sample_rate: int = 16000,
) -> List[dict]:
    """对语种切换点附近的时间戳做平滑处理
    
    语种切换边界的词级时间戳不可靠 → 用邻域插值替代。
    """
    if not switch_points:
        return words
    
    smoothed = list(words)  # 浅拷贝
    
    for switch_idx in switch_points:
        # 取切换点前后各 3 个可靠词的时间戳做线性插值
        pre_idx = max(0, switch_idx - 3)
        post_idx = min(len(words) - 1, switch_idx + 3)
        
        if post_idx <= pre_idx:
            continue
        
        # 在切换区 [pre_idx, post_idx] 内做均匀时间分布
        t_start = words[pre_idx]["start"]
        t_end = words[post_idx]["end"]
        n_words_in_switch = post_idx - pre_idx + 1
        
        for j, idx in enumerate(range(pre_idx, post_idx + 1)):
            fraction = j / max(n_words_in_switch - 1, 1)
            smoothed[idx] = {
                **words[idx],
                "start": t_start + fraction * (t_end - t_start) * 0.9,
                "end": t_start + (fraction + 1.0/n_words_in_switch) * (t_end - t_start) * 0.9,
                "_timestamp_smoothed": True,
            }
    
    return smoothed
```

**性能影响**：第 1 层和第 3 层为纯后处理，耗时 <10ms；第 2 层仅增加 Prompt 文本，不影响 LLM 调用延迟。

#### 5.12.3 突发非人声高能事件的标尺仲裁

**现有覆盖**：方案七的 `validate_with_arbitration()`（3.11 节）已包含 RMS 双确认机制，可过滤部分非人声事件。但该仲裁仅依赖 RMS 能量特征，无法区分"人大声说话"和"拍桌子"——两者的 RMS 特征相似。

**未覆盖的盲区**：ffmpeg 构建的声学骨架将拍桌子、掌声、音乐爆点标记为"语音段"，方案七的物理吸附可能将字幕端点拉到这些噪音的边界。

**建议方案**：在方案七的仲裁中引入**方案一的 Silero VAD 作为人声验证器**。

```python
def classify_acoustic_events(
    skeleton: List[tuple],
    silero_segments: List[SpeechSegment],
    audio: np.ndarray,
    sample_rate: int,
) -> List[dict]:
    """将声学骨架中的事件分为"人声"和"非人声高能事件"
    
    判定逻辑:
    - ffmpeg 标记为语音 + Silero 也标记为语音 → 人声（可信）
    - ffmpeg 标记为语音 + Silero 未标记 → 非人声高能事件（跳过吸附）
    - ffmpeg 标记为静音 + Silero 标记为语音 → 低音量人声（Silero优先）
    """
    classified = []
    
    for sk_start, sk_end in skeleton:
        # 检查该区间是否被 Silero VAD 确认
        silero_overlap = _compute_vad_overlap(
            sk_start, sk_end, silero_segments
        )
        
        if silero_overlap > 0.5:
            event_type = "human_speech"
            confidence = "high"
        elif silero_overlap > 0.1:
            event_type = "human_speech"
            confidence = "low"  # 边缘情况，可能是语尾渐弱
        else:
            # ffmpeg 检测到能量但 Silero 不认为是人声
            event_type = "non_human_energy"
            confidence = "high"
            
            # 进一步分类（可选）：基于频谱特征
            # 检查是否为音乐（谐波结构）或瞬态噪音（无谐波）
            event_subtype = _classify_energy_type(
                audio, sample_rate, sk_start, sk_end
            )
        
        classified.append({
            "start": sk_start,
            "end": sk_end,
            "type": event_type,
            "confidence": confidence,
            "silero_overlap_ratio": round(silero_overlap, 2),
        })
    
    return classified


def _compute_vad_overlap(
    start: float, end: float, vad_segments: List[SpeechSegment]
) -> float:
    """计算区间与 Silero VAD 的重叠比例"""
    duration = end - start
    if duration <= 0:
        return 0.0
    
    overlap_total = 0.0
    for seg in vad_segments:
        overlap_start = max(start, seg.start)
        overlap_end = min(end, seg.end)
        if overlap_start < overlap_end:
            overlap_total += overlap_end - overlap_start
    
    return min(1.0, overlap_total / duration)


def _classify_energy_type(
    audio: np.ndarray, sample_rate: int, start: float, end: float
) -> str:
    """基于频谱特征区分噪音类型
    
    谐波比 (Harmonics Ratio)：音乐 > 0.3，瞬态噪音 < 0.1
    """
    start_sample = int(start * sample_rate)
    end_sample = int(end * sample_rate)
    segment = audio[start_sample:end_sample]
    
    if len(segment) < 256:
        return "unknown"
    
    # 简易谐波比检测（时域自相关法）
    try:
        import numpy as np
        # 自相关
        autocorr = np.correlate(segment, segment, mode='full')
        autocorr = autocorr[len(autocorr)//2:]
        autocorr = autocorr / (autocorr[0] + 1e-8)
        
        # 找第一个峰值（基频）
        peaks = []
        for i in range(1, len(autocorr) - 1):
            if autocorr[i] > autocorr[i-1] and autocorr[i] > autocorr[i+1]:
                if autocorr[i] > 0.2:
                    peaks.append((i, autocorr[i]))
        
        if not peaks:
            return "transient_noise"  # 无谐波结构 → 瞬态噪音
        
        # 谐波比 = 峰值平均 / 谷值平均
        peak_vals = [p[1] for p in peaks[:10]]
        harmonics_ratio = sum(peak_vals) / len(peak_vals)
        
        if harmonics_ratio > 0.3:
            return "music_or_tonal"
        else:
            return "transient_noise"
    except Exception:
        return "unknown"
```

#### 5.12.4 字幕断句与排版联动

**现有覆盖**：方案五 LLM 合并决策返回 `{"ids": [1, 2], "reason": "..."}`，仅决定"合并哪些片段"，不涉及排版。方案六（帧级无缝衔接）处理了时间轴连续性，但不涉及文本换行。

**未覆盖的盲区**：合并后的字幕如果时长接近 5 秒且文本量大（如 30+ 字符），在播放器渲染时会超出屏幕宽度或被截断。专业字幕规范要求：

```python
def apply_layout_suggestions(
    events: List[SubtitleEvent],
    layout_suggestions: List[dict],
) -> List[SubtitleEvent]:
    """将 LLM 的断行建议应用到字幕事件
    
    对于 ASS 格式：使用 \N 作为换行标记
    对于 SRT 格式：使用 \n
    """
    for suggestion in layout_suggestions:
        group_id = suggestion["group_id"]
        if group_id < len(events):
            line1 = suggestion.get("line1", "")
            line2 = suggestion.get("line2", "")
            if line1 and line2:
                events[group_id].text = f"{line1}\\N{line2}"
                events[group_id]._layout_applied = True
    
    return events
```

**自动断行降级**（LLM 不可用时）：

```python
def auto_line_break_fallback(
    text: str, max_chars_per_line: int = 20
) -> str:
    """纯规则的自动断行（LLM 不可用时的降级方案）
    
    在以下位置寻找断行点（按优先级）：
    1. 逗号/分号后
    2. 介词/连词前（and, but, or, 在, 给, 为）
    3. 中点字符数（最后手段）
    """
    if len(text) <= max_chars_per_line:
        return text
    
    # 寻找自然断点
    break_candidates = []
    for char in [',', '，', ';', '；', '—', '…']:
        idx = text.rfind(char, 0, max_chars_per_line)
        if idx > max_chars_per_line * 0.5:  # 不在太前面断
            break_candidates.append(idx + 1)
    
    # 寻找连词/介词
    for word in [' and ', ' but ', ' or ', ' to ', ' for ',
                 ' 在', ' 给', ' 为', ' 和', ' 而且', ' 但是']:
        idx = text.rfind(word, 0, max_chars_per_line + len(word))
        if idx > max_chars_per_line * 0.5:
            break_candidates.append(idx)
    
    if break_candidates:
        break_point = max(break_candidates)  # 最靠后的自然断点
        return text[:break_point] + "\\N" + text[break_point:].lstrip()
    
    # 最后手段：中点附近找空格
    mid = len(text) // 2
    for offset in range(0, len(text) // 4):
        for direction in [1, -1]:
            idx = mid + offset * direction
            if 0 <= idx < len(text) and text[idx] == ' ':
                return text[:idx] + "\\N" + text[idx+1:]
    
    return text  # 无法断行，保留原文
```

#### 5.12.5 实时流式处理的架构兼容性

| 方案七 全局声学标尺 | 需要对整个文件跑 ffmpeg | 未来音频未知 |

```python
@dataclass
class PipelineMode:
    """Pipeline 运行模式"""
    mode: str = "offline"  # "offline" | "streaming"
    
    # 流式模式参数
    streaming_chunk_duration: float = 2.0    # 每次处理的音频窗口（秒）
    streaming_overlap_duration: float = 0.5  # 窗口重叠（秒）
    streaming_max_latency: float = 3.0       # 最大允许延迟（秒）


class PipelineRunner:
    """支持离线/流式双模式的 Pipeline 执行器"""
    
    def __init__(self, config: dict):
        self.mode = PipelineMode(
            mode=config.get("mode", "offline"),
            **config.get("streaming", {})
        )
        self._degraded_modules = set()
    
    def resolve_active_modules(self) -> dict:
        """根据运行模式决定启用哪些模块"""
        if self.mode.mode == "offline":
            return {
                "macro_chunk": True,       # 方案〇
                "ffmpeg_vad": True,        # 方案一
                "boundary_fusion": True,   # 方案二（如启用）
                "pre_split": True,         # 方案三
                "asr_refine": True,        # 方案四
                "llm_merge": True,         # 方案五
                "frame_seamless": True,    # 方案六
                "acoustic_validation": True,  # 方案七
            }
        else:  # streaming
            return {
                "macro_chunk": False,           # ❌ 无全局视角
                "ffmpeg_vad": True,             # ✅ 可在窗口内运行
                "boundary_fusion": False,        # ❌ 简化（仅 Silero VAD）
                "pre_split": True,              # ✅ 窗口内预切分
                "asr_refine": True,             # ✅ 窗口内精修
                "llm_merge": "local_only",      # ⚠️ 降级：仅本地 NLP
                "frame_seamless": True,         # ✅ 窗口内无缝衔接
                "acoustic_validation": False,    # ❌ 无全局标尺
            }
    
    def run_streaming(self, audio_stream: Iterator[np.ndarray]):
        """流式处理主循环"""
        buffer = StreamingBuffer(
            chunk_duration=self.mode.streaming_chunk_duration,
            overlap_duration=self.mode.streaming_overlap_duration,
        )
        
        for audio_chunk in audio_stream:
            buffer.append(audio_chunk)
            
            if buffer.ready():
                window = buffer.get_window()
                
                # 在滑动窗口内执行精简版 Pipeline
                segments = self._run_vad_on_window(window)       # 方案一
                segments = self._pre_split_window(segments)       # 方案三
                fragments = self._asr_window(segments)            # ASR
                fragments = self._refine_window(fragments)        # 方案四
                events = self._local_merge_window(fragments)      # 方案五 (local NLP)
                events = self._seamless_stitch_window(events)     # 方案六
                
                # 立即输出（不等待全局信息）
                yield events
                
                buffer.advance()
```

**流式模式的合并策略适配**：

```python
class StreamingMergeEngine:
    """流式合并引擎（替代离线方案五的 Batch LLM）
    
    使用滑动窗口 + 本地 NLP 模型 + 简单规则。
    """
    
    def __init__(self):
        self.similarity_model = self._load_local_model()
        self.sentence_buffer = []  # 保留最近 N 条未决字幕
    
    def decide_merge_streaming(
        self, current: ASRFragment, previous: ASRFragment
    ) -> bool:
        """实时合并决策（必须 <50ms 内完成）"""
        gap = current.start - previous.end
        
        # 快速路径 (<5ms)
        if gap < 0.15:
            return True
        if gap > 0.80:
            return False
        
        # 标点规则 (<1ms)
        if previous.text.rstrip()[-1] in {',', '，', ';', '；'}:
            return True
        if previous.text.rstrip()[-1] in '.!?。！？':
            return False
        
        # 本地语义模型 (~30ms)
        similarity = self._compute_similarity(previous.text, current.text)
        return similarity > 0.6
    
    def _load_local_model(self):
        """加载轻量本地模型（单次加载，全局复用）"""
        try:
            from sentence_transformers import SentenceTransformer
            return SentenceTransformer(
                "paraphrase-multilingual-MiniLM-L12-v2"
            )
        except ImportError:
            return None  # 降级到纯规则
    
    def _compute_similarity(self, text_a: str, text_b: str) -> float:
        if self.similarity_model is None:
            return 0.5  # 无模型时返回中性值
        emb = self.similarity_model.encode([text_a, text_b])
        return float(np.dot(emb[0], emb[1]) / 
                     (np.linalg.norm(emb[0]) * np.linalg.norm(emb[1]) + 1e-8))
```

## 六、总结

### 核心架构

```
长音频 (10min+)
    │
    ▼ 宏观切分 (方案〇: 长静音切30-60s大块, 含重叠)
    │
    ├── 大块1 ──→ 底噪自适应采样
    │              ├── 微观切分 (方案三: VAD+ffmpeg并行, 动态RMS, 最小片段保护)
    │              ├── 逐段ASR
    │              ├── 双向边界精修 (方案四: 三帧斜率校验)
    │              ├── 混合合并 (方案五: Fast-Slow Path, 帧级无缝衔接)
    │              └── 物理校验 (方案七: ffmpeg 声学标尺吸附 + 诊断报告)
    │
    ├── 大块2 ──→ (同上, 可并行)
    │   ...
    └── 大块N
            │
            ▼ 时间偏移合并 + 重叠区能量低谷缝合
            │
            ▼ 最终字幕
```

### 关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 合并主体 | LLM（混合策略） | 语义判断优于规则；Fast-Slow Path 降本 70%+ |
| 切分粒度 | 激进（先切后合） | 声学精度优先，语义层负责合并 |
| RMS 阈值 | 动态相对（每段独立） | 避免语尾渐弱被系统性切尾 |
| 时间基准 | 整数采样点索引 | 消除浮点精度毛刺 |
| 宏观切块 | 按长静音 + 重叠 | 保证语音完整性，支持并行 |
| 字幕衔接 | 帧级无缝 | 消除闪烁，专业字幕标配 |
| **物理校验** | **ffmpeg 声学标尺** | **物理基准线兜底，消除模型"幻觉时间戳"** |
