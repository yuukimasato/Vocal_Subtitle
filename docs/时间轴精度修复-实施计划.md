# 时间轴精度修复 - 代码落实计划

## 概述

在 `segment_events`（词边界预切分）和 `_split_long_events`（兜底拆分）之间
插入 `_merge_short_events` 步骤，将词级碎片合并回句子级字幕。

## 修改清单

### 修改 1/3：`vocal_subtitle/mapping/finalize.py`

#### 1a) `FinalizeConfig` 增加 `min_duration` 字段

位置: 第 22-32 行，增加一行：

```python
min_duration: float = 0.8  # 新增：最小时长，用于合并词级碎片
```

#### 1b) `finalize_subtitle_events()` 增加合并步骤

位置: 第 116-119 行（`segment_events()` 调用之后，`_split_long_events` 块之前）

插入如下代码块：

```python
    # Merge word-level fragments back to sentence-level subtitles after
    # strict segmentation. The splitter's _split_long_events does NOT
    # merge short events — it only splits over-long ones — so this step
    # is essential to restore readable sentence-level granularity.
    before_merge = len(valid_events)
    builder = SubtitleBuilder(
        rule=SubtitleRule(
            min_duration=cfg.min_duration,
            max_duration=cfg.max_duration,
            max_chars_cjk=cfg.max_chars_cjk,
            max_chars_latin=cfg.max_chars_latin,
            max_lines=cfg.max_lines,
        )
    )
    valid_events = builder._merge_short_events(valid_events)
    diagnostics["merge_short_event_count"] = max(
        0, before_merge - len(valid_events)
    )
    diagnostics["step"].append("merge_short_events")
```

然后修改后续的 `SubtitleBuilder` 创建块，将 `SubtitleBuilder` 和 `SubtitleRule` 的导入及创建提前到合并步骤处。
为避免重复导入和重复创建，将 `SubtitleBuilder, SubtitleRule` 的导入提升到文件顶部，
`splitter` 构造可以直接复用同一个 `builder`。

实际上，由于 `_merge_short_events` 会修改事件（可能会 `extend` words），
而 `_split_long_events` 也需要工作，更安全的方式是创建独立实例，或直接复用同一个 `builder`。

**最终优化方案**：在 segment_events 之后追加合并步骤，导入和实例化复用后面的已有代码。

具体插入点：在第 116-117 行之间（紧接 `diagnostics["step"].append("strict_segmentation")` 之后，
在 `# Split logical cues` 注释块之前）。
