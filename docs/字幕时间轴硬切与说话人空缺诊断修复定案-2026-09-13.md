## 0. 结论(TL;DR)

用户在 `TTS中文朗读测试-双人` 素材上报告六类症状:说话人标注空缺、句尾硬切、幻听单字行(「得」)、幻听行无说话人、下一句行首吞静音、与人工修正字幕不一致。诊断结论是**两条根因链**:

1. **说话人空缺链**:yaml 里的 `early_turns: true` 是**死配置**(loader 从未解析该键,运行时恒为 false),身份主干层1从未生效;回退路径 `run_speaker_fusion` 中"全局线↔嵌入线归属冲突即置空"的策略叠加低质量嵌入聚类(两人素材聚出 5 簇、silhouette 0.187),产出 16 条空缺 cue(与任务诊断 `conflict_count=16` 精确相等)。
2. **时间轴偏早链**:faster-whisper 词级时间戳在句边界普遍偏早 60~300ms,而整条后处理链单向——end 只能缩短、start 只能向前吸,骨架明知道截尾也只标记不修(`validator.py` 旧注释:"只报告疑似截尾,不自动延长");幻听「得」整段落在静音区(真实语音 12.92s 起,「得」却配到 12.52-12.88),合并引擎又因"unknown 说话人不合并"与零间隙不进 LLM 队列的死锁,让幻听行永久独立存在。

修复后(红线检查器口径):说话人空缺 16→**0**、语音内截尾 7→**0**、行首吞静音 6→**0**、幻听碎片 4→**1**(「哎。」为真实语气词的显示尾部保持,非幻听)。

## 1. 红线反馈回路

诊断期间建立可复跑的红线检查器 `scripts/check_subtitle_quality.py`(已入库):

```
python3 scripts/check_subtitle_quality.py <subtitle.ass|srt> <source.wav>
```

以源音频 20ms 帧峰值能量门限(>4% 全局峰值)提取真实语音区间,断言四类症状:A 幻听碎片(cue 与真实语音重叠率<30%)、B 语音内截尾(区间尾部 >120ms 无 cue 覆盖)、C 吞并静音(cue 开头 140ms 内无能量且真实起点晚于 cue.start >150ms)、D 说话人空缺。退出码:有红=1,全绿=0。

素材级真值参照(20ms 能量门限,与人工听辨一致):

| 真实语音 | 实际区间 | 修复前 ASR 输出 |
| --- | --- | --- |
| 我脚底板现在还在打颤 | 10.98~12.58 | 10.99~12.52(截尾 64ms) |
| 得了吧 | 12.92~13.36 | 幻听「得」12.52~12.88(整段在静音里)+「了吧」12.88~13.10(截尾 264ms) |
| 行行行 | 19.70~20.36 | 19.40 起(吞静音 300ms) |

## 2. 根因明细

| # | 根因 | 位置 | 证据 |
| --- | --- | --- | --- |
| 1 | `diarization.early_turns` 等 3 个键 loader 从不解析,身份主干从未激活 | `config/loader.py`(DiarizationConfig 构造) | 任务生效配置 `early_turns: false`,而 yaml 写 true;诊断键缺 `early_turns` |
| 2 | 两线冲突置空 | `diarization/speaker_fusion.py` 冲突分支(旧:`speaker_id=None`) | `conflict_count=16 == unknown_count=16` |
| 3 | 嵌入线 3s 粗窗口聚类质量差 | `_extract_embedding_evidence` | silhouette=0.187,2 人素材聚出 5 个说话人 |
| 4 | validator 只标记截尾不延长 | `acoustic/validator.py` end 分支(旧) | 运行报告 `events_flagged` 18 条 possible_truncation(48~150ms),`snapped_ends=0` |
| 5 | start 吸附限幅 150ms 且被高置信词豁免 | validator start 分支(旧) + `max_snap_distance` | 「行行行」偏早 303ms 超限只标记;词 conf 0.99 全部走 reliable 豁免 |
| 6 | unknown 说话人禁止合并 × 零间隙片段不进 LLM 队列 = 幻听行死锁 | `merging/merge_engine.py` fast path 守卫与 skip 逻辑 | 「得」「了吧」零间隙两行永久保留 |
| 7 | finalize 显示拆行以词起点/文本宽度为准,骨架路径合并事件无词表 | `mapping/finalize.py` → `member_projection` | 校验阶段事件是整段长事件(探针实证),2s 边界按 10 字宽度比例切出 |

## 3. 修复内容(全部可独立回退)

| 修复 | 位置 | 开关/回退 |
| --- | --- | --- |
| 配置管道接通:loader 补读 `early_turns`/`word_split_on_turn`/`single_speaker_shortcut` | `config/loader.py` | yaml 置 false 即回退 |
| 冲突择优回退:全局↔嵌入归属冲突时回退全局线(源标记 `global_conflict_fallback`),不再置空 | `diarization/speaker_fusion.py` | 无开关(诊断计数保留) |
| 截尾延长:end 落在连续语音骨架段内部 → 延长到该段语音终点,钳制到下一事件 start-20ms 之前,绝不跨静音/吞下一句 | `acoustic/validator.py` end 分支 | `acoustic_validation.allow_end_extend: true`(置 false 回到只标记) |
| start 后向吸附:能量驱动(词首前方 120ms 基本静音 + 能量确认起点),限幅 `max_start_snap_distance: 0.45s`;不再做 reliable-boundary 豁免(后移只裁静音,不移动语音) | `acoustic/validator.py` start 分支,新增 `_leading_silence_ahead`/`_next_energy_onset_after`/`_speech_frame_mask` | `max_start_snap_distance`(调 0 即关闭) |
| 能量判据:帧峰值 > max(4% 全局峰值, 2× 底噪 RMS)。只用底噪倍数会把 TTS 残留噪声(底噪的 2~2.5 倍)误判为语音(实测静音帧 0.005~0.009 vs 语音 ≥0.117,分离干净) | `_speech_frame_mask` | — |
| 静音碎片吸收器:覆盖率<40% 的短事件(≤0.8s)文本并入后继真实语音事件并重锚定到真实起点;前后无语音可并则整行丢弃。在说话人归属之前运行 | `merging/fragment_absorber.py`(新) | `acoustic_validation.enabled` 门控 |
| 词级时间戳重锚定:整词落在静音里的词起点吸到能量起点(保单调、不越下一词) | `fragment_absorber.reanchor_word_timestamps` | 函数级,当前接进 postprocess |
| 显示 cue 能量对齐:finalize 拆行后、导出前,对最终 cue 复用 `_physical_snap_validation` 做一轮 start 吸附 + end 骨架内延长 | `application/run_lifecycle.py`(finalize 之后) | `acoustic_validation.enabled` 门控 |

## 4. E2E 验证记录(2026-09-13)

- 素材:`test/TTS中文朗读测试-双人.wav`(157.9s,双人对话);环境:`.venv-production`(large-v3 int8 CPU),`cli run --skip-separation -p default`,全程 67.7s。
- 红线检查:见 §0 对比表;「打颤得了吧」「行行行」等关键位置全部对齐真实语音边界。
- 全量回归:**1475 passed / 3 skipped**(含新增用例:吸收器 6 项、重锚定 2 项、冲突回退 1 项、截尾延长/钳制 3 项、start 能量吸附 2 项、loader 回归 2 项;更新 3 项编码旧契约的测试并注明契约变更)。
- 迭代教训(留档):
  - `word_split_on_turn: true` 在无词级时间戳的合并事件上走 fallback 拆分,把整段文本压进首个说话人小片段(60ms 塞 12 字),已回退 false 并在 yaml 注明前置条件(需先修 unworded 事件的词表传递)。
  - `member_split_min_gap` 0.3→0.25 无效:跨说话人合并发生在更上游的 chunk 级物理段合并(`MergeStrategy.min_silence_gap: 0.4`),已回退。

## 5. 已知问题与待办

- [ ] **chunk 级换人合并**:`MergeStrategy`(gap<0.4s)在 ASR 之前合并物理段,无说话人知识;「…打颤得了吧」「…还好意思说我行行行」仍跨话轮合并为一行。需在 merge 阶段接入 `_early_turn_spans`(不同 speaker 永不合并),这是「得了吧」被并入上一行(且随 pyannote 标为 B 而非人工修正的甲)的直接原因。
- [ ] **pyannote 短话轮归属**:0.44s 短句(「得了吧」)归到前一说话人;`.venv-production` 缺 speechbrain,嵌入线无法交叉验证。装齐后融合路径的嵌入证据可复核。
- [ ] **word_split_on_turn 开启前置**:unworded 事件的词表传递修复后,按 §定案 P2 流程在无静音换人素材上验证。
- [ ] **「哎。」类短语气词显示尾部**:骨架把语气词+后句并入同一语音段时,end 延长钳制到下一句 start,显示略长于语音;纯观感,不影响同步。

## 6. 验证工具

`scripts/check_subtitle_quality.py`:对任意输出字幕(ass/srt)+ 源 wav 断言 A/B/C/D 四类症状,`--json` 输出机器可读结果,退出码可供 CI/回归使用。人工修正字幕(`test/TTS中文朗读测试-双人-人工修正.ass`)仍作为文本与话轮划分的参照真值。
