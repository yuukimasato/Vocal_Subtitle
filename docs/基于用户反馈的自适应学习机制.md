## 一、概述与目标

### 1.1 问题定义

当前 Vocal Subtitle 的管道参数（VAD 阈值、合并间隙、padding、LLM 合并策略等）通过场景模板（default / podcast / education / variety_show / music_live）静态配置。同一模板内，所有音频使用相同的参数，无法适配：

- **用户个人偏好**：有些用户喜欢更长的字幕行，有些喜欢短小精悍。
- **特定音频特征**：某类录音环境（会议室回声、户外风噪）的系统性偏差。
- **内容类型差异**：即使同属"播客"，访谈和单人讲述对合并/拆分策略的需求不同。

### 1.2 目标

构建一个**自适应反馈与参数调优引擎**，使系统能够：

1. **学习用户偏好**：用户上传修订后的字幕 + 原始音频，系统自动分析差异，调整参数。
2. **记忆音频指纹**：将调优后的参数与音频声学特征绑定，遇到相似音频自动应用。
3. **渐进收敛**：多次反馈逐步逼近用户理想参数，不破坏系统默认行为。
4. **模式隔离**：不影响现有 CLI/Web GUI/流式/骨架模式的正常运作。

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **增量叠加** | 用户配置文件作为"补丁"覆盖默认配置，而非替换 |
| **安全优先** | 每次更新自动备份，质量断崖式下降时自动回滚 |
| **置信度驱动** | 修改样本越多，参数调整越激进；单次修改仅微调 |
| **模式无感** | 学习引擎通过 `PipelineConfig` 参数覆盖机制透明介入 |
| **离线优先** | 对齐与归因分析完全离线运行，无需外部 API |

## 三、核心模块详细设计

### 3.1 智能字幕对齐器 (`aligner.py`)

由于用户可能合并、拆分、重排序或删除字幕行，简单的按行号对比无效。需要基于**时间轴重叠 + 语义相似度 + 粗粒度锚点**的多层匹配算法。

```python
@dataclass
class AlignmentPair:
    """一对对齐结果"""
    auto_events: List[SubtitleEvent]   # 1个（精确匹配）或多个（合并）
    manual_events: List[SubtitleEvent] # 1个（精确匹配）或多个（拆分）
    match_type: str  # "1:1" | "1:N" | "N:1" | "N:M" | "INSERT" | "DELETE"
    time_iou: float  # 时间交并比
    text_similarity: float     # 字面文本相似度 (Levenshtein)
    semantic_similarity: float # 语义相似度 (Sentence-BERT)
    composite_score: float     # 综合匹配得分


class SubtitleAligner:
    """将自动生成的字幕与人工修订字幕对齐

    三层对齐策略（由粗到细）：
    Layer 1 — 全局粗粒度锚点匹配：
      利用音频的长停顿点（>2s 静音）或关键词簇
      （TF-IDF 前 5 词汇）将字幕切分为多个大块，
      先做大块级别的配对，防止大段删减或重排序
      导致 DTW 全局崩溃。

    Layer 2 — 语义增强的 DTW 对齐：
      在每个大块内部运行 DTW，代价函数融合三项：
      cost = 1.0 - (0.35 × time_iou + 0.30 × text_sim + 0.35 × semantic_sim)

    Layer 3 — 残差匹配：
      剩余未匹配项通过宽松的时间窗口 + 纯语义匹配
      做最后一次尝试，标记为 INSERT/DELETE。
    """

    def align(
        self,
        auto_events: List[SubtitleEvent],
        manual_events: List[SubtitleEvent],
    ) -> List[AlignmentPair]:
        """
        匹配策略（优先级递降）:
        1. 全局粗粒度锚点切分（长停顿 + 关键词簇）
        2. 时间交并比 (IoU) > 0.3 → 候选匹配池
        3. 综合得分 = 0.35 × time_iou + 0.30 × text_sim + 0.35 × semantic_sim
        4. 在候选池上运行语义增强 DTW，处理 N:M 复杂情况
        5. 残差宽松匹配 → INSERT / DELETE 标记
        """
```

#### 3.1.1 语义相似度引入

在口语化字幕中，用户可能进行同义词替换或语序微调。字面相似度（Levenshtein）对"我们去看电影吧" vs "咱们去观影吧"给出低分，但两者语义相同。

**方案**：使用项目已缓存的多语言 Sentence-BERT 模型（`paraphrase-multilingual-MiniLM-L12-v2`，已在 `project-overview` 中记录），对每条字幕文本计算 384 维句向量，以余弦相似度作为 `semantic_similarity`。

```python
class SemanticScorer:
    """轻量级语义相似度计算器"""

    def __init__(self):
        # 复用项目中已缓存的 sentence-transformers 模型
        from sentence_transformers import SentenceTransformer
        self._model = SentenceTransformer(
            "paraphrase-multilingual-MiniLM-L12-v2"
        )

    def pairwise_similarity(
        self,
        auto_texts: List[str],
        manual_texts: List[str],
    ) -> np.ndarray:
        """计算 auto × manual 的语义相似度矩阵
        返回 shape (len(auto), len(manual)) 的 float 矩阵
        """
```

**性能考量**：语义编码仅在 DTW 的候选池中计算（即时间 IoU > 0.3 的配对），而非对所有 N×M 组合全量计算，避免引入过大开销。

#### 3.1.2 大段重排序检测

用户可能对字幕进行大段删减或重排序（如删除开头广告段落、调整访谈问答顺序）。单纯依赖 DTW 的对齐会在重排序边界处崩溃。

**方案**：在对齐前增加全局粗粒度锚点匹配——

```python
def _find_global_anchors(
    auto_events: List[SubtitleEvent],
    manual_events: List[SubtitleEvent],
    audio_silence_points: List[float],  # 音频中 >2s 的静音点
) -> List[Tuple[int, int]]:
    """
    1. 按音频长停顿点（>2s 静音）将字幕序列切分为段落
    2. 在每个段落内提取 TF-IDF 关键词簇（top-5 词汇）
    3. 对 auto 段落和 manual 段落做关键词 Jaccard 匹配
    4. 建立段落级锚点配对 → 约束后续 DTW 搜索范围
    """
```

若锚点匹配失败（段落无法配对），说明用户做了大幅重排序，系统降级为"段落级重新匹配"而非强行 DTW，并在报告中标记该次反馈为"结构性修订"（参数学习权重降低）。

#### 3.1.3 对齐质量门控

- DTW 路径覆盖率 < 0.7 → 抛出 `AlignmentError`，提示用户检查文件是否匹配同一音频。
- 语义相似度中位数 < 0.5 → 警告"文本差异较大，可能为不同语言或内容"，降低该次反馈的学习权重至 50%。

### 3.2 差异分类与归因分析器 (`diff_analyzer.py`)

对齐后分析用户"为什么这么改"，将修改行为映射到 `PipelineConfig` 的具体参数。

| 修改行为 | 检测特征 | 归因目标参数 | 调整方向 |
|----------|----------|-------------|----------|
| 时间轴整体平移 | `delta_start` 和 `delta_end` 同方向且差值相似 | `MergingConfig.padding` | 补偿平移量 |
| 句尾被截断 | `manual.end > auto.end` 且文本末尾多字词 | `MergingConfig.padding` / `MergingConfig.padding_max` | 增大 end_padding |
| 句首被截断 | `manual.start < auto.start` 且文本开头多字词 | `MergingConfig.padding` / `MergingConfig.padding_min` | 增大 start_padding |
| 本该合并却被拆分 | `1个 manual 对应 N个 auto`，间隙 < 1.2s | `MergeDecisionConfig.fast_merge_max_gap` | 调大合并间隙 |
| 本该拆分却被合并 | `N个 manual 对应 1个 auto` | `MergeDecisionConfig.llm_decision_max_gap` | 调小拆分阈值 |
| 句末标点修改 | 文本相似度 > 0.9，仅标点不同 | LLM 优化 Prompt | 记录为 Few-shot 示例 |
| 说话人标签修正 | speaker_label 被重命名 | `SpeakerRoleConfig` | 记录偏好角色名 |
| 整体偏长/偏短 | 系统性时长偏差 | `SubtitleBuildConfig.max_duration` | 调整最大时长约束 |

```python
@dataclass
class DiffReport:
    """单次反馈的差异分析报告"""
    total_pairs: int
    alignment_coverage: float       # 对齐覆盖率
    time_shifts: List[TimeShift]    # 时间偏移列表
    merge_actions: List[MergeAction]  # 合并/拆分动作
    text_edits: List[TextEdit]      # 文本修改
    attribution: Dict[str, ParamAdjustment]  # 参数调整建议
    # ★ 以下字段为数据库预留（schema 支持），归因分析器暂未填充：
    #    asr_confidence_map / low_confidence_zones — 待 ASR 数据通道就绪（见附录 C.4）
    structural_revision: bool = False     # 是否为结构性修订


class DiffAnalyzer:
    def analyze(self, pairs: List[AlignmentPair]) -> DiffReport:
        """
        对每一对齐对分类:
        1. 时间偏移类: delta_start / delta_end 的分布
        2. 结构变化类: 合并数 vs 拆分数
        3. 文本修改类: 标点 / 大小写 / 措辞
        4. 按归因表汇总为参数调整建议
        """
```

#### 3.2.1 上下文感知归因（消解多解性）⚠️ 部分延后

某些修改行为存在多解性。例如"句尾被截断"可能因为：
- **A**: padding 不足（→ 应调整参数）
- **B**: ASR 引擎漏识别了尾词（→ 不应调整参数，应记录为 ASR 误差样本）
- **C**: 用户主观删减了冗余尾词（→ 不应调整参数）

**当前状态**：基础归因已实施（`diff_analyzer.py:_attribute()` 通过时间偏移 + 合并/拆分比例 + 文本编辑分类进行归因），但 ASR 置信度感知的决策树（`_resolve_end_truncation()`）因 `no_speech_prob` 数据通道未确认（见附录 C.4）而延后。数据库 `feedback_history` 表已预留 `asr_low_confidence_zones` 字段，待数据通道就绪后接入。

**设计方案**（待后续实施）：在归因分析时引入 ASR 置信度时间戳（`avg_logprob` 和 `no_speech_prob`），构建决策树：

```python
def _resolve_end_truncation(
    pair: AlignmentPair,
    asr_confidence_at_end: float,    # ASR 在该事件结束时间附近的置信度
    asr_no_speech_prob: float,       # ASR 报告的无声概率
) -> AttributionResult:
    """
    归因决策树:

    asr_confidence_at_end < -1.5  (极低)
      → 归因: "ASR 低置信度区间 — 可能是漏识别或噪音"
      → 动作: 不调整 padding，记录为 ASR 误差样本
      → 学习权重: 0.0 (本次不学习此参数)

    asr_no_speech_prob > 0.8  (ASR 认为此处大概率无语音)
      → 归因: "用户主观补充了 ASR 未识别的内容"
      → 动作: 记录为 ASR 误差样本，不调整 padding
      → 学习权重: 0.0

    文本末尾 delta < 3 个字符 且 语义相似度 > 0.95
      → 归因: "仅标点/语气词差异 — 用户格式偏好"
      → 动作: 记录为 Few-shot 标点示例
      → 学习权重: 0.3 (轻度影响)

    otherwise (高置信度下系统性后移)
      → 归因: "padding 不足"
      → 动作: 按标准 EMA 调整 merging.padding
      → 学习权重: 1.0
    """
```

归因结果通过**学习权重**（`learn_weight ∈ [0, 1]`）控制该条反馈对参数更新的影响力度。低置信度归因的权重降低或归零，避免噪声数据污染参数。

#### 3.2.2 参数耦合解耦（隔离调整策略）

`fast_merge_max_gap` 和 `llm_decision_max_gap` 在合并决策中存在耦合：增大前者会让更多片段进入"快速合并"路径，间接减少了进入 LLM 决策的片段数；调整后者也会改变整体合并率。

**方案**：在 `ParamLearner` 中引入**参数隔离调整策略**——同一批次反馈中，若同时检测到拆分行为和合并行为，优先只调整其中一个高置信度参数，下一次反馈再评估是否需联动调整另一个。

```python
class ParamDecoupler:
    """参数解耦器 — 防止联动参数同时调整导致震荡"""

    COUPLED_GROUPS = [
        # (主参数, 从属参数, 耦合关系)
        ("merge_decision.fast_merge_max_gap",
         "merge_decision.llm_decision_min_gap",
         "boundary"),   # 前者的调整改变快速合并的上界，需联动 min_gap 维护区间
        ("merge_decision.llm_decision_min_gap",
         "merge_decision.llm_decision_max_gap",
         "interval"),  # 二者构成 LLM 裁决区间 [min, max]，调整一个需校验区间非空
        ("merging.padding",
         "merging.padding_max",
         "dependent"),  # padding_max 是 padding 的上界约束
    ]

    def select_adjustments(
        self,
        raw_attributions: Dict[str, ParamAdjustment],
        profile_history: List[Dict],
    ) -> Dict[str, ParamAdjustment]:
        """从原始归因中选择本轮应执行的调整

        策略:
        1. 若同组内两个参数都有调整建议 →
           选择置信度更高的那个，另一个标记为 pending
        2. 若上一轮已调整过同组的另一个参数 →
           本轮允许调整当前参数（交替验证）
        3. 若连续 3 轮同组参数都无需调整 →
           pending 标记自动清除（说明已稳定）
        """
```

**解耦效果**：避免"调大 fast_merge_max_gap 增加合并 → 用户反而拆分更多 → 调小 llm_decision_max_gap → 两个参数在相反方向震荡"的典型过调场景。

### 3.3 参数自适应更新引擎 (`param_learner.py`)

核心设计：**用户配置文件**（User Profile）作为默认配置的增量补丁，通过 `ConfigLoader.merge_with_overrides()` 机制透明覆盖。

```python
class ParamLearner:
    """基于用户反馈的参数自适应学习器

    采用滑动平均 (EMA) 更新策略，避免单次修改过拟合。
    更新幅度与样本数量成正比（置信度驱动）。
    """

    def __init__(self, user_profile_path: Path):
        self.profile_path = user_profile_path
        self.profile = self._load_profile()

    def learn_from_diff(
        self,
        diff_report: DiffReport,
        audio_fingerprint: Optional[np.ndarray] = None,
    ) -> Dict[str, Any]:
        """根据差异分析结果更新用户配置

        更新策略:
        - 样本数 ≤ 2: 仅记录，不触发参数变更（置信度不足）
        - 样本数 3~5: 以 15% 学习率逐步靠拢
        - 样本数 6~15: 以 25% 学习率加速
        - 样本数 > 15: 以 35% 学习率（上限，保留系统默认的权重）
        """
```

**参数更新公式**（加权滑动平均）：

```
new_value = current_value + (observed_target - current_value) × learn_rate
learn_rate = min(0.35, 0.10 + 0.02 × max(0, sample_count - 2))
```

**有界约束**：每个参数有硬限制范围，防止学习到极端值破坏管道稳定性。

**匹配策略（三维度升级）**：

#### 3.4.1 马氏距离替代余弦相似度

48 维声学特征中，不同维度的方差分布差异极大（如 `duration_seconds` 量级为 10²、`mfcc_means[0]` 量级为 10¹、`zero_crossing_rate` 量级为 10⁻²）。直接使用余弦相似度可能被高方差维度主导，余弦值对尺度不敏感但对方差敏感——方差异常大的维度会主导内积。

**方案**：使用**马氏距离（Mahalanobis Distance）**替代余弦相似度。马氏距离通过协方差矩阵的逆对各维度进行"白化"，自动消除量纲和方差差异的影响。

```python
class MahalanobisMatcher:
    """基于马氏距离的指纹匹配器"""

    def __init__(self):
        # 从指纹库中估计协方差矩阵（定期更新）
        self._cov_matrix: Optional[np.ndarray] = None
        self._cov_inv: Optional[np.ndarray] = None

    def fit(self, fingerprint_vectors: np.ndarray):
        """用指纹库中的所有向量估计协方差矩阵"""
        self._cov_matrix = np.cov(fingerprint_vectors.T)
        # 正则化：防止奇异矩阵（加小量对角扰动）
        reg = self._cov_matrix + np.eye(self._cov_matrix.shape[0]) * 1e-6
        self._cov_inv = np.linalg.inv(reg)

    def mahalanobis_distance(
        self, vec_a: np.ndarray, vec_b: np.ndarray
    ) -> float:
        """计算两个指纹向量之间的马氏距离"""
        delta = vec_a - vec_b
        return float(np.sqrt(delta.T @ self._cov_inv @ delta))

    def to_similarity(self, mah_dist: float) -> float:
        """将马氏距离转化为 [0, 1] 的相似度分数
        使用指数衰减映射: sim = exp(-dist / sqrt(dim))
        """
        return float(np.exp(-mah_dist / np.sqrt(48)))
```

入库前对所有维度进行 Z-score 标准化（以指纹库全局均值/标准差为基准），确保新入库的指纹与已有指纹在同一尺度空间。

#### 3.4.2 动态 KNN 阈值策略

固定的 0.85 阈值可能在不同场景下表现不一：音频种类多样时 Top-1 相似度普遍偏低（大量 0.70-0.80），种类单一时 Top-1 普遍偏高（大量 >0.90）。

**方案**：引入 KNN 动态阈值——取最近邻 Top-3 的相似度均值作为动态基线：

```python
def find_similar_dynamic(
    self,
    fingerprint: AudioFingerprint,
    k: int = 3,
    min_absolute_similarity: float = 0.70,  # 绝对下界
    relative_margin: float = 0.08,          # 相对余量
) -> Optional[Tuple[str, float]]:
    """
    动态阈值匹配策略:

    1. 检索指纹库中所有向量的马氏距离 → 转为相似度
    2. 取 Top-K 最近邻，计算:
       - baseline = mean(Top-K 相似度)
       - top1_sim = Top-1 相似度
    3. 匹配条件（全部满足才触发）:
       - top1_sim >= min_absolute_similarity (绝对下界，默认 0.70)
       - top1_sim >= baseline + relative_margin (相对余量，默认 0.08)
       - Top-1 与 Top-2 的差距 >= 0.05 (防止多个高分候选时的歧义)
    4. 若匹配成功 → 返回 (profile_id, confidence)
       若匹配失败 → 返回 None
    """
```

**效果**：
- 音频种类多样时，`baseline ≈ 0.72`，top1 需 ≥ 0.80 才匹配 → 自动收紧
- 音频种类单一时，`baseline ≈ 0.88`，top1 需 ≥ 0.96 才匹配 → 自动放宽相对要求
- `min_absolute_similarity = 0.70` 作为绝对下界，防止在指纹库极小时误匹配

#### 3.6.1 Few-shot 缓存生命周期管理

随着反馈积累，`few_shot_cache` 可能膨胀到数十甚至上百条。早期偏好可能已过时，且过长的 Few-shot 注入会稀释 Prompt 的有效信号。

**方案**：LRU（最近最少使用）+ 置信度衰减 双重淘汰机制。

```python
class FewShotCacheManager:
    """Few-shot 示例缓存管理器

    淘汰策略（优先级递降）：
    1. 置信度衰减淘汰: 示例的 decayed_weight < 0.15 → 自动移除
       使用与参数分级相同的衰减半衰期（180 天）
    2. LRU 淘汰: 缓存超过 max_capacity（默认 20 条）时，
       移除最久未被"命中"的示例
    3. 重复检测: 新增示例与缓存中某条的语义相似度 > 0.9
       → 更新旧示例的时间戳和权重，而非新增

    命中定义：该示例的类型（merge/split/format）在当前批次
    反馈中被再次观察到。
    """

    def __init__(self, max_capacity: int = 20):
        self.max_capacity = max_capacity
        self._cache: List[FewShotExample] = []

    def add(self, example: FewShotExample) -> None:
        """添加示例（含自动淘汰逻辑）"""
        # 1. 重复检测
        for existing in self._cache:
            if self._semantic_overlap(existing, example) > 0.9:
                existing.touch()  # 更新时间戳
                existing.weight = max(existing.weight, example.weight)
                return

        # 2. 衰减淘汰
        self._cache = [
            ex for ex in self._cache
            if ex.decayed_weight(datetime.now()) >= 0.15
        ]

        # 3. LRU 淘汰
        if len(self._cache) >= self.max_capacity:
            self._cache.sort(key=lambda ex: ex.last_hit_at)
            self._cache.pop(0)  # 移除最久未命中的

        self._cache.append(example)

    def get_active_examples(
        self, max_count: int = 3
    ) -> List[FewShotExample]:
        """获取当前活跃的示例（按权重排序，取 Top-K）"""
        active = [
            ex for ex in self._cache
            if ex.decayed_weight(datetime.now()) >= 0.3
        ]
        active.sort(key=lambda ex: ex.decayed_weight(datetime.now()), reverse=True)
        return active[:max_count]
```

**容量设计理由**：最多保留 20 条，每次注入 Prompt 取权重最高的 3 条——确保 Prompt 精简且符合最新偏好，避免上下文窗口膨胀。

### 6.1.1 健康度评分（Health Score）标准化定义

`health_score` 是触发自动回滚的核心指标，需严格定义其计算口径：

```python
def compute_health_score(
    auto_events: List[SubtitleEvent],
    manual_events: List[SubtitleEvent],
    aligner: SubtitleAligner,
) -> Tuple[float, Dict[str, float]]:
    """计算字幕质量的综合健康度评分

    Returns:
        overall: 0-100 的综合评分
        detail: 各子项得分（用于回滚根因分析）
    """
    pairs = aligner.align(auto_events, manual_events)

    # 子项 1: 对齐覆盖率 (权重 35%)
    alignment_coverage = len(pairs) / max(len(auto_events), len(manual_events))
    score_coverage = alignment_coverage * 100

    # 子项 2: 文本语义相似度均值 (权重 35%)
    semantic_sims = [
        p.semantic_similarity for p in pairs
        if p.match_type in ("1:1", "1:N", "N:1")
    ]
    score_semantic = (np.mean(semantic_sims) if semantic_sims else 0.0) * 100

    # 子项 3: 时间 IoU 均值 (权重 20%)
    time_ious = [
        p.time_iou for p in pairs
        if p.match_type in ("1:1", "1:N", "N:1")
    ]
    score_time = (np.mean(time_ious) if time_ious else 0.0) * 100

    # 子项 4: 结构一致性 (权重 10%)
    # 1:1 匹配占比越高越好，INSERT/DELETE 占比越低越好
    one_to_one_ratio = sum(
        1 for p in pairs if p.match_type == "1:1"
    ) / max(len(pairs), 1)
    score_structure = one_to_one_ratio * 100

    overall = (
        0.35 * score_coverage
        + 0.35 * score_semantic
        + 0.20 * score_time
        + 0.10 * score_structure
    )

    return overall, {
        "alignment_coverage": score_coverage,
        "semantic_similarity": score_semantic,
        "time_iou": score_time,
        "structure_consistency": score_structure,
    }
```

在 `feedback_history` 表中增加 `health_score_detail` 字段（JSON 格式），记录各子项得分，便于回滚时进行根因分析。

### 6.2 置信度衰减（分级）

较早的修改记录权重随时间指数衰减，但不同参数分级使用不同半衰期（详见 3.3.1）：

```
weight = exp(-t / half_life)

长期偏好 (half_life = 180 days):
- 30 天前的修改：权重 ≈ 0.89
- 90 天前的修改：权重 ≈ 0.71
- 180 天前的修改：权重 ≈ 0.50

中期偏好 (half_life = 90 days, 默认):
- 30 天前的修改：权重 ≈ 0.79
- 90 天前的修改：权重 ≈ 0.50
- 180 天前的修改：权重 ≈ 0.25

短期环境 (half_life = 60 days):
- 30 天前的修改：权重 ≈ 0.71
- 60 天前的修改：权重 ≈ 0.50
- 120 天前的修改：权重 ≈ 0.25
```

这确保：
- 格式偏好长期稳定，不因时间流逝而"遗忘"
- 声学参数快速响应设备/环境迁移
- 合并策略处于两者之间，兼顾稳定性和适应性

### 6.3 异常值过滤

在计算参数目标值时，使用 **IQR（四分位距）方法**过滤异常修改：

```python
def filter_outliers(values: List[float]) -> List[float]:
    q1, q3 = np.percentile(values, [25, 75])
    iqr = q3 - q1
    lower = q1 - 1.5 * iqr
    upper = q3 + 1.5 * iqr
    return [v for v in values if lower <= v <= upper]
```

### 6.4 影子模式（Shadow Mode）

在 Phase 5.2 实施阶段，引入**影子模式**做渐进式灰度验证：

```

                    │   Pipeline.run()            │
                    │                             │
                    │   用户配置: user_default     │
                    │   shadow 模式: ON            │
                    │                             │
                    │   ┌── 正式路径 (热路径) ──┐  │
                    │   │ 使用旧参数 (v_current) │  │
                    │   │ → 输出字幕给用户       │  │

                    │                             │
```

```python
@dataclass
class ShadowModeConfig:
    """影子模式配置"""
    enabled: bool = False
    min_shadow_runs: int = 10          # 最少影子运行次数才考虑升级
    upgrade_threshold: float = 0.05    # 新参数需比旧参数好 5% 以上
    max_shadow_duration_days: int = 14 # 最长影子运行天数


class ShadowModeEvaluator:
    """影子模式评估器 — 决定是否将新参数升级为正式参数"""

    def should_upgrade(self, shadow_runs: List[ShadowRunResult]) -> Tuple[bool, str]:
        """
        升级条件（全部满足）:
        1. shadow_runs 数量 >= min_shadow_runs（默认 10 次）
        2. 新参数 health_score 均值 > 旧参数 health_score 均值 + upgrade_threshold
        3. 新参数在各项子指标上均无显著退化（无子项下降 > 10%）
        4. 运行天数 <= max_shadow_duration_days（超期自动对比并决定）
        """
```

影子模式的工程价值：
- **零风险验证**：新参数的效果在后台验证，不影响用户实际获得的字幕质量
- **数据驱动升级**：积累足够对比数据后，系统自动决定是否切换到新参数
- **快速回退**：若影子评估不通过，新参数被丢弃，旧参数继续使用，用户无感知

当检测到"连续 3 次反馈都朝相反方向调整同一参数"触发震荡检测时，系统不应仅静默回滚，而应主动引导用户。

```python
class ConflictDetector:
    """参数震荡检测与交互引导"""

    def detect_oscillation(
        self,
        param_path: str,
        history: List[Dict],
        window: int = 5,
    ) -> Optional[ConflictReport]:
        """
        震荡检测:
        1. 取最近 window 次该参数的调整记录
        2. 计算调整方向的符号序列（+1 = 增大, -1 = 减小）
        3. 若符号序列中出现 >= 3 次翻转 → 判定为震荡
        4. 生成 ConflictReport 供前端渲染交互式引导
        """

    def resolve(
        self,
        report: ConflictReport,
        user_choice: str,  # "lock" | "branch" | "continue"
    ) -> None:
        """根据用户选择执行冲突解决"""
```

**关键设计**：不静默处理冲突，而是将决策权交还给用户——因为只有用户知道"为什么第 2 次和第 1/3 次偏好不同"。

```
│  │                                                  │   │
│  │  base = load_profile("podcast")                  │   │
│  │  user_overrides = UserProfileManager.load()      │   │
│  │  final = merge(base, user_overrides)  ←── 透明介入│   │
│  └──────────────────────────────────────────────────┘   │
│                                                          │
│  反馈通道（独立于热路径）：                                │
│                                                          │
│  fingerprint → match? → load user profile                 │
│       │                                                  │
│       └── no match → use base config only                │
└──────────────────────────────────────────────────────────┘
```

- **不影响人声分离**：反馈学习只调整 VAD/合并/字幕构建参数，不触及分离引擎。
- **不影响 LLM 合并决策**：Few-shot 示例是可选的 Prompt 增强，LLM 合并模块在无示例时完全正常。
- **不影响声学标尺校验**：声学校验作为 Post-processing 的最后一环，在学习到的 padding 之后运行，仍然有效。
- **不影响流式模式**：反馈学习需要全量修订字幕，仅支持离线模式。流式模式下自动禁用。

## 附录 A：参数映射表（完整）

| 用户修改行为 | 检测条件 | 映射参数 | 调整公式 |
|-------------|---------|---------|---------|
| 结束时间后移 | `median(delta_end) > 50ms` 且 delta_end > 0 | `merging.padding` | `new = old + median(delta_end) × lr` |
| 开始时间前移 | `median(delta_start) < -30ms` 且 delta_start < 0 | `merging.padding` | `new = old + abs(median(delta_start)) × lr` |
| 合并→拆分 | `N:1 ratio > 0.15` | `merge_decision.llm_decision_max_gap` | `new = max(llm_decision_min_gap + 0.10, old - 0.05 × merge_ratio)` ★ |
| 拆分→合并 | `1:N ratio > 0.15` | `merge_decision.fast_merge_max_gap` | `new = min(0.50, old + 0.03 × split_ratio)` |
| 间隙小但未合并 | 间隙 < `llm_decision_min_gap` 但 LLM 建议 SPLIT | `merge_decision.llm_decision_min_gap` | `new = min(llm_decision_max_gap - 0.10, old - 0.02 × gap_ratio)` |
| 句末标点统一 | `结尾标点修改占比 > 0.3` | LLM Prompt (few-shot) | 注入标点偏好示例 |
| 字幕整体变短 | `median(duration_diff) < -500ms` | `subtitle.max_duration` | `new = max(2.0, old + median(duration_diff))` |

> ★ `llm_decision_max_gap` 调整时强制保持 ≥ `llm_decision_min_gap + 0.10`，防止 LLM 裁决区间坍缩为空集。
