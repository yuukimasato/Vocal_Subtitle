# 复杂音频 ASR 代码审计与优化方案

**日期**：2026-07-29
**范围**：Vocal_Subtitle 当前工作区的离线 Pipeline、ASR、VAD、音频预处理、时间轴映射、说话人融合和质量基准
**本轮交付**：代码审计与优化方案，不修改代码和默认配置

> 本文以当前工作区文件为准。工作区已有未提交修改，本文不对这些修改进行回滚或重写；涉及行号时以本次审计时的文件版本为准。

## 1. 审计结论

问题的主因不是单一 ASR 模型能力不足，而是复杂音频进入了一个以“先切成可信语音段，再逐段识别”为核心假设的链路。人工录音、影视对白和非中文音频同时破坏了这个假设，导致内容错误和时间轴错误相互放大。

最重要的结论有五项：

1. **全局 ASR 设计存在，但当前 `Pipeline.run()` 没有实际调用全局路径。** `global_asr.enabled=true`、`_resolve_asr_path()` 和 `_run_global_transcription_path()` 都存在，但当前主流程只调用 `_process_skeleton_segmented()` 或 `_process_chunk_pipeline()`；代码搜索未发现全局路径的调用点。
2. **默认 `skeleton_mode=true` 并没有真正消除分段 ASR。** 它先用固定阈值的 ffmpeg 骨架切段，再对每个骨架段再次执行 VAD、合并和逐段 ASR，复杂场景下仍然发生上下文断裂。
3. **噪声画像目前主要是诊断数据，没有形成闭环控制。** `_process_chunk_pipeline()` 会计算噪声画像，但没有用它动态调整 Silero threshold、ffmpeg `noise_db`、骨架阈值或 ASR 路由。
4. **三方法边界融合是已有能力，但默认关闭。** `FusionConfig.enabled` 默认是 `False`，现有多个场景配置也显式关闭。在真实噪声环境下，单一 Silero 或纯能量判断都不应承担全部边界责任。
5. **质量验证基础设施不完整。** `.venv` 中全量测试收集 854 项，844 项通过、10 项失败；失败来自可选 diarization 依赖缺失和质量清单引用不存在的音频文件。当前还没有一套可稳定运行的复杂场景端到端基线。

因此建议的优先级不是先调大 padding 或简单降低 VAD 阈值，而是：

> **先接通并验证全局/上下文 ASR，再把物理声学证据改成自适应控制，最后对低置信区域做局部恢复和模型路由。**

## 2. 当前真实调用链

文档和代码中存在多套设计描述，实际 `Pipeline.run()` 的离线主流程如下：

```text
输入音频/视频
  -> 人声分离
  -> 可选宏观切块
  -> 默认进入 skeleton_mode
       -> ffmpeg silencedetect 固定阈值 -40 dB 构建骨架
       -> 对每个骨架段调用 _process_chunk_pipeline
            -> 可选降噪
            -> 计算噪声画像，但只写入诊断上下文
            -> Silero VAD + ffmpeg VAD
            -> fusion.enabled=true 时才做三方法融合
            -> 片段合并
            -> 每个合并段独立调用 ASR
            -> 边界精修 / 边界冗余识别
            -> 时间轴映射
       -> 把每个骨架段的结果加回全局偏移
  -> 事件级说话人融合
  -> 帧级衔接
  -> LLM 语义合并
  -> 声学校验
  -> 最终化和导出
```

关键代码位置：

- `Pipeline.run()` 在 [pipeline.py](../vocal_subtitle/pipeline.py#L1102) 先判断 `skeleton_mode`，而不是先按 `global_asr.routing` 选择 ASR 路径。
- [pipeline.py](../vocal_subtitle/pipeline.py#L3780) 的 `_process_skeleton_segmented()` 对每个骨架段再次调用 [pipeline.py](../vocal_subtitle/pipeline.py#L3463) 的完整 VAD → Merge → ASR 流程。
- [pipeline.py](../vocal_subtitle/pipeline.py#L2056) 的 `_run_asr()` 明确是“每个片段独立识别”。
- 全局路径实现位于 [pipeline.py](../vocal_subtitle/pipeline.py#L219)，路径解析位于 [pipeline.py](../vocal_subtitle/pipeline.py#L479)，但当前主流程没有调用点。
- `GlobalTranscriber` 已实现窗口、重叠去重和可选对齐，见 [global_transcriber.py](../vocal_subtitle/asr/global_transcriber.py#L36)，但没有接入主流程。

### 2.1 “时间轴累积偏移”的准确解释

当前实现并不是简单把每个片段的误差逐段相加，因此不能笼统地断言“每段 ±50 ms 最终必然累积到数秒”。实际风险来自以下组合：

- VAD 起止点错误导致 ASR 上下文被截头或截尾；
- 片段之间的 gap/overlap 被合并、去重或重新投影；
- 骨架段和宏观块分别加全局 offset，边界错误会在块间缝合时表现为跳变；
- 事件级后处理改变事件边界，但可能缺少可靠的词级物理约束；
- 失败窗口、漏识别区间和重叠字幕被后处理删除后，用户看到的时间轴会出现“整体向前/向后漂移”的表象。

所以解决方向应是“保留全局绝对词时间 + 物理证据分配”，而不是继续叠加局部 padding。

## 3. 已有能力与实际缺口

| 能力 | 代码现状 | 对复杂场景的实际价值 | 当前缺口 |
|---|---|---|---|
| 全局 ASR | `GlobalASRConfig`、`GlobalTranscriber`、物理分配器已存在 | 可恢复上下文和绝对词时间 | 主流程未接入；默认配置容易造成“看似启用、实际未用” |
| 物理时间轴 | `PhysicalTimeline`、bins、coverage audit、word alignment 已存在 | 可把 ASR 词投影到声学证据范围 | 依赖可靠的早期物理证据，且没有成为主路由入口 |
| 噪声画像 | `AudioUtils.estimate_noise_floor_per_chunk()` 和 `LocalNoiseProfile` 已存在 | 可估计环境噪声、稳定性和局部差异 | 没有反向控制 VAD、ffmpeg 或 ASR 参数 |
| 三方法 VAD 融合 | `BoundaryFusion` 已实现 | 适合处理中等噪声和边界不确定性 | 默认关闭；融合规则未按场景校准 |
| 降噪 | `AudioPreprocessor` 支持谱门和突发噪声保护 | 可改善 VAD 输入 | 默认关闭；不能无条件用于 ASR，可能损伤清辅音和音乐中的人声 |
| 幻觉过滤 | 已有训练短语过滤、重复/质量模块 | 可减少无声段和低质量文本 | 当前主流程可见的训练短语规则过窄，应使用声学证据、`no_speech_prob`、logprob 和重复率联合判断 |
| 语言检测 | faster-whisper 支持全局检测，分段低置信度可回退 | 能改善短段语言误判 | 仅单次全局检测 + 分段回退；混合语言和低资源语言仍需验证 |
| FunASR | 明确是中文专用，并返回 `zh` | 中文场景可作为专用后端 | 非中文只记录 warning，不阻止错误输出或自动切换 |
| 声学校验 | 已有方向性边界保护、RMS 确认和诊断字段 | 能防止一部分跨静音吸附 | 仍依赖固定 `skeleton_noise_db`；骨架失败时直接跳过 |
| 质量基准 | 有比较脚本、真实素材清单和 benchmark 目录 | 可支撑回归 | benchmark 目录基本为空，清单有坏路径，无法形成稳定端到端基线 |

## 4. 根因分析与风险分级

### P0：全局上下文路径未接入

**证据**：全局路径代码存在于 [pipeline.py](../vocal_subtitle/pipeline.py#L219)，但 `run()` 的三个离线分支均调用 `_process_chunk_pipeline()` 或 `_process_skeleton_segmented()`。`stats.asr_path` 和 `global_attempted` 也没有在主流程中形成可信的运行状态。

**影响**：

- 每个 VAD/merge 段独立识别，缺少句法、词汇和说话连续性上下文；
- 复杂噪声下短段更容易出现语言误判、幻觉和术语错误；
- 词级时间戳只在局部片段内生成，后续需要依赖段起点、边界修正和事件映射恢复绝对时间；
- 用户无法从结果确认实际使用了 global 还是 segmented。

**审计判断**：这是最值得先修的结构性问题，优先级高于调任何 VAD 数值。

### P0：默认骨架模式形成二次切分

`skeleton_mode=true` 时，ffmpeg 骨架负责第一次切分，但骨架段内部仍然执行 Silero VAD、ffmpeg VAD、合并和逐段 ASR。这样既没有获得完整音频上下文，也增加了边界转换次数。

复杂音频中可能出现三种结果：

1. 背景音乐抬高能量，骨架段过长，内部 VAD 继续误切；
2. 远场或低声压语音被固定阈值骨架删除；
3. 语音跨越骨架边界时，两个 ASR 调用都只看到半句话。

此外，`_process_skeleton_segmented()` 在“没有骨架”回退分支返回两个值，而调用方按三个值解包，这是一个独立的可靠性缺陷，应在后续实现阶段先修正。

### P1：固定声学阈值不适合真实录音

当前关键阈值包括：

- Silero `threshold` 默认 0.5；
- ffmpeg `noise_db` 默认约 -35 dB；
- 声学骨架 `skeleton_noise_db` 默认 -40 dB；
- `skeleton_min_silence` 默认 100 ms。

这些值没有使用当前音频的噪声底、动态范围、混响或音乐占比。尤其是 `skeleton_noise_db=-40 dB`：

- 对 TTS 或干净人声通常足够敏感；
- 对底噪约 -30 dB 的影视/户外音频，可能把底噪和 BGM 连成“语音”；
- 对低音量远场语音，可能把真实语音吞掉；
- 骨架构建失败后，`AcousticValidator.validate()` 会直接返回 skipped，物理兜底消失。

### P1：噪声画像没有形成控制闭环

`_process_chunk_pipeline()` 在降噪后计算 `noise_profile`，并存入 `PipelineContext`。但 VAD 调用仍然只读取静态 `self.config.vad.threshold`，ffmpeg 仍读取静态 `acoustic_validation.skeleton_noise_db`。这意味着当前“自适应采样”主要是日志和后续诊断，不会改变检测结果。

还要注意：分离阶段会对 vocals 做峰值归一化，见 [audio_utils.py](../vocal_subtitle/utils/audio_utils.py#L214)。归一化不会改变相对 SNR，但会改变基于 dBFS 的绝对阈值含义，因此固定 dB 阈值跨素材不具备稳定可比性。

### P1：三方法融合默认关闭

`FusionConfig.enabled` 默认值为 `False`，多个配置模板也写明 `enabled: false`。当前代码只有在 `ffmpeg_result` 存在且配置开启时才调用 `BoundaryFusion`，见 [pipeline.py](../vocal_subtitle/pipeline.py#L3597)。

这不是“必须全局打开”的简单问题：音乐和持续环境声会让纯能量方法产生系统性假阳性。因此应先建立置信度/场景路由，再对适合的场景启用融合，而不是直接把开关改成 True。

### P1：预处理默认关闭，但全局开启也有副作用

`NoiseReductionConfig` 在默认配置中关闭，`AudioPreprocessor` 支持谱门和突发噪声保护。现有实现适合作为 VAD 辅助输入，但不应直接覆盖 ASR 原始输入：

- 谱门可能削弱清辅音、尾音和低声压语音；
- 突发噪声插值会改写真实语音中的爆破音或短促音节；
- 音乐现场中的乐器和人声频带重叠，简单谱门不能保证保留人声。

推荐维护“原始/分离音频用于 ASR”和“轻度清理副本用于 VAD/边界检测”两条输入线，并用诊断指标决定是否采用清理副本。

### P1：非中文路由存在错误输出风险

FunASR 的 `detect_language()` 设计上始终返回 `zh`，非中文场景只记录 warning，随后仍会生成中文乱码。对用户而言，这不是普通的低置信度，而是错误后端选择。

faster-whisper 的语言检测目前基于前 30 秒，随后把结果用于所有分段；混合语言再通过片段 logprob 回退。该策略比逐短段检测好，但仍有以下风险：

- 前 30 秒静音、音乐或语言分布不代表全片；
- 多语言视频的段级回退需要可靠的语言概率/文本语言分类；
- 当前缓存需要确保语言、引擎、模型和路径策略全部进入键。

### P2：说话人融合是质量放大器，不是 ASR 修复器

事件级说话人融合已放在后处理阶段，适合修正标签和跨段说话人连续性，但它不能恢复被 VAD 漏掉的文本，也不能把错误 ASR 文本变正确。当前工作区测试环境缺少 `librosa`、`scikit-learn`、`torch`、`pyannote` 和 `huggingface_hub` 等可选依赖，导致相关测试失败，说明运行能力与“全量可用”之间还有环境边界。

## 5. 场景失效画像

| 场景 | 主要破坏条件 | 最可能的首发故障 | 推荐主路径 |
|---|---|---|---|
| TTS | 静音干净、音量稳定、单人 | 当前链路基本可用 | global/windowed ASR + 物理校验；保持低干预 |
| 产品评测 | 口头语、术语、混响、语速变化 | VAD 截断上下文、术语在短段中被误识 | global/windowed ASR；不确定术语做局部重识别 |
| 个人演讲 | 长句、停顿、轻声、尾音渐弱 | 固定静音阈值切断句内停顿，end 时间偏早 | 全局上下文 + 局部边界校正；保守合并 |
| 影视剧 | BGM、音效、多人重叠、对白混响 | 分离残留 + VAD 假阳性/假阴性 + 重叠对白丢失 | 人声分离质量门 + 全局窗口 ASR + overlap/diarization |
| 非中文 | FunASR 中文专用、短段语言检测不稳 | 中文乱码或错误语言锁定 | 语言路由硬门；faster-whisper 多语模型；混合语言局部回退 |
| 音乐现场 | 音乐长期存在，能量边界不代表语音边界 | ffmpeg 骨架和 RMS 失效 | 以 ASR 词时间和 VAD 神经证据为主，降低纯能量权重 |

## 6. 优化方案

### 6.1 P0：先修主路径和时间坐标

#### P0-1：接通可观测的 global/windowed ASR 路由

建议把离线路由重排为：

```text
早期物理证据/噪声画像
  -> 构建 PhysicalTimeline 和上下文窗口
  -> GlobalTranscriber 按窗口识别，窗口带左/右上下文和重叠去重
  -> 词级时间投影到 physical bins
  -> coverage audit
  -> 仅对失败/低覆盖区间做 segmented local recovery
  -> 最终字幕事件和物理校验
```

实现要求：

- `auto` 必须真实尝试 global，并在结果中写明 `asr_path=global` 或 `legacy_degraded`；
- global 失败不能静默伪装成成功的 segmented；
- 长音频按上下文窗口运行，不要把整小时音频一次性塞入模型；
- global 的词时间是候选事实，物理证据用于判断覆盖、截断和异常，不应无条件覆盖高置信词边界；
- fallback 只处理失败窗口或物理覆盖缺口，避免整条音频退回逐段 ASR。

#### P0-2：把 skeleton 从“ASR 分割器”降级为“物理证据源”

骨架可用于建立候选 speech spans 和校验边界，但不要再对每个骨架段完整执行一次 VAD → ASR。候选窗口应覆盖骨架两侧上下文，允许一句话跨过短静音或边界。

如果保留独立 skeleton mode，它应满足：

- skeleton 段只作为物理窗口所有权，不是独立语义上下文；
- 每个窗口至少带可配置的左右上下文；
- 结果合并使用词 ID/时间/文本去重，不使用“start 接近就保留更长文本”的弱规则；
- 无骨架回退返回值、统计和 `stats.asr_path` 必须统一。

#### P0-3：建立单一时间坐标契约

所有模块应明确：

- ASR 窗口内时间：相对窗口起点；
- `GlobalWord.raw_start/raw_end`：全局绝对时间；
- `SubtitleEvent.start/end`：显示时间；
- `physical_start/physical_end`：物理证据包络；
- 每次 offset 只允许在一个边界层执行一次。

建议在开发阶段加入不变量检查：词时间不能倒序、事件不能越过音频总时长、窗口 offset 不能重复应用、跨窗口重复词必须有来源 ID。

### 6.2 P1：建立自适应声学控制

#### P1-1：噪声画像驱动候选阈值，而不是直接替换为任意新常数

应从音频估计以下特征：噪声底、局部噪声 MAD、动态范围、稳定噪声比例、音乐/谐波比例、speech-to-noise proxy。然后选择一组候选策略：

- 低噪声：保持现有敏感度，避免过度清理；
- 稳态中噪声：VAD 召回优先，交给 ASR 置信度和声学证据过滤；
- 高噪声/音乐：降低纯能量证据权重，扩大 ASR 上下文，启用不确定窗口重识别；
- 非稳态噪声：短时边界采用神经 VAD + 局部能量梯度，不使用全局固定 dB 门限。

每次策略选择都应写入诊断：输入特征、选中的阈值、触发原因、候选数量和最终覆盖率。不要只在配置中保存最终数值，否则无法解释结果。

#### P1-2：VAD 多证据融合按置信度加权

建议融合 Silero、ffmpeg/RMS 和 ASR 词时间时使用加权证据：

- Silero：主要负责“是否像语音”；
- ffmpeg/RMS：主要负责起止附近能量变化；
- ASR 词时间：主要负责已识别词的绝对边界；
- 分离质量/音乐检测：负责降低纯能量证据权重。

融合结果应保留每个候选边界的来源和置信度。`min_consensus=2` 只能作为初始规则，不能成为所有场景的永久常数。

#### P1-3：降噪采用双路输入和质量门

建议：

- VAD/骨架使用轻度清理副本；
- ASR 默认使用原始 vocals 或清理前后 A/B 选择更优者；
- 若清理后 ASR 的 `no_speech_prob`、词覆盖或术语一致性变差，自动回退原始输入；
- 对音乐现场默认不启用强谱门，只启用经过验证的突发噪声保护或不做预处理。

### 6.3 P1：ASR 路由、置信度和恢复

#### P1-4：语言硬门和混合语言路由

- FunASR 只允许在明确的中文任务中使用；检测到非 `zh` 时应停止、要求切换或自动回退 faster-whisper；
- 自动语言检测应保存语言概率和检测窗口，不只保存字符串；
- `language_mode=single` 时必须拒绝与检测结果明显冲突的后端；
- `language_mode=mixed/auto` 时，按窗口或事件允许语言变化，并将语言写进词/段元数据；
- 语言、ASR 引擎、模型、路径策略、预处理策略必须进入转录缓存键。

#### P1-5：以“低置信窗口恢复”代替全量重复识别

触发条件可以组合：低平均 logprob、较高 `no_speech_prob` 但有物理语音证据、重复/压缩异常、语言概率冲突、coverage 缺口、词时间跨越物理边界。

恢复顺序建议：

1. 原窗口扩大左右上下文；
2. 保持原始/轻度清理音频做一次 A/B；
3. 使用另一 ASR 后端或更适合该语言的模型；
4. 只在仍然失败时使用局部 segmented recovery；
5. 所有恢复结果保留来源、尝试次数和降级状态。

#### P1-6：增强幻觉过滤，但不靠文本规则误删真实短句

过滤条件应至少包含文本重复、`compression_ratio`、`avg_logprob`、`no_speech_prob`、物理 speech overlap 和上下文重复。训练短语黑名单只能是一个小的补充规则。

对“短词、口头语、数字、产品型号”应使用保守策略：低置信不直接删除，进入 recovery/review 队列，避免把真实内容变成时间轴空洞。

### 6.4 P2：复杂场景专项能力

- 影视剧/多人重叠：将 overlap 作为一等公民，允许重叠物理事件，不用简单去重抹掉第二个说话人；
- 说话人融合：只负责跨窗口 speaker identity 和标签，不作为文本质量判断依据；
- 术语和产品评测：建立词表/上下文提示，但必须经过 ASR 置信和人工基准验证；
- 模型选择：按语言、设备和场景选择 faster-whisper/FunASR/其他兼容后端，不把单一大模型当成所有场景的解决方案；
- 反馈学习：先以 shadow mode 记录参数建议，只有在基准集和用户修订都证明有效时才自动应用。

## 7. 不建议作为首要方案的做法

1. **只把 VAD threshold 调低**：通常会提升召回，也会把 BGM、风声和噪声带入 ASR。
2. **默认全局开启强降噪**：可能改善静音，却损伤清辅音、尾音和音乐中的对白。
3. **只增大 padding 或 `max_snap_distance`**：能减少截尾，但会扩大跨句、跨说话人和跨静音错误。
4. **把 LLM 当作时间轴修复器**：LLM 可做文本规范化和语义合并，不应替代词级时间和物理证据。
5. **只比较最终字幕文本**：必须同时比较事件匹配、内容召回、start/end MAE、物理违规和幻觉率。

## 8. 验证方案与验收指标

### 8.1 先修复基准入口

当前 `test/quality_manifest.yaml` 引用了 `test/中文朗读测试-双人.wav`，仓库实际文件为 `test/TTS中文朗读测试-双人.wav`，导致 `test_quality_benchmark.py` 不能通过。应先修复清单路径，并将可选依赖测试分组：

- core：不需要 torch、sklearn、pyannote、huggingface_hub 的测试；
- asr/vad：需要相应 ASR/VAD 可选依赖；
- diarization：需要 librosa/sklearn/torch/pyannote 的测试；
- e2e-quality：需要真实音频、模型和人工字幕。

### 8.2 建议基准场景

至少保留以下八类样本，且每类包含人工字幕或明确标注“不做文本对比”：

| 类别 | 最少样本 | 必要标签 |
|---|---:|---|
| TTS/干净朗读 | 2 | 语言、单/双人、静音比例 |
| 产品评测 | 2 | 语言、术语、混响、人工字幕 |
| 个人演讲/教学 | 2 | 语速、长句、停顿、人工字幕 |
| 播客/访谈 | 2 | 说话人数、打断、重叠 |
| 影视对白 | 2 | BGM、音效、重叠对白、分离质量 |
| 户外/远场 | 2 | 风噪、混响、距离、音量变化 |
| 非中文 | 2 | 语言、是否混合语言、人工字幕 |
| 音乐现场 | 2 | 音乐占比、歌词/对白、人工字幕 |

### 8.3 指标

**文本质量**：CER/WER 或内容召回、漏词率、幻觉字符率、术语准确率、语言识别准确率。
**时间轴质量**：匹配事件数、start MAE、end MAE、P95、偏差超过 300 ms/500 ms 的比例。
**物理一致性**：事件在语音证据内的比例、跨静音比例、覆盖缺口、重复/重叠处理数。
**工程质量**：实际 ASR 路径、fallback 分类、恢复次数、模型加载失败、每阶段耗时和显存峰值。

### 8.4 消融顺序

每次只改变一组因素，保存完整 JSON 诊断：

1. 当前路径 baseline；
2. 接通 global/windowed ASR；
3. global ASR + skeleton 只做物理证据；
4. 加入自适应噪声控制；
5. 加入场景化 VAD 融合；
6. 加入 VAD/ASR 双路预处理；
7. 加入低置信窗口 recovery；
8. 最后评估 diarization、LLM 合并和术语提示的独立收益。

建议的发布门槛是“复杂场景有收益、干净场景不回退、失败可解释”，具体数值应以修复后的真实基准 baseline 为准，而不是预先承诺未经测量的百分比。

## 9. 分阶段实施路线

### 阶段 0：基准和可观测性

修复质量清单路径；隔离可选依赖；统一 `PipelineStats` 的 `asr_path`、fallback、语言、噪声画像和诊断字段；确保每个测试场景能报告成功/失败及原因。

**进入下一阶段条件**：core 测试全通过，至少六个有人工字幕的真实素材可重复运行。

### 阶段 1：全局 ASR 正式接入

接通 `GlobalTranscriber`、物理 bins、coverage audit 和局部 recovery；实现 global → failed-window recovery → segmented fallback 的明确状态机；修复骨架回退返回值和 offset 不变量。

**进入下一阶段条件**：global/segmented 两条路径的文本和时间轴指标可对比，不能出现静默降级。

### 阶段 2：物理证据自适应

让噪声画像参与阈值候选和证据权重；将 skeleton、VAD、RMS 和 ASR 词时间统一成带来源的 evidence；按场景校准融合，而不是直接全局打开。

**进入下一阶段条件**：高噪声场景骨架跳过率下降，干净 TTS 的时间轴和文本不回退。

### 阶段 3：低置信区域恢复与语言路由

增加语言硬门、非中文自动回退、混合语言窗口、ASR A/B 输入和局部 recovery；完善幻觉过滤和恢复诊断。

**进入下一阶段条件**：非中文不再产生未标记的 FunASR 乱码；失败区域可定位到窗口和原因。

### 阶段 4：影视/多人/音乐专项优化

加入 overlap 事件模型、分离质量门、音乐检测和 speaker fusion 的场景化策略。此阶段不应反过来改变阶段 1 的核心时间坐标契约。

## 11. 最终建议

建议按照以下顺序排期：

1. 修复基准入口和运行状态可观测性；
2. 接通 global/windowed ASR，并让 skeleton 只提供物理证据；
3. 修复全局时间坐标和局部 recovery；
4. 用噪声画像驱动 VAD/ffmpeg/骨架证据权重；
5. 增加非中文硬门、混合语言和双路预处理；
6. 最后处理影视重叠、音乐现场和说话人专项问题。

如果只能先做一项，应选择第 2 项。它同时改善复杂场景的上下文、词级绝对时间和后续物理校验基础，收益面大于单独调 VAD、降噪或字幕合并参数。
