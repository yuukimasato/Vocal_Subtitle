# Vocal Subtitle 离线字幕全链路整体落实计划

日期：2026-08-04  
依据：[离线字幕全链路方案](离线字幕全链路方案-2026-08-02.md)、[功能优先级评估](离线字幕全链路-功能优先级评估-2026-08-04.md)、当前代码、黄金集 manifest 和已有运行报告。  
范围：离线批量字幕生产、质量报告、黄金集门禁和相关诊断。流式模式只保持兼容，不纳入本计划的质量收敛范围。

## 1. 计划结论

当前项目已经具备以下基础能力：

- segmented primary、global evidence、Context Re-ASR/Qwen review 的候选链路；
- `OfflineProductionCoordinator`、`EvidenceDecision` 和 `DecisionEventProjector`；
- shadow/authoritative 两种运行模式；
- PhysicalTimeline、physical owner/bin 校验和覆盖审计；
- golden gate 的基础指标、门禁级 miss attribution 和 per-case 失败摘要；
- 独立运行报告中的引擎 availability 快照。

当前不可发布的主要原因不是缺少新的识别模型，而是质量证据还没有完全闭合：

1. 不同报告的运行模式、manifest、参考集数量和指标口径没有绑定，历史结果不可直接比较。
2. strict match、可听空白和尾随静音尚未作为并列、可审计的最终指标输出。
3. miss attribution 目前能定位到门禁级别，但不能完整定位物理候选、ASR、决策、后处理和最终匹配责任。
4. 黄金集缺少针对短回应和尾段语音的诊断 fixture；已有重叠场景还不能隔离重叠归属问题。
5. engine availability、engine_pair 和窗口实际执行状态尚未合并为一个黄金报告视图。

本计划先冻结测量和诊断，再补质量门禁，最后推进展示契约和治理类 P1。任何质量问题都不得通过放宽匹配或绕过统一投影来“修复”。

## 2. 实施原则

1. 保留现有用户改动，不做无关重构。
2. 代码已具备的 coordinator、global alternative 和 physical merge protection 不重复实现；只补契约、诊断、覆盖和回归。
3. 旧指标与新指标并列一段时间，禁止用新口径直接覆盖旧 baseline。
4. 每个阶段先增加或确认测试，再改变报告或生产行为。
5. global evidence 的默认职责仍是风险和覆盖信号；只有满足已有准入条件的 candidate 才能作为 alternative。
6. shadow 只观察和投影校验，不改变最终事件；authoritative 才允许 projector 结果作为最终事件。
7. 没有物理 speech span 或最终 cue 输入的 case 不得默认计为 coverage 通过，应标记为 `not_evaluable`。
8. `implemented`、`runnable`、`benchmarked`、`gated`、`release-default` 作为能力成熟度记录，不修改既有 `ReleaseStatus` 语义。

## 3. 当前基线

### 3.1 默认运行行为

默认配置是 segmented primary：

```text
segmented/skeleton/chunk primary
  -> global evidence
  -> risk scoring
  -> optional review
  -> EvidenceDecision
  -> DecisionEventProjector
  -> post-process/finalize/export
```

显式 global 路径也会进入 `_run_offline_production_review()` 和 `OfflineProductionCoordinator`，不能再把“global bypass”作为当前代码事实。剩余工作是统一 global signal/alternative 的证据报告和选择追踪。

### 3.2 当前已实现但需保留回归的能力

| 能力 | 当前状态 | 本计划动作 |
|---|---|---|
| OfflineProductionCoordinator | 已接入主要路径 | 保留路径和失败降级回归 |
| global alternative | 已有高风险/冲突窗口准入和物理校验 | 补充角色字段、选择统计和拒绝原因 |
| shadow projection | 已投影诊断但返回 baseline | 保留 `shadow_observed` 语义 |
| SubtitleBuilder 物理合并保护 | 已经调用 `can_merge_events()` | 补齐入口覆盖和 trace，不重复实现 owner 校验 |
| golden miss attribution | 已有门禁级阶段分类 | 深化到 candidate/decision/final event 链路 |
| engine availability | 运行报告已有快照 | 合并到 golden case 的实际执行状态 |

### 3.3 当前阻断指标

当前报告中出现过 `0.116667`、`0.175000`、`0.083333` 等不同 `real_speech_drop_rate`。这些结果来自不同时间、运行模式、引擎组合或参考集口径，不能直接作为同一趋势。

新计划首先冻结以下元数据：

- `input_schema_version` 和 `golden_quality_gate_version`；
- manifest 路径、版本/hash 和 case 列表；
- primary/secondary engine、model、model path；
- production mode、review policy、route/pair route version；
- reference case count、expected speech count 和 reference role 规则；
- old match policy 与 strict match policy。

## 4. 阶段与依赖

### Phase 0：冻结运行口径和报告输入

优先级：P0，所有质量实现的前置。  
目标：让不同运行结果可比较、可复现、可解释。

涉及文件：

- `test/quality_manifest.yaml`
- `scripts/run_offline_golden_production.py`
- `scripts/run_golden_quality_gate.py`
- `vocal_subtitle/quality/golden_gate.py`
- `vocal_subtitle/reporting/run_report_schema.py`
- `docs/superpowers/reports/`

任务：

1. 定义 golden input/report 的运行元数据必填字段。
2. 明确 `reference_role=advisory/strict/none` 和 `reference_status` 的计数规则。
3. 在报告中同时输出 manifest case count、reference case count、expected speech count 和 expected non-speech count。
4. 为旧匹配口径增加显式版本名，例如 `legacy-overlap-v1`。
5. 每次生产运行写入配置、模型、模式、引擎组合和 manifest hash。
6. 将方案文档中的旧验收数字标记为历史结果，并引用具体报告路径。

验收：

- 同一输入重复运行能得到相同的 case 数量和参考集统计；
- 报告可以回答“这次结果使用了什么 manifest、什么模式和什么匹配口径”；
- 不同运行若元数据不同，报告明确标记为不可直接比较；
- 不改变当前字幕输出行为。

禁止并行：Phase 0 完成前，不修改发布阈值、不替换主引擎、不据单次 drop rate 调整 VAD。

### Phase 1：引擎状态和初步 miss table

优先级：P0。  
依赖：Phase 0。  
目标：先知道哪些引擎实际运行，以及 miss 出现在哪个粗粒度阶段。

涉及文件：

- `vocal_subtitle/reporting/engine_availability.py`
- `vocal_subtitle/reporting/run_report.py`
- `vocal_subtitle/reporting/run_report_schema.py`
- `vocal_subtitle/asr/evidence_review.py`
- `vocal_subtitle/application/offline_production.py`
- `scripts/run_offline_golden_production.py`
- `vocal_subtitle/quality/golden_gate.py`

任务：

1. 将 availability snapshot 和 case 级 optional engine diagnostics 合并为 `engine_status`。
2. 每个引擎记录 `lifecycle`、`enabled`、`selected`、`available`、`status`、`model_path`、`windows_processed`、`windows_failed` 和 `reason`。
3. 区分 `selected_but_disabled`、`model_missing`、`port_missing`、`residual_risk_gate` 和 `execution_failed`。
4. 保留现有 `engine_pair`，不再把它当作“实际执行证明”。
5. 输出 per-case miss table，至少包含 expected event、best overlap、best text、时间 gap、当前 attribution stage。

验收：

- 黄金报告能区分选中、启用、可用和实际处理窗口；
- 每个未匹配 speech reference 都有一条可审计的 miss 记录；
- 旧报告输入仍能读取，缺字段时明确标记 unavailable，而不是静默通过。

### Phase 2：strict match 与物理覆盖门禁

优先级：P0。  
依赖：Phase 0、Phase 1 的报告输入。  
目标：同时测量文本/时间匹配质量和最终字幕对物理语音的覆盖质量。

涉及文件：

- `vocal_subtitle/quality/golden_gate.py`
- `scripts/run_golden_quality_gate.py`
- `vocal_subtitle/physical/timeline.py`
- `vocal_subtitle/physical/coverage.py`
- `vocal_subtitle/mapping/finalize.py`
- `vocal_subtitle/acoustic/validator.py`
- `tests/test_golden_quality_gate.py`
- `tests/test_physical/test_coverage_recovery.py`
- `tests/test_end_time_fixes.py`

任务：

1. 保留 legacy match 结果，同时增加 strict match 结果；两者不得覆盖同一字段。
2. strict match 增加最小重叠秒数和可选 overlap ratio，并记录未匹配原因。
3. 为 golden case 增加物理 speech span、final cue 和 coverage audit 的输入字段。
4. 新增 `audible_blank_rate`：统计有文本证据的 physical speech span 未被最终 cue 覆盖的比例。
5. 新增 `trailing_silence_ms`：检查 cue end 与最后有效 speech span end 的差值。
6. 缺少物理证据的 case 输出 `not_evaluable`，不参与“通过”统计。
7. 先以报告指标运行两轮，不立即把 strict match 或新 coverage 指标写入默认发布阻断。

验收：

- legacy 与 strict 口径可以在同一报告中对照；
- 0.001 秒触碰不会在 strict match 中通过；
- 有语音无 cue 和 cue 进入尾随静音都能被独立识别；
- 物理证据缺失不会伪造通过；
- 现有物理违规、跨静音和 raw bypass 检查不退化。

禁止并行：Phase 2 的第一轮对照报告完成前，不调整主 ASR、VAD 或后处理阈值。

### Phase 3：诊断 fixture 和完整 miss attribution

优先级：P0。  
依赖：Phase 1、Phase 2。  
目标：让当前 recall blocker 能定位到责任阶段，而不是继续泛化增加模型。

fixture：

1. 150ms 短词/短回应，至少包含 3 个不同位置的短事件。
2. 最后 2 秒仍有语音的尾段样本。
3. 有明确人工参考和 overlap ownership 标注的双人重叠样本。

涉及文件：

- `test/quality_manifest.yaml`
- `test/golden/`
- `scripts/run_offline_golden_production.py`
- `vocal_subtitle/quality/golden_gate.py`
- `vocal_subtitle/asr/evidence.py`
- `vocal_subtitle/asr/evidence_review.py`
- `vocal_subtitle/physical/coverage.py`
- `vocal_subtitle/physical/decision_projection.py`
- `tests/test_golden_quality_gate.py`
- `tests/test_offline_golden_production.py`

完整归因链：

```text
expected event
  -> nearest physical span / coverage
  -> segmented candidate
  -> global/review/recovery candidate
  -> EvidenceDecision
  -> projected event
  -> post-process/final cue
  -> match classification
```

任务：

1. 为每个阶段保存 candidate IDs、decision IDs、physical span IDs 和 final event IDs。
2. 将当前的 `speech_candidate_missing`、`asr_text_mismatch` 和 `timeline_shift_or_boundary_mismatch` 保留为汇总类别。
3. 增加 `physical_coverage_missing`、`decision_drop_or_unresolved`、`postprocess_coverage_loss` 和 `strict_match_only_failure` 等细分类别。
4. 对每个 case 输出 miss count、阶段分布、最接近候选和物理覆盖情况。
5. 诊断 fixture 只用于归因，不因为加入 fixture 就改变真实参考集分母。

验收：

- 每个未匹配事件能落到一个主要责任阶段或 `unknown_with_evidence_gap`；
- 能区分“没有候选”“有候选但文本错”“决策后丢失”和“最终匹配口径导致失败”；
- fixture 能至少触发短回应、尾段和 overlap 三类预期风险；
- 不通过修改匹配阈值掩盖候选或后处理问题。

### Phase 4：展示层边界回归和统一 trace

优先级：P1。  
依赖：Phase 2、Phase 3。  
目标：巩固已经存在的物理边界保护，避免不同最终化入口产生行为差异。

涉及文件：

- `vocal_subtitle/mapping/subtitle_builder.py`
- `vocal_subtitle/mapping/event_constraints.py`
- `vocal_subtitle/mapping/finalize.py`
- `vocal_subtitle/merging/merge_constraints.py`
- `vocal_subtitle/merging/merge_engine.py`
- `vocal_subtitle/acoustic/validator.py`
- `vocal_subtitle/physical/events.py`
- `tests/test_mapping/test_finalize.py`
- `tests/test_mapping/test_event_ops.py`
- `tests/test_physical/test_phase_three.py`

任务：

1. 核对 SubtitleBuilder、strict segmenter、LLM merge、frame stitch 和 acoustic validator 是否都调用共享 physical owner/bin 约束。
2. 补充缺省 physical spans、physical region、跨 bin、跨 speaker、hard split 和最大时长测试。
3. 让 SubtitleBuilder 的 short-event merge 记录参与 event IDs、物理 owner 和 merge reason。
4. 让 acoustic micro-gap merge 记录 merge count、event IDs、speaker/bin 结果和 boundary trace。
5. 不改变已有“跨物理 bin 不合并”的行为，只统一诊断和测试覆盖。

验收：

- 75 项已有聚焦测试继续通过；
- 所有最终化入口在同一边界条件下得到一致的允许/拒绝结果；
- 任意最终 cue 的边界变化都有 revision/boundary trace；
- 不出现跨 physical bin、跨确认 speaker 或跨 hard split 的 merge。

### Phase 5：骨架/Chunk schema 与 global evidence 契约收敛

优先级：P1。  
依赖：Phase 3、Phase 4。  
目标：把当前已有能力变成稳定、可消费、可比较的证据契约。

涉及文件：

- `vocal_subtitle/application/chunk_runner.py`
- `vocal_subtitle/application/asr_path.py`
- `vocal_subtitle/asr/evidence.py`
- `vocal_subtitle/asr/evidence_review.py`
- `vocal_subtitle/asr/evidence_decision.py`
- `vocal_subtitle/application/offline_production.py`
- `tests/test_asr/test_evidence_review.py`
- `tests/test_asr/test_evidence_review_decision.py`
- `tests/test_offline_production.py`

任务：

1. 统一 skeleton、macro chunk、global、review 和 recovery 的 source ID、offset ID、window ID、去重键和 diagnostics schema。
2. 将 global evidence 角色明确为 `global_signal` 或 `global_alternative`，保留 source=`global` 兼容性。
3. 对 alternative 记录准入规则、rejected reasons、alternative_for、selected candidate ID 和最终 decision。
4. 对 shadow 报告分别统计 signal count、considered alternative count、accepted alternative count 和 selected global count。
5. 骨架空 ASR、物理覆盖缺口和 review unavailable 必须有结构化计数与时间范围。

验收：

- skeleton 与 chunk 路径的同一音频片段可以按 source/offset/word/physical IDs 对照；
- global candidate 不满足物理或词时间契约时只能产生风险诊断，不能替换文本；
- report 能回答 global 是否被选中，以及为什么被拒绝或保留。

### Phase 6：能力成熟度、噪声 shadow 和反馈 profile

优先级：P1/P2，质量基线稳定后执行。  
依赖：Phase 0-5 的报告和回归闭合。  
目标：治理后续可选能力，不让新开关掩盖主链问题。

任务：

1. 在 run report 中增加独立 capability maturity 字段，不修改 `ReleaseStatus` 的三态语义。
2. 将 `implemented`、`runnable`、`benchmarked`、`gated`、`release-default` 绑定到测试、运行报告和黄金门禁证据。
3. 输出噪声画像诊断和建议阈值，例如 `suggested_vad_threshold`、`suggested_skeleton_noise_db`，但默认不应用。
4. 在运行入口明确是否加载 `config.feedback.active_profile`，记录 profile、版本和 overrides hash。
5. profile 先 shadow 对照，满足回归和回滚条件后再允许用户级或场景级消费。
6. 将 `cover_policy` 与 `engine_policy` 拆分前，先保留旧 `review_policy` 兼容映射。

验收：

- 任何可选引擎、噪声建议或 profile 都能回答“是否实际生效”；
- profile 失败可以回退到 base config；
- 噪声建议不改变默认 VAD/ffmpeg/hallucination 行为；
- 未通过真实/回归质量验证的能力不能标记为 `gated` 或 `release-default`。

## 5. 推荐执行顺序

```text
Phase 0  运行口径、manifest、schema 冻结
  -> Phase 1  engine_status + 初步 miss table
  -> Phase 2  strict match + audible blank + trailing silence
  -> Phase 3  诊断 fixture + 完整 miss attribution
  -> Phase 4  展示边界回归 + trace
  -> Phase 5  skeleton/chunk schema + global evidence 契约
  -> Phase 6  capability maturity + noise shadow + feedback profile
```

Phase 0-3 必须串行推进，因为它们共同定义当前发布阻断项的测量与归因。Phase 4-5 可以在 Phase 3 的归因报告稳定后分别准备，但 Phase 5 的最终 schema 收敛应吸收 Phase 4 的边界回归结果；期间不得同时修改主 ASR 和门禁口径。Phase 6 只能在前面阶段没有未解释的 raw bypass、物理违规或报告缺失时启动。

## 7. 阶段完成定义

### P0 完成

- 报告元数据完整且运行结果可比较；
- engine_status 能区分选择、启用、可用和实际执行；
- legacy/strict match 并列；
- audible blank 和 trailing silence 可测量或明确标记不可评估；
- 短回应、尾段和 overlap 诊断 fixture 可复现；
- 每个 miss 至少有粗粒度阶段归因；
- 现有 physical violation、cross silence、raw bypass 和 trace 检查不退化。

### P1 完成

- miss attribution 可沿 candidate/decision/projection/final cue 链路追踪；
- 最终化入口共享 physical boundary policy 和 trace；
- skeleton/chunk/global evidence schema 可对照；
- global signal/alternative 的准入和实际选择有统一报告；
- capability maturity 与 ReleaseStatus 分离。

### 发布条件

`real_speech_drop_rate <= 0.05` 仍是目标条件，但必须与 strict match、参考集版本、场景分布和 miss attribution 一起解释。若指标未通过，项目保持“不可发布/质量改进中”，并根据归因结果继续修复，不以增加模型数量或放宽门禁替代质量证据。
