# 离线字幕全链路 功能需求优先级评估（2026-08-04）

基于 2026-08-04 代码审计结果，对照 [离线字幕全链路方案-2026-08-02](离线字幕全链路方案-2026-08-02.md) 文档，逐项评估各项功能需求的紧迫性和适用性。

---

## 评估方法

每项功能按四个维度评估：

| 维度 | 说明 |
|------|------|
| **必要性** | P0（阻断发布）/ P1（质量提升）/ P2（锦上添花）/ N（不需要） |
| **当前状态** | 已实现 / 部分实现 / 缺失 |
| **文档偏差** | 文档描述是否与代码实际一致 |
| **建议动作** | 补全 / 修正文档 / 保持不变 / 移除 |

## 一、需要做（P0 — 阻断发布或影响质量基线）

### 1.1 Golden Gate 匹配条件收紧

| 项 | 说明 |
|----|------|
| **当前状态** | `_matched()` 仍仅要求 `overlap > 0` + `similarity >= 0.35`，0.001s 触碰即可匹配；但当前已有的多轮报告不是同一运行口径，不能直接把不同报告的 drop rate 横向比较 |
| **文档偏差** | 文档 R10.3/R10.5 已指出此问题，列为"即日可执行"但尚未实现 |
| **建议动作** | 先保留旧口径作为 baseline，同时增加 strict match（`min_overlap_seconds >= 0.15`、可选 `min_overlap_ratio >= 0.3`、更严格文本相似度）并列输出；连续两轮可复现后，再决定是否将 strict 口径纳入发布门禁 |
| **影响文件** | [golden_gate.py:107-110](vocal_subtitle/quality/golden_gate.py#L107-L110) |

**理由**：当前方案文档、2026-08-02 runtime 报告和 2026-08-03 strict 报告分别出现 `0.116667`、`0.175000`、`0.083333`，运行模式和参考集口径不同。必须先固定 run schema、模型、模式、manifest 版本和参考集数量，再做新旧匹配口径并列，否则会把测量变化误判为质量变化。

### 1.2 可听空白率 (audible_blank_rate) 和尾随静音 (trailing_silence_ms) 门禁

| 项 | 说明 |
|----|------|
| **当前状态** | 代码和 golden gate 中尚无这两个最终指标；已有 PhysicalTimeline、projection coverage 和 acoustic validator，可作为实现基础 |
| **文档偏差** | 文档 G11/G12 和 15.8 节定义了这两个指标，标注为"NOT YET" |
| **建议动作** | 先扩展每个 golden case 的物理 speech span 和最终 cue 输入契约，再实现：(1) 逐 speech span 计算 final cue coverage；(2) 校验 `cue.end <= speech_end + 3ms`；(3) 将缺少物理证据的 case 标记为不可评估，而不是默认通过 |
| **影响文件** | [golden_gate.py](vocal_subtitle/quality/golden_gate.py), [subtitle_builder.py](vocal_subtitle/mapping/subtitle_builder.py), [validator.py](vocal_subtitle/acoustic/validator.py) |

**理由**：有语音但无字幕的空窗是用户体验的直接损伤。当前只检查了 `cross_silence`（跨静音），没有检查反向问题——语音区间缺少字幕覆盖。
