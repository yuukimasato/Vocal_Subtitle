# 字幕识别浏览器实测优化方案

日期：2026-07-27
范围：`test/` 真实音频、Web GUI 浏览器链路、字幕时间轴与字幕事件构建

## 1. 目标与结论

本方案基于 Web GUI 实际上传音频、后台 Pipeline 识别、导出 ASS，并与 `test/` 下人工 ASS 对比的结果制定。

本轮最主要的问题不是所有时间戳都存在固定偏移，而是：

1. 一个 ASR 事件包含多个自然句子，字幕构建没有始终按句末标点和词级时间戳拆分。
2. 相邻事件的起止边界由 VAD 段边界、ASR 段级时间戳和后处理合并共同决定，连续讲话时会形成约 1 秒级的错位。
3. `TimeMapper` 在每个语音段的最后一个 ASR 结果上倾向使用整个 `speech_seg.end`，会把段尾静音或下一句前的空白带入字幕。
4. 声学校验健康度只说明事件是否落在声学范围内，不能代替人工字幕的句子边界质量评估。
5. WebSocket 完成事件存在竞态：短任务可能在前端完成 WebSocket 连接前结束，页面会一直显示“处理中”。

建议采用“物理边界约束 + 词级时间戳 + 句法拆分 + 语义合并”的分层策略：

```text
声学证据确定可用范围
    -> ASR 词级时间戳确定词边界
    -> 句末标点/硬边界拆分字幕事件
    -> 只在无硬边界且满足时长约束时合并
    -> 最终声学校验与结构校验
```

## 3. 根因定位

### 3.1 字幕构建只在“过长”时拆分

`vocal_subtitle/mapping/subtitle_builder.py` 的 `_split_long_events()` 只有在超过 `max_duration` 或字符数限制时才调用 `_split_event()`。因此一个 3～5 秒、字符数尚未超限、但包含多个句末标点的事件不会被拆分。

虽然 `_split_event()` 已支持句末标点和词级时间戳，但它没有成为所有多句事件的常规路径。这正是中文多人样本中“立即……楼梯 / 酒店火警请立即离开”被合并、培训样本中多个英语短句被合并的直接原因。

### 3.2 CJK 文本与词级时间戳匹配能力不足

`_time_utterances()` 会调用 `_match_words_to_text()`。当前实现主要依赖正则词匹配，英文可以按空格匹配，中文连续文本缺少天然词边界时容易退回字符比例估算。字符比例无法表达真实停顿和说话速度变化，会把句内多个句子的时间平均摊开。

优化应优先使用 ASR 返回的词顺序和时间范围；中文应增加字符级或规范化后的连续匹配，并将句末标点归属于前一个内容词。

### 3.3 末尾事件过度使用语音段结束时间

`vocal_subtitle/mapping/time_mapper.py` 在一个语音段的最后一个 ASR 结果上将 `global_end` 锚定到 `speech_seg.end`。当同一段内包含多个 ASR 事件时，这会把最后事件的结束点扩展到整个 VAD 段末；当 ASR 未覆盖段尾或段内存在自然停顿时，容易产生结束时间偏差。

改造后应遵循：

- 有词级时间戳：以最后一个真实内容词的 `end` 为主。
- 有声学尾随证据：只允许在受限范围内追加尾随余量。
- 无词级时间戳：才回退到 ASR 段级时间或 `speech_seg.end`。
- 任何回退都不得越过下一事件起点、物理硬边界或音频范围。

### 3.4 合并决策没有把“强句末边界”作为硬约束

当前合并流程同时处理声学间隙、短片段和语义合并。若一个事件以句末标点结束，且下一事件是新的完整句子，不能仅因为间隙较短或合并后总时长未超限就合并。

应将以下边界设为不可跨越：

- 说话人变化。
- 物理骨架硬切点。
- 明确的句末标点加上后续完整句子。
- `hard_split_before`、物理区域不连续或来源词不连续。

只有没有这些硬边界时，才允许用语义合并解决“换气但仍是一句话”的情况。

### 3.5 WebUI 完成状态存在短任务竞态

`vocal_subtitle/webui/static/index.html` 的 `handleRun()` 先提交 REST 请求，再连接 WebSocket。短音频可能在 WebSocket 建立前就完成，前端收不到 `complete`，`isRunning` 保持为真。此次浏览器测试中，首个短样本确实出现了页面仍显示“处理中”、刷新后才能提交下一任务的现象。

## 4. 分阶段优化方案

### Phase 0：建立可重复基线

目标：保证后续改动能区分“识别文本错误”“事件边界错误”和“测试工具误匹配”。

工作项：

1. 在 `test/quality_manifest.yaml` 中登记所有音频、人工 ASS、语言、场景类别和是否可验收。
2. 扩展 `scripts/compare_timeline.py`，输出事件数量差异、1:N/N:M 对齐、文本相似度、句子合并/拆分分类，而不是只按事件数量相同直接 zip。
3. 每次报告记录 ASR 模型、语言、设备、是否跳过分离、配置哈希、实际 ASR 路径和缓存命中状态。
4. 将声学健康度与字幕参考对齐质量分成两个指标，禁止用健康度 100% 推断字幕边界正确。

验收：同一输入和同一配置重复运行，输出统计和事件数量稳定；无人工字幕的样本不会进入精度汇总。

### Phase 1：修复字幕事件完整性和句子边界

目标：先消除“多句合一”和“首部标点/孤立碎片”，不改变 ASR 模型。

修改范围：

- `vocal_subtitle/mapping/subtitle_builder.py`
- `vocal_subtitle/mapping/strict_segmenter.py`
- `vocal_subtitle/asr/text_normalizer.py`
- 必要时同步 `vocal_subtitle/physical/events.py`

实现要点：

1. 句末标点默认触发候选拆分，不再只在过长事件中拆分。
2. 拆分必须落在词级时间戳或中文字符序列的稳定边界上，禁止把一个词拆成两个事件。
3. CJK 文本使用规范化后的字符级顺序匹配；英文保留词级匹配。
4. 句末标点、逗号、括号和引号归属前一个内容词；纯标点事件丢弃。
5. 同一 speaker、无硬边界、总时长和显示长度允许时，短碎片可合并；明确句末后的完整新句不得被短片段规则重新合并。
6. 事件重建统一复制 `speaker_id`、`speaker_label`、`words`、来源词和物理边界元数据。
7. 最终统一重新编号，保证 index 连续、唯一且按 start 排序。

验收重点：

- 中文多人样本中两句火警播报应拆为两条。
- 培训和视频样本中的编号短句、问句、短回应不被合并到前后事件。
- 无首部标点、无纯标点事件、无单字/单词孤立后缀。

### Phase 2：修复词级时间边界和段尾扩展

目标：降低连续讲话中的 1 秒级 start/end 错位。

修改范围：

- `vocal_subtitle/mapping/time_mapper.py`
- `vocal_subtitle/asr/boundary_refiner.py`
- `vocal_subtitle/acoustic_validator.py`
- `vocal_subtitle/pipeline.py`

实现要点：

1. `TimeMapper` 对每个事件优先使用首词 start 和末词 end，不因事件是语音段最后一条就直接扩展到 `speech_seg.end`。
2. 用“前一事件末词 end 与后一事件首词 start 的中点/声学转折点”确定相邻边界，避免整段边界向前或向后吞并。
3. 只在末词时间戳缺失或明显非法时回退到段级边界，并记录回退原因。
4. `BoundaryRefiner` 的收缩和扩展限制在物理骨架允许范围内；保留足够尾随余量，禁止重复收缩。
5. 帧级无缝衔接只适用于无句末硬边界、无 speaker 变化且 gap 小于阈值的事件。
6. 声学校验必须运行在所有语义合并和事件重建完成之后，并输出 `word_boundary_error`、`physical_boundary_error` 等细分诊断。

验收目标：

- 配对样本总体 Start/End MAE <= 250ms。
- 每个配对样本 >300ms 的 start/end 事件比例 <= 20%。
- 视频和培训样本不再出现连续 1 秒阶梯式边界漂移。
- 事件不越过物理静音硬边界，且不产生负时长或交叉覆盖。

### Phase 3：优化声学切段与合并策略

目标：减少 VAD 误合并，同时不把自然换气全部切成碎片。

修改范围：

- `vocal_subtitle/vad/ffmpeg_vad.py`
- `vocal_subtitle/vad/boundary_fusion.py`
- `vocal_subtitle/merging/merge_strategy.py`
- `vocal_subtitle/merging/llm_merge_engine.py`
- `vocal_subtitle/config.py` 与场景 YAML

实现要点：

1. 将“物理硬边界”“句法边界”“可合并自然停顿”分成三类，不用单一 gap 阈值处理。
2. 合并前检查句末标点、speaker、物理来源连续性和词序。
3. 对 200～600ms 的中间区间使用规则/本地 NLP；只有存在真实歧义时才调用云端 LLM。
4. LLM 只能决定是否合并以及文本组织，不能改写时间、speaker 或物理来源。
5. 调整配置前先用 Phase 0 基线做单参数实验，避免继续叠加无法归因的 YAML 改动。

验收：相同输入在 `rule_only`、本地 NLP 和 LLM 级联三种模式下均保持事件合法；LLM 不可用时规则降级不会重新引入句末跨越。

### Phase 4：修复 WebUI 任务完成闭环

目标：保证短任务、长任务、缓存命中和 WebSocket 断线时页面状态一致。

修改范围：

- `vocal_subtitle/webui/static/index.html`
- `vocal_subtitle/webui/api.py`
- WebSocket 相关测试

实现要点：

1. REST 提交成功后先读取任务状态，再建立 WebSocket；若状态已经是 completed/failed，直接加载结果。
2. WebSocket 连接后增加轻量轮询兜底；连接断开时继续查询任务状态，而不是永久保持 running。
3. `complete`、`error` 和轮询结果统一走同一个状态收敛函数，保证 `isRunning`、按钮、结果区和历史记录一致。
4. 增加短音频竞态测试、长任务刷新测试、缓存命中测试和失败恢复测试。

验收：短音频完成后 1 秒内按钮恢复可用；WebSocket 丢失时任务仍能显示最终结果；刷新页面后可从任务历史恢复结果。

## 5. 测试与回归矩阵

### 单元测试

- 句末标点触发拆分。
- CJK 字符级词时间匹配。
- 词级边界优先于 `speech_seg.end`。
- 段尾缺失词时间戳时的受限回退。
- speaker/physical/source 元数据在拆分和合并后保留。
- index 连续唯一，事件按时间排序。
- 纯标点、首部标点和孤立碎片清理幂等。

### 真实素材回归

每次优化至少运行四个有人工字幕样本，并分别记录：

- 匹配率和 1:N/N:M 结构差异。
- Start/End MAE、P95、>300ms 和 >500ms 比例。
- 文本字符级相似度或 CER/WER。
- speaker 切换一致性。
- 物理越界、重叠、负时长、重复 index。
- 实际耗时、缓存命中和降级路径。

无人工字幕样本只做稳定性、耗时、错误率和输出合法性检查。

### WebUI 回归

使用浏览器技能覆盖：

1. 上传短样本并等待结果。
2. 上传长样本并等待结果。
3. 任务完成前刷新页面，从历史恢复。
4. WebSocket 断开后任务完成。
5. 缓存命中结果加载。
6. 导出 SRT、VTT、ASS 并检查三种格式事件一致。

## 6. 发布门槛、风险与回滚

### 发布门槛

- 全量单元测试通过。
- 配对真实样本总体 Start/End MAE <= 250ms。
- 每个配对样本匹配率 >= 90%，且 >300ms 比例 <= 20%。
- 不存在重复 index、负时长、事件越过物理硬边界。
- WebUI 短任务和 WebSocket 丢失场景均可恢复。
- 与生产默认 `large-v3`、完整分离流程至少各完成一次抽样回归。

### 主要风险

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 句末强拆导致字幕过碎 | 阅读体验下降 | 只在有词级/稳定字符边界时拆分，短片段按硬边界保护合并 |
| CJK 匹配误配字符 | 时间边界错误 | 记录匹配置信度，低置信度回退并标记诊断 |
| 声学阈值对不同录音不稳定 | 某些素材漏检或过切 | 保留场景配置和 shadow 对比，不直接全局调参 |
| 参考 ASS 的事件切分风格不同 | 误判质量下降 | 同时看文本覆盖、物理合法性和时间误差，不强制事件数量相等 |
| 修复 WebSocket 引入重复请求 | 后端重复任务 | 任务 ID 幂等查询，不能重复启动 Pipeline |

### 回滚策略

每个 Phase 独立提交，配置参数通过 profile 控制；任何阶段导致总体指标下降时，回滚该阶段，保留对比报告和诊断数据，不删除浏览器测试输出。

## 7. 推荐实施顺序

1. 先完成 Phase 0，修正评测工具和素材清单。
2. 实施 Phase 1，解决句子合并、CJK 匹配和事件结构问题。
3. 实施 Phase 2，处理 `TimeMapper` 段尾扩展和连续讲话边界。
4. 用固定参数对 Phase 1/2 做真实素材 A/B 对比。
5. 再实施 Phase 3 的声学与语义合并调优。
6. 独立实施 Phase 4，修复 WebUI 任务状态闭环。
7. 最后使用生产模型和完整默认流程进行发布前回归。

本方案不把“人工字幕事件数量完全一致”作为硬目标；硬目标是文本覆盖正确、事件边界可解释、时间轴物理合法、字幕可读且结果稳定。
