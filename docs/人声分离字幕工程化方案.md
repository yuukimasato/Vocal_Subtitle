## 一、项目概述

### 1.1 项目背景

在视频内容生产、在线教育、会议记录、播客后期等场景中，从音频中分离人声并生成精准字幕是高频刚需。市场上虽有多款闭源商业方案，但存在以下痛点：

- **费用高昂**：按分钟计费的云端 ASR 服务，长视频成本难以承受
- **数据隐私**：音频上传至第三方服务存在合规风险
- **协议风险**：开源工具的模型权重协议各异，商用场景下易踩坑
- **流程割裂**：人声分离、VAD、ASR、字幕拼接各自独立，缺少统一工程方案

### 1.2 项目目标

构建一条**全开源、全 MIT 兼容、可私有化部署**的人声分离+字幕生成工具链，涵盖从原始音频到 SRT/VTT 字幕的完整流程。

### 1.3 适用范围

| 场景 | 典型输入 | 期望输出 |
|------|----------|----------|
| 播客/访谈 | 1–3 小时音频（WAV/MP3） | SRT 字幕，准确率 ≥ 95% |
| 教学视频 | 课程录音（含板书讲解） | 带时间轴的 VTT 字幕 |
| 会议记录 | 多人对话录音 | 按说话人标注的字幕 |
| 综艺/直播 | 含背景音乐的节目音频 | 精准人声提取 + 字幕 |
| 短视频批量 | 批量 1–3 分钟视频 | 快速生成 SRT，批量输出 |

### 1.4 技术选型原则

1. **协议优先**：所有依赖必须为 MIT / Apache 2.0 / BSD 类协议，模型权重须单独验证
2. **本地离线**：核心链路不依赖云端 API，支持完全私有化部署
3. **品质可调**：支持多档分离/识别工具，按场景需求配置品质/速度平衡
4. **工程化**：CLI 一键执行、YAML 配置驱动、批量处理、进度反馈

## 二、需求分析

### 2.1 功能性需求

#### F1 — 人声分离

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| F1.1 | 支持从音频中分离人声与伴奏（2-stem） | P0 |
| F1.2 | 支持多种分离引擎（Spleeter / Open-Unmix / UVR）可切换 | P0 |
| F1.3 | 分离后输出标准化为 16kHz / mono / PCM 16-bit WAV | P0 |
| F1.4 | 支持多说话人分离（音色聚类）+ LLM 角色标注 | P1 ✅ |
| F1.5 | 支持去混响/去回声处理 | P2 |

#### F2 — VAD 语音检测

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| F2.1 | 基于神经网络的语音活动检测（Silero VAD） | P0 |
| F2.2 | 支持可配置的灵敏度和最小语音/静音时长 | P0 |
| F2.3 | 降级方案：WebRTC VAD / ffmpeg silencedetect | P1 |
| F2.4 | 双重 VAD 精切模式（粗切+精切） | P2 |

#### F3 — 片段合并

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| F3.1 | 相邻间隔 < 阈值的片段自动合并 | P0 |
| F3.2 | 超长片段（> 30s）在最长静音处切分 | P0 |
| F3.3 | 片段两端自动添加 padding | P0 |
| F3.4 | 合并参数按场景模板化配置 | P1 |

#### F4 — ASR 语音识别

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| F4.1 | 基于 faster-whisper 的高精度语音识别 | P0 |
| F4.2 | 支持语言锁定（zh/en/ja 等），跳过自动检测 | P0 |
| F4.3 | 词级时间戳输出（word_timestamps） | P0 |
| F4.4 | 每段独立识别，防止跨段幻觉 | P0 |
| F4.5 | 支持 whisper.cpp 降级方案（CPU/Apple Silicon） | P1 |
| F4.6 | 中文优化方案（Fun-ASR-Nano） | P2 |

#### F5 — 时间轴映射与字幕输出

| 编号 | 需求描述 | 优先级 |

| F5.1 | 段内时间戳 + 段偏移 = 全局时间的精准映射 | P0 |

| F5.4 | 多格式输出：SRT / VTT / ASS | P0 |
| F5.5 | 使用 pysubs2 统一管理字幕格式 | P1 |

#### F6 — LLM 后处理优化

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| F6.1 | LLM 修正 ASR 识别错误（错别字、断句等） | P1 |
| F6.2 | 去除语气词和噪音标记 | P1 |
| F6.3 | Agent Loop 自动验证和重试机制 | P1 |
| F6.4 | 批量并发优化，保持索引对齐 | P1 |

```python
            output_dir: 输出目录

        Returns:
            SeparationResult: 包含人声路径和伴奏路径

        ...

    @abstractmethod

        """加载模型（延迟加载）"""
```

```
格式：WAV (PCM 16-bit)
```

通过 `audio_utils.normalize_audio()` 统一转换。

### 4.2 Stage 2 — VAD 语音检测模块

### 4.3 Stage 3 — 片段合并模块

#### 4.3.1 合并算法

```
输入: List[SpeechSegment]  (VAD 检测结果)
输出: List[SpeechSegment]  (合并/切分/填充后的片段)

Step 1: 按 start 时间排序
Step 2: 遍历相邻段：
         if gap < min_silence_gap → 合并
Step 3: 遍历合并后片段：
         if duration > max_segment_length → 在段内最长静音处切分
Step 4: 每段两端加 padding
Step 5: 边界裁剪（不超出 0 ~ 音频总时长）
```

#### 4.3.2 参数设计

```python
@dataclass
class MergeConfig:
    min_silence_gap: float = 0.4     # 合并阈值（秒）
    max_segment_length: float = 30.0  # 最大段长（秒）
    padding: float = 0.1             # 两端填充（秒）
    min_segment_length: float = 0.5  # 最小段长（秒），过短丢弃
```

### 4.5 Stage 3.5 & 4.5 — 说话人分离与角色标注（新增）

说话人标注分为两个独立可选的子阶段：
- **Stage 3.5 说话人分离**：基于音色特征的凝聚聚类，离线运行，无需网络
- **Stage 4.5 角色标注**：利用 LLM 从对话上下文中挖掘姓名和角色，可选云端步骤

#### 4.5.1 Stage 3.5 — 音色特征聚类

**算法流程**：

1. 从完整音频中按边界提取各语音片段
2. 计算 ~87 维声学特征向量（MFCC 65d + 频谱 12d + 基频 2d + 共振峰 4d + 时域 2d + 能量 2d）
3. StandardScaler 标准化 → PCA（保留 95% 方差）→ AgglomerativeClustering（余弦距离）
4. 计算 Silhouette Score 评估聚类质量：
   - \> 0.5：清晰分离
   - 0.25–0.5：可接受
   - \< 0.25：低置信度，建议人工审核

**关键参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `distance_threshold` | 0.5 | 凝聚聚类合并阈值（余弦距离），越小越容易分成更多说话人 |
| `min_speakers` | 1 | 最少说话人数（后处理约束） |
| `max_speakers` | 10 | 最多说话人数（后处理约束） |
| `use_pca` | true | 聚类前是否 PCA 降维 |
| `pca_variance` | 0.95 | PCA 保留的方差比例 |

**输出**：与片段等长的 `List[int]`，每个值代表对应片段的说话人编号（0, 1, 2, ...）。

**依赖**：librosa（ISC） + scikit-learn（BSD），均为宽松协议，可商用。

**未来升级路径**：预留 `DiarizationEngine` 抽象接口，后续可接入 SpeechBrain ECAPA-TDNN（Apache 2.0）或 Resemblyzer（MIT）获得更高精度的神经说话人嵌入。

#### 4.5.2 Stage 4.5 — LLM 角色标注

**三级命名策略**：

| 级别 | 来源 | 示例输出 | 触发条件 |
|------|------|---------|---------|
| **身份识别** | 上下文名字挖掘 | `张三(嘉宾)` | 从介绍/称呼/自述中发现姓名 |
| **角色推断** | 对话动态分析 | `主持人` | Q&A 模式、说话占比、专业度等 |
| **兜底** | 序列编号 | `说话人A` | 无法识别任何信息 |

**名字挖掘模式**（以中文为例）：

| 模式 | 示例 | 提取 |
|------|------|------|
| **介绍** | "今天我们请到了**张三教授**" | 姓名 + 头衔 |
| **直接称呼** | "**李老师**，您怎么看？" | 从称呼中提取姓名 |
| **自我介绍** | "我是**王五**，来自..." | 姓名 |
| **第三方提及** | "刚才**小陈**说的很对" | 交叉引用 |

**角色推断信号**：

| 信号 | 通常角色 |
|------|---------|
| 开场/结束对话，介绍嘉宾 | 主持人 |
| 向他人提问多 | 采访者 / 主持人 |
| 长篇回答问题，分享专业知识 | 嘉宾 / 受访者 |
| 使用大量领域术语、提供详细分析 | 专家 / 讲师 |
| 提问式对话，求教语气 | 学生 / 听众 |
| 叙述/描述事件（非对话） | 旁白 / 解说 |

**输出格式**：
```json
{
  "A": {"name": "张三", "role": "嘉宾", "label": "张三(嘉宾)", "confidence": "identity"},
  "B": {"name": null, "role": "主持人", "label": "主持人", "confidence": "role"},
  "C": {"name": null, "role": null, "label": "说话人C", "confidence": "fallback"}
}
```

`label` 字段即为最终显示在字幕中的标签。

**容错设计**：
- JSON 解析失败 → 重试一次（更低温度 + 严格 JSON 指令）
- 重试仍失败 → 自动退化为 `说话人A`、`说话人B`...
- LLM API 不可用 → 同上兜底

#### 4.5.3 字幕输出效果

**Bracket 样式**（默认）：
```
1

[张三(嘉宾)] 谢谢主持人，很高兴能来这里。

2
00:00:04,500 --> 00:00:08,300
[主持人] 张教授，您怎么看当前的经济形势？
```

支持的显示格式：`bracket`（`[角色] 文本`）、`prefix`（`角色: 文本`）、`none`（无标签）。

### 4.6 Stage 5 — 时间轴映射模块

#### 4.5.1 核心映射算法

```
全局时间 = 片段偏移 + 段内 ASR 时间戳

对于第 i 个片段:
  片段偏移 offset_i = 片段在原始音频中的起始时间
  ASR 返回段内时间: (local_start, local_end)
  → 全局时间: (offset_i + local_start, offset_i + local_end)
```

#### 4.5.2 段间间隙处理策略

```
间隙 gap = T_B_start - T_A_end

策略：
  gap ≤ 0.2s   → A 字幕结束时间 = B 开始时间 - 1ms（无缝）
  0.2 < gap ≤ 1.0s → 保留自然停顿
  gap > 1.0s   → 保留为段落间隔（双换行）
```

#### 4.5.3 字幕行构建规则

```python
@dataclass
class SubtitleRule:
    min_duration: float = 0.8      # 最小字幕时长（秒）
    max_duration: float = 5.0      # 最大字幕时长（秒）
    max_chars_cjk: int = 20        # 中文每行最多字数
    max_chars_latin: int = 42      # 英文每行最多字符数
    max_lines: int = 2             # 单条字幕最多行数
```

该模块从 [VideoCaptioner](https://github.com/WEIFENG2333/VideoCaptioner) 提取并独立封装，已实现：

- **多 API 兼容**：支持任意 OpenAI 兼容 API

详见 [llm_subtitle_optimizer/README.md](../llm_subtitle_optimizer/README.md)。

### 8.4 精度评估方案

```python
# 使用 WER (Word Error Rate) 评估 ASR 识别精度
# 使用 IoU (Intersection over Union) 评估 VAD 区间精度
# 使用 Mean Time Error 评估时间轴偏移

def evaluate_pipeline(audio_path, ground_truth_srt):
    """全链路精度评估"""
    output_srt = pipeline.run(audio_path)

    # 文本精度
    wer = compute_wer(ground_truth_srt.text, output_srt.text)

    # 时间精度
    time_error = compute_mean_time_error(
        ground_truth_srt.timestamps,
        output_srt.timestamps
    )

    return {"WER": wer, "mean_time_error_ms": time_error}
```

### C. 关键公式

```
全局时间 = 片段偏移 + 段内 ASR 时间戳

字幕行拆分条件:
  if duration > max_duration or char_count > max_chars:
      → 在标点处拆分

相邻段间隙处理:
  gap = T_next.start - T_current.end
  if gap ≤ 0.2s  → merge (无缝衔接)
  if 0.2 < gap ≤ 1.0s → keep (自然停顿)
  if gap > 1.0s  → paragraph break (段落间隔)
```
