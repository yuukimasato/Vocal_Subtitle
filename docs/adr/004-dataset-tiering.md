# ADR-004: 数据集分层

**状态**: 部分实施
**日期**: 2026-08-02
**决策者**: yuukimasato

## 背景

当前项目包含多种测试素材：`test/` 目录音频、`quality_manifest.yaml`、合成 TTS 样本、开发调试录音等。这些素材的来源、授权状态、标注质量和使用目的各不相同，但历史上被笼统称为"测试集"或隐含"黄金集"语义。这种混淆导致：
- 在低质量样本上的失败被等同于"不可发布"
- 特定样本驱动了针对性优化，可能损害泛化能力
- 缺乏正式的回归集来稳定评估版本趋势

## 决策

1. **所有数据分为五层管理**：
   - **D0 工程诊断集**：单一功能测试、合成片段、临时复现音频。用于单元/组件/端到端回归。允许随功能增加。
   - **D1 参考回归集**：已审核、可复现、场景覆盖明确的内部授权样本。用于版本趋势和退化发现。
   - **D2 候选反馈集**：用户同意留存的原始任务和人工修订结果。入库后先脱敏、去重、质量检查。
   - **D3 反馈回归集**：从 D2 中完成授权、匿名化、标注审核和分层抽样的样本。可作为发布门禁。
   - **D4 场景挑战集**：高风险真实样本（长音频、多人重叠、噪声、混合语言）。用于识别短板，不阻断一般发布。

2. **当前 `test/` 目录音频统一归入 D0**：删除其"黄金集"语义，保留其作为工程回归与问题复现输入的价值。

3. **D0/D1 的指标用于警报、趋势与问题排序，不是唯一发布阻断条件**：除非发现数据损坏、大面积回归或字幕严重误导，不因单次未达固定分数阻断普通版本。

4. **D1→D3 升级需经标注审核**：从 D0/D1 挑选样本进入 D3 必须补齐授权、标注审查、场景标签和版本记录。

5. **禁止基于单一 D0/D1 样本添加面向特定文本、文件名、时间点或录音特征的代码分支**。

## 后果

- 测试失败不再直接等价于"不可发布"
- 需要为 D1/D3 建立正式的标注和审核流程
- D2/D3 需要合规的授权和匿名化流程
- 质量评估报告需按数据层级和场景切片，不能只报告单一总分
