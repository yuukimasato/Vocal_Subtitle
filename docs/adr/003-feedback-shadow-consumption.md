# ADR-003: 反馈影子消费

**状态**: 部分实施
**日期**: 2026-08-02
**决策者**: yuukimasato

## 背景

自适应反馈学习系统（Phase 5）已具备差异分析、参数学习、健康度评分、音频指纹匹配和 Shadow Mode 等能力。但反馈的直接消费存在风险：
- 单次用户修订可能包含风格偏好而非真值修正
- 未经审核的参数更新可能污染其他用户的默认配置
- 反馈样本的授权状态和匿名化尚未完全规范

## 决策

1. **自动学习默认只产生建议和影子结果**：参数学习模块 (`param_learner`) 的输出作为 "建议 profile 版本"，不直接覆盖用户当前默认配置。

2. **Shadow Mode 是学习结果启用的前置条件**：任何学习结果在影响默认输出前，必须经过 shadow mode 在已授权样本上验证无明显退化。

3. **反馈分为三类，不混用更新策略**：
   - **展示偏好**（标点、说话人标签）— 用户级快速生效
   - **结构偏好**（合并/拆分）— 场景级，需较多样本
   - **声学/识别问题**（漏词、错词、边界）— 需审核后进入回归集

4. **Profile 版本化与可回滚**：每次学习生成新版本，保留差异、健康度和回滚能力。模型、VAD 或主链版本变化时自动重新验证或回退。

5. **反馈审核是必经环节**：用户修订进入 D3（反馈回归集）前必须完成独立审核，争议样本标记为 `disputed`。

## 后果

- 反馈学习初期不会直接提升默认质量，需要通过审核和影子验证逐步产生效益
- 需要建立反馈审核流程和人员安排
- 用户可见的偏好设置与底层引擎参数更新解耦
- 增加了 profile 版本管理的存储和逻辑复杂度
