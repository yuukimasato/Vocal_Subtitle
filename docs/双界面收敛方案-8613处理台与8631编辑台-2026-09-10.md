# 双界面收敛:8613 处理台与 8631 编辑台整合方案

- 日期:2026-09-10
- 范围:`vocal_subtitle/webui`(8613,FastAPI + 静态 SPA)、`tools/subtitle-editor`(8631,零后端独立编辑器,嵌套 git 仓库)
- 状态:**已定稿(grill-me 三轮评审),实施中**
- 关联:`docs/全栈架构定型与审核学习整合方案-2026-09-10.md`(D13"审核前端退役"的延续与收尾)、`tools/subtitle-editor/README.md`

## 0. 结论(TL;DR)

1. **两个界面各司其职**:8613 = **处理台**(提交任务、历史、质量报告、反馈档案治理),8631 = **编辑台**(波形打轴、字幕校对、一键学习回传)。用户只面对这两个界面,不再有独立的历史页/质量页/反馈学习页。
2. 8613 删除全部旧编辑/展示链路:波形面板、字幕时间轴表格、内联编辑、deprecated `PUT /subtitle/*` 端点及其 service、孤儿审核代码(`ui-review.js`/`#workspace-review`,D13 承诺的"保留一个里程碑"到期)。
3. 8613 导航 **5 → 2**:处理(历史与质量内联其中)、反馈档案(治理功能保留,学习动作外迁 8631)。
4. 反馈学习入口迁至 8631:浮动面板调用既有 `POST /api/feedback/learn`,**一键"从当前会话学习"为主**(当前音频 + 当前字幕 + 顺带上送编辑日志),手动选文件兜底;预览(dry_run)→确认 两步;后端一行不改。
5. 8613 任务完成后提供 **"在编辑器中打开"深链**(`8631/?media=…&subs=…&manifest=…`),与 8631→8613 的既有 API 通道构成双向闭环。
6. 8631 保持**零后端、零 npm 运行时依赖、独立仓库**;所有集成沿用 `pipeline.js` 的 base-url + feature-detect 模式,离线能力不受影响。

## 1. 背景与目标

### 1.1 现状问题

- 8613 单页应用内有 5 个工作区(处理/反馈学习/任务历史/质量报告 + 已下线导航但代码尚存的审核区)。编辑与打轴职责已迁 8631(D13),但 8613 仍维护波形打轴(`js/waveform.js`,1023 行)+ 字幕表格编辑(`js/ui-subtitles.js`,678 行)+ 两个 deprecated `PUT /subtitle/*` 写回端点——同一能力双处展示、双份维护。
- 反馈学习界面在 8613:用户校对完字幕(工作发生在 8631)后,还要切回 8613、手动重选修订字幕和音频两个文件才能学习——纯摩擦。
- 任务历史与质量报告各占一个独立工作区,查看一次结果需要在处理/历史/质量三个视图间切换。

### 1.2 目标

- 减少界面切换频率:一次处理任务的"跑→看→校对→学习"闭环最多打开两个界面。
- 单一职责:编辑/查看能力只在 8631;治理与分析只在 8613。
- 删除死代码:孤儿审核链路、deprecated 编辑端点随本次一并物理删除。

### 1.3 非目标

- 管线与学习后端逻辑不变(`/api/feedback/learn`、journal sink、质量报告接口原样)。
- 8631 不引入构建依赖、不加任何后端;独立仓库边界与 independence 测试约束不破。
- `app.css` 中已删区块的遗留样式暂不清理(纯死规则,无行为风险,另开清理任务)。

- **`js/feedback.js`**(新):学习客户端。`detect()` 复用 `pipeline.js` 的 `/api/journal/sink` 202 探测;`learn()` multipart 调 `/api/feedback/learn`;日志上送复用 `pipeline.js` 既有 POST journal;base 复用 `vstEditor.pipeline.base`。
