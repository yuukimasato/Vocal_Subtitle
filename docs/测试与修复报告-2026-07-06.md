> **日期**: 2026-07-06 | **环境**: Python 3.12.3, Ubuntu Linux, CPU-only | **测试音频**: `test/` 目录下中英文多人员音频

## 1. 项目概述

**Vocal Subtitle** 是一款人声分离 + 字幕生成全链路工具，核心流程为：

```
音频输入 → 人声分离 → VAD 语音检测 → 片段合并 → ASR 识别 → 说话人分离 → 字幕输出
```

测试覆盖三条路径：
- **CLI 链路测试**：`python main.py run` 直接处理音频
- **Web UI 端点测试**：FastAPI REST API + WebSocket
- **Agent Browser 模拟测试**：浏览器自动化模拟用户操作

测试音频为酒店火警应急场景，13~19 秒内 6 位不同人员快速交替发言，是极端的多人短对话场景。

## 3. 问题诊断与修复

### 修复一：间隙说话人交替算法优化

**文件**: `vocal_subtitle/pipeline.py` — `_gap_based_speaker_assignment()`

**问题**:
- 原算法仅支持**二元交替**（`current_speaker = 1 - current_speaker`），最多只能检测 2 个说话人
- 切换阈值使用 `median_gap × 1.2`，下界固定 0.12s，在快速多人对话中过于保守

**修复**:
```python
# 旧：二元交替
current_speaker = 1 - current_speaker

# 新：多人交替 + 回切检测
current_speaker = next_speaker
next_speaker += 1
# 极短间隙 → 回切到上一说话人（A→B→A 模式）
if 0 < gap <= back_switch_threshold and prev_speaker is not None:
    current_speaker = prev_speaker
```

阈值调整：`median_gap × 1.2` → `median_gap × 1.0`，下界 `0.12s` → `0.08s`

**效果**: 中文：1→3 说话人 | 英文：2→3 说话人

### 修复三：speechbrain 模型离线加载（核心修复）

**文件**: `vocal_subtitle/diarization/speaker_embedding.py`

这是最复杂的修复，涉及 4 个子问题：

#### 3.1 绕过 k2_fsa 可选依赖懒加载失败

**问题**: `from speechbrain.pretrained import EncoderClassifier` 触发 `speechbrain.integrations.k2_fsa` 懒加载，k2 未安装导致 ImportError

**修复**: 在 import 之前预注册 dummy 模块
```python
import sys
_k2_mod = type(sys)("speechbrain.integrations.k2_fsa")
_k2_mod.__file__ = "k2_not_installed"
sys.modules["speechbrain.integrations.k2_fsa"] = _k2_mod
```

#### 3.2 绕过所有网络 fetch 调用

**问题**: `EncoderClassifier.from_hparams()` 内部通过 `speechbrain.utils.fetching.fetch()` → `huggingface_hub.hf_hub_download()` 访问 HuggingFace，离线环境超时阻塞 130+ 秒

**修复**: Monkey-patch 所有 `speechbrain.*` 模块的 `fetch` 引用，直接从本地 `savedir` 返回文件

```python
def _offline_fetch(filename, source, savedir=None, save_filename=None, **kw):
    fname = save_filename or filename
    # 检查 speechbrain 传入的 savedir
    if savedir is not None:
        local = Path(savedir) / fname
        if local.exists() and local.stat().st_size > 200:
            return local
    # 回退到我们的本地 _savedir
    local2 = Path(_savedir) / fname
    if local2.exists() and local2.stat().st_size > 200:
        return local2
    # label_encoder.ckpt → label_encoder.txt
    if fname.endswith(".ckpt"):
        ...
    return _orig_fetch(...)
```

并通过 `sys.modules` 迭代覆盖所有已加载的 speechbrain 模块，对可选依赖懒加载失败做 `try/except` 静默跳过。

#### 3.3 PyTorch 2.x 兼容

**问题**: speechbrain `__init__` 中 `"cuda" in self.device` 在 PyTorch 2.x 的 `torch.device` 对象上报 `TypeError`

**修复**: `run_opts={"device": "cpu"}` 传字符串而非 `torch.device` 对象

#### 3.4 默认缓存路径修正

**问题**: `SpeakerEmbeddingConfig.cache_dir = ""` → `Path("")` = `PosixPath('.')` → 默认路径判定失效，savedir 被解析为相对路径

**修复**: `__init__` 中增加空字符串/当前目录判定
```python
if cache_dir is None or (isinstance(cache_dir, Path) and str(cache_dir) in ("", ".")):
    self._cache_dir = DEFAULT_CACHE_DIR
```

---

### 修复四：HuggingFace 下载超时优化

**文件**: `vocal_subtitle/diarization/speaker_embedding.py` — `create_embedding_engine()`

**问题**: 即使 monkey-patch 了 fetch，备用路径仍可能触发 HF Hub 网络请求。原超时 10s × 5 次重试（指数退避 1s/2s/4s/8s/8s）≈ 73s

**修复**: 设置 `HF_HUB_DOWNLOAD_TIMEOUT=3` + `REQUESTS_TIMEOUT_SECONDS=3`

（后续因 monkey-patch 已完全切断网络路径，此修复为兜底保障）

## 7. 已知限制

1. **极限多人场景**：13 秒 6 人交替是最极端情况，当前 4/6 的检出率在类似场景中属合理。常规 2-3 人对话准确率会显著更高。

2. **LLM 合并**：当前无 API 配置，LLM 语义合并回退到规则模式。配置 API 后可进一步减少跨说话人合并错误。

3. **Silero VAD 偶发超时**：`Failed to load Silero VAD from GitHub` 会阻塞 ~90s 后回退到本地缓存。可通过预下载本地缓存解决。
