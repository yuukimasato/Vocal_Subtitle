## 0. 结论(TL;DR)

幻觉过滤的诊断计数此前是**硬编码占位值**:`_apply_hallucination_stats` 固定写入
`filter_version="v1"`、`dropped_count=1`、`drop_reasons={"training_phrase": 1}`,
无论实际过滤了多少段、什么原因。下游 `PipelineStats.to_dict()` 为兼容这种"字段
可能不存在"的状态,在序列化时用 `getattr(self, ..., 默认值)` 兜底——即数据类上
根本没有声明这些字段,靠运行时动态属性续命。

本次改造后:

1. 三个诊断字段提升为 `PipelineStats` 的正式 dataclass 字段,序列化/反序列化
   双向覆盖(含新增的 `hallucination_drop_reasons` 按原因计数)。
2. `_filter_asr_results` 返回 `(过滤后分段, 按原因计数 dict)`,调用侧经
   `_record_hallucination_drops` 跨 VAD 块累加,不再丢失每次过滤的明细。
3. ASR 阶段入口 `_reset_hallucination_counters` 按 run 归零——Pipeline 实例被
   WebUI 任务跨次复用时,上一次运行的计数不会串进本次统计。
4. 阶段收口统一调用 `_apply_hallucination_stats(stats)`,把真实累计值写入统计,
   `filter_version` 取自 `config.asr.hallucination_filter_version`(配置源:
   `configs/default.yaml`,默认 `"v1"`),不再硬编码。

## 2. 语义影响

- `run_stats.json`(及 WebUI 任务事件)中的 `hallucination_dropped_count` 从恒为
  `1` 变为真实过滤总数;`hallucination_drop_reasons` 从恒为
  `{"training_phrase": 1}` 变为按原因真实分布,且新增字段会持久化、可回读。
- `_filter_asr_results` 为内部 API,签名变化已同步全部两处生产调用点(缓存命中
  路径 `stage_runner.py:457` 与分块识别路径 `stage_runner.py:543`)。
- 缓存键本就包含 `hallucination_filter_version`(`config/models.py` 默认
  `"v1"`),本次未改变过滤行为与缓存身份,历史缓存不受影响。
