- 日期:2026-09-11

- 状态:**决策已定 + S1 冒烟已通过(2026-09-11)**,真实素材实验(S2/S3)待跑
- 关联:`configs/default.yaml`(`asr.global_asr` / `asr.evidence_review`)、`vocal_subtitle/application/asr_path.py`、`vocal_subtitle/asr/evidence_review.py`、`vocal_subtitle/application/offline_production.py`、`vocal_subtitle/physical/coverage.py`

## 0. 结论(TL;DR)

1. **"骨架分段为主干 + 全程识别为辅助校验"就是本项目现行默认架构**,不添加任何新功能。`global_asr.routing: "segmented"`(分段为主)+ `evidence_enabled: true`(全程识别在分段主识别后自动运行,角色 = 对照证据 evidence),每次任务的双份识别成本已在支付。
2. **"全程识别没有缺漏"这一前提不成立**:Whisper 类模型在长音频上会跳读、幻觉、漏段(项目内幻觉过滤与风险评分的存在即为证明)。它的真正价值在于与骨架分段路径的**漏法不同**——能量静音边界漏气声低音量语音,整段识别漏长音频中后段——交叉比对暴露分歧。现有 evidence 框架的 risk_only 策略已是这个逻辑。
3. 全程识别**可以**拿到完整文本 + 时间轴:faster-whisper `word_timestamps: true` 产出词级+段级时间轴与置信度(`avg_logprob`/`no_speech_prob`/`compression_ratio`);≤180s 一次性整段,>180s 按 180s 窗口 + 0.5s 重叠分窗。
4. 现状唯一落差:`evidence_review.shadow_mode: true` —— 校验差异照常全量计算(含"影子预演":物理投影验证)但**不修改最终输出**。是否落地由 §5 的数据判定标准决定,纯配置变更。

## 1. 背景与原始设想

- 现有主干:ffmpeg silencedetect 生成静音骨架,把骨架段切成精确切片(切片端点 = 静音边界),每个切片独立 ASR,局部时间戳偏移回全局轴。
- 设想:全程识别(整段音频过一遍 ASR)可拿到完整文本与时间轴(时间轴不精确,但理论上无缺漏);能否以骨架分段为主干、全程识别为辅助校验?
- 待回答:①全程识别能否拿到完整文本+时间轴;②该设想是否需要新增功能。

## 2. 事实基础(2026-09-11 代码调查)

### 2.1 骨架分段主干(已实现,默认开启 `skeleton_mode: true`)

| 环节 | 实现 |
| --- | --- |
| 静音骨架 | `unified_ffmpeg_pass` 一次 ffmpeg 调用产出骨架/粗 VAD/静音区间(`vocal_subtitle/vad/ffmpeg_vad.py:235`,-40dB/0.1s,采样级精度) |
| 窗口聚合 | >0.4s 硬静音永远是严格 ASR 窗口边界(`vocal_subtitle/acoustic/skeleton.py:12`) |
| 切片端点 | 单成员窗口严格保留骨架端点、无 padding;多成员聚合窗口 ±0.25s 上下文、端点钳制到硬静音中点(`vocal_subtitle/application/chunk_runner.py:629-656`) |
| 切片识别 | 每切片走完整局部管线(Silero VAD→ffmpeg VAD→合并→ASR→边界精修);聚合窗口结果按词级时间戳重投影钳回物理成员边界(`vocal_subtitle/application/member_projection.py:159`) |
| 全局时间轴 | 切片结果单次刚体偏移 `offset_subtitle_event`(`vocal_subtitle/mapping/time_mapper.py:243`,重复偏移抛错) |

### 2.2 全程识别路径(已实现,默认作为证据运行)

- 引擎层:`engine.transcribe(full_audio)` 接受任意长度数组;`word_timestamps: true` 默认开启(`vocal_subtitle/asr/faster_whisper_engine.py:43`),词级+段级时间轴+逐段置信度字段。
- 应用层:global ASR 路径 `_run_global_transcription_path_legacy`(`vocal_subtitle/application/asr_path.py:439`)——≤180s 一次性整段识别;>180s 由 `GlobalTranscriber` 按 `max_window_duration: 180.0` + `window_overlap: 0.5` 分窗合并(`vocal_subtitle/asr/global_transcriber.py`)。
- 默认配置(`configs/default.yaml:217-228`):`enabled: true`、`routing: "segmented"`、`evidence_enabled: true`、`hallucination_filter: true`。识别结果分配到物理 bin 并做覆盖审计与质量门禁。

### 2.3 校验/补偿机制(已实现,比"全程 vs 分段"二分更细)

| 机制 | 位置 | 作用 |

| LocalRecovery | `vocal_subtitle/asr/local_recovery.py:186` | 缺失区间带 ±0.5s 上下文局部重识别(≤3 次,词置信度 ≥0.5),结果作为证据重新进评审 |

| 尾部截断修复 / 质量门禁整跑 | `vocal_subtitle/application/asr_path.py:714`、`run_lifecycle.py:490` | 防静默截尾;覆盖率 <0.80 换引擎重跑整条骨架分段 |

### 2.4 开关语义(已核实)

- `shadow_mode: true`(默认):输出 = baseline 原样返回(`evidence_review.py:325-328`);decisions/diagnostics 照常计算并附在结果中;`offline_production` 以 `shadow_observed` 记录"若落地会发生什么"。
- `authoritative_mode: true`(或单关 `shadow_mode: false`,回退逻辑见 `offline_production.py:75`):输出 = `decisions_to_subtitle_events(decisions)`,校验真正落地修改字幕。

### 2.5 diff 数据落盘现状(2026-09-11 查证结论)

- **CLI 运行无结构化落盘**:evidence 评审全量诊断(decisions/risk/global_evidence/physical_projection.recovery_ranges)只存在于内存 `stats.quality_diagnostics["evidence_review"]`(`asr_path.py:305`);`run_report.json` 只写聚合计数(`run_reporter.py:167-183`);`coverage_audit.json` 通道存在但无代码赋值 `quality_diagnostics["coverage_audit"]`,实际永不生成;日志无 diff 内容;`vocal_subtitle/diagnostics/` 目录无写入代码。
- **WebUI 运行经 SQLite 全量持久化**:`task_history.result_json` 写入整个 `stats.to_dict()`(`webui/pipeline_tasks.py:213-253`),可经 `GET /history/{task_id}` 读回。
- **无现成词级 diff 工具**:`scripts/compare_timeline.py` 对照的是人工参考字幕,不是 global evidence。
- **应对**:新增独立实验驱动脚本 `scripts/run_global_evidence_diff_smoke.py`(跑管线 + `_get_asr_engine_for(global backend)` 复用引擎整段识别 + `difflib` 字符级 diff → M1-M5 指标 JSON),**零管线改动**。

## 4. 实验设计

### 4.1 指标定义

| 指标 | 定义 | 度量来源 |
| --- | --- | --- |
| M1 全程独有 | global 有而分段无的内容(= 分段真漏句候选) | global 词与 baseline 词比对 + 覆盖审计 uncovered bins |
| M2 分段独有 | 分段有而 global 无的内容(= global 缺漏,反向指标) | 同上,反向 |
| M3 分歧点 | `global_text_conflict` 触发数 + 人工抽样判定谁对 | evidence decisions(`evidence_review.py:338`) |
| M4 幻觉触发 | global 侧 `no_speech_prob≥0.6` / `avg_logprob<-1.0` / `compression_ratio≥2.4` 触发次数 | `risk_scoring.py:130-141` |
| M5 时间轴偏差 | 分歧点上 global 词时间 vs baseline 词时间差值分布 | 双方词级时间戳 |

### 4.2 步骤

- **S1 冒烟(仓库 fixtures)**:✅ **已通过(2026-09-11,`.venv-production`,CPU int8)**。工具:`scripts/run_global_evidence_diff_smoke.py`;报告输出 `.scratch/evidence_diff/*.evidence_diff.json`。

| 素材 | 基线 | 全程 | M1 全程独有 | M2 分段独有 | M3 评审 | M4 幻觉触发 | M5 时间轴差(global−baseline) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 中文多人员测试音频.wav(13.3s) | 6 条/66 字 | 8 段/66 字 | **0** | **0** | 1 decision(仅缺词置信度标记) | 0/8 | 中位 −0.18s,p90 \|Δ\| 0.47s,最大 0.58s |
| 181人声.wav(58.5s) | 20 条/161 字 | 25 段/153 字 | **1** 处("婉儿"@52.98s) | **4** 处("嗯"/"啊"/"道"/"婉儿") | 20 decisions:18 keep / **2 replace**(shadow 未落地);全部带 `global_text_conflict` | **14/25** 段 no_speech_prob≥0.6 | 中位 −0.16s,p90 \|Δ\| 0.53s,最大 0.88s |

S1 初判(非定论,样本过小):

1. 机制端到端可用——shadow 诊断可提取,diff 可计算,脚本可直接复用于 S2。
2. 差异真实存在且可检测:M1 的"婉儿"是潜在的"分段漏识/措辞分歧"样本;M2 以语气词(嗯/啊)为主——whisper 倾向丢弃语气词,反向说明**分段路径更全**。
3. 全程识别自身不稳定信号明显(14/25 段高 no_speech_prob;时间轴系统性偏差 0.2~0.5s),支持 D3/D5:全程识别不当裁判、独有句不自动补入。
4. M1"婉儿"@52.98s 与 M2"婉儿"@57.75s 并存,可能是说话人重复也可能是 diff 聚类伪影——正是 S3 人工抽样要裁决的类型。

- **S2 真实素材**:≥2 个、总量 ≥2 小时、覆盖日常典型音质;含气声/低音量段者优先(那是骨架能量边界最可能漏、也是辅助校验最有增量价值的类型)。跑 `scripts/run_global_evidence_diff_smoke.py`,收集 M1-M5。
- **S3 抽样人工判定**:M1 全部(若 ≤20 处)或随机 ≥20 处;M3 随机 ≥20 处。

## 5. authoritative 开启判定标准(预写,实验填数)

满足**全部三条**才开:

- **C1 增量**:真实素材上 M1 ≥ 1 处/小时。否则辅助校验在当前素材类型上无增量,保留 shadow 长期观察,本文档归档结论。
- **C2 可靠性**:M1 抽样中 global 独有句人工判定为真实语音的占比 ≥ 80%,且 M4 幻觉触发率无明显异常。
- **C3 仲裁优势**:M3 抽样中 global 更准的占比 ≥ 70%。

开启方式:`configs/default.yaml` → `asr.evidence_review.shadow_mode: false`(`offline_production.py:75` 的回退逻辑使 authoritative 随之生效)。**纯配置变更,无代码改动。**开启后按 D5,global 独有句仍走标记+人工核验,不自动补入。
