# Vocal Subtitle 优化方案（基于 `main` 实际代码）

## 分析边界

本方案基于当前工作区 `main` 分支的 Python/TypeScript 实际代码、配置和测试文件，不以项目文档作为依据。当前 `main` 相对 `origin/main` ahead 12 个提交，工作区另有未提交修改；实施前必须先记录并保护这些修改。

代码可通过 `python -m compileall -q vocal_subtitle llm_subtitle_optimizer`。使用 `uv run pytest` 运行的 ASR 路由与显示时间轴测试共 25 项全部通过；直接执行 `pytest` 因环境没有该命令而失败。

## 主要发现

1. `Pipeline` 通过多个 Mixin 组合，`application/run_lifecycle.py` 的 `run()` 约 900 行，依赖大量实例级隐式状态。长函数还出现在 ASR、声学校验、分段、反馈和 WebUI 任务模块。
2. 字幕时间会被 `time_mapper`、`finalize`、`display_timeline`、`acoustic/validator` 和生命周期后处理多次修改。当前未提交修改已增加最终防重叠修复，说明时间轴不变量仍需集中管理。
3. global、segmented、legacy、fallback 和 review 多条 ASR 路径在生命周期函数中交织，状态字段分散在多个字典和 `PipelineStats` 属性中。
4. 窗口执行使用线程池和协作取消；超时后 `shutdown(wait=False)` 可能留下仍占用模型/GPU 的线程。边界重识别还保留另一套线程池实现。
5. 代码中约有 237 处 `except Exception`，核心流程、WebUI 和模型加载都存在宽泛捕获，错误分类和降级原因不够统一。
6. `config/loader.py` 的 `_parse_config()` 约 528 行；配置域多，继续扩展会增加字段转换和 profile 合并风险。
7. 缓存键在 `CacheManager.make_key()` 中包含绝对路径，没有强制绑定内容 hash、模型身份、阶段版本和 schema 版本。
8. 音频和 ndarray 在多个阶段重复加载/切片；WebUI `pipeline_tasks.py` 同时承担任务调度、进度、历史、WebSocket、模型准备和反馈学习。
9. 质量门禁、声学校验、覆盖率、fallback 和报告信息分散在多个诊断字典中，缺少统一的阶段质量模型。

## 优化方向

### P0：稳定性与可观测性

- 引入统一异常：配置、音频解码、依赖缺失、ASR、时间轴和可恢复阶段错误分别建模。
- 将宽泛异常捕获限制在阶段边界；所有降级必须写入结构化诊断。
- 把最终时间轴校验、重叠数、静音区重叠、覆盖率等指标统一到 `QualityReport`。
- 为线程池记录活动任务、超时任务、取消原因和资源释放状态。
- 统一测试入口为 `uv run pytest`，先建立基线报告。

### P1：拆分主流程

- 引入显式 `RunContext`，承载输入、音频、VAD、ASR、事件、诊断和取消令牌。
- 将生命周期拆成 Preflight、Audio、Separation、VAD、ASR、Diarization、Mapping、Postprocess、Export 阶段。
- 保留 `Pipeline.run()` 公开接口，使迁移可以分阶段完成。

### P1：统一 ASR 与时间轴

- 用 `ASRExecutionPlan` 和固定状态机表达 primary/fallback/global/segmented 路径。
- 所有窗口任务复用 `WindowExecutionCoordinator`，统一并发预算和取消策略。
- 时间轴只允许在唯一仲裁阶段写入；导出阶段只读校验。
- 最终事件使用不可变模型或复制后修改，并保留 `revision_trace`。

### P2：配置、缓存和性能

- 拆分配置解析函数，进行递归 profile merge 和未知字段校验。
- 缓存键改为内容 hash、规范化配置 hash、引擎/模型身份、阶段版本和 schema 版本。
- 引入只读 `AudioBuffer`，复用采样率转换结果和切片视图。
- 增加缓存容量、LRU 清理、命中率和失效原因。

### P2：WebUI 与兼容层

- 将 WebUI 任务执行、事件发布、持久化和路由序列化分离。
- 为 legacy 路径增加使用计数和弃用边界，稳定新路径后删除。

## 验收指标

- `run_lifecycle.py` 的 `run()` 控制在 150 行以内。
- 核心流程裸 `except Exception` 数量减少 70% 以上。
- 所有窗口 ASR 使用同一个协调器。
- 最终相邻字幕重叠数为 0，且每次修复有诊断记录。
- 缓存可跨路径复用，并能因模型/阶段版本变化自动失效。
- 每个任务都有阶段耗时、质量指标、降级原因和最终状态。
- 完整测试可用 `uv run pytest` 重复运行。
